# 后端分层约定

一句话：**依赖只能往一个方向走**。`cmd` → `httpapi` → `domain` → `platform`，箭头反向即错。

门禁是 `node scripts/check-layering.mjs`（CI 的 `contract` job）。它扫 `backend/` 下所有
非测试 Go 文件，抽出对**本仓库**其它包的 import，按下面的规则判。

## 三层加两个生成物

```
cmd/            装配层：读配置、开连接池、把东西接起来、管进程
  └─ httpapi/   传输层：路由、请求解析、状态码、序列化
       └─ domain/   业务层：一个业务域一个包，规则与不变量住在这里
            └─ platform/   基础设施：配置、连接池、日志、外部服务客户端

api/   ← 生成物（OpenAPI 契约 → Go 类型与路由表）
store/ ← 生成物（sqlc 查询 → Go 代码）
```

`api/` 和 `store/` 不是「一层」，是两个**产物**。它们的位置由工具决定，不由架构决定。

## 五条规则

| # | 规则 | 违反之后会长成什么样 |
| --- | --- | --- |
| L1 | `platform/**` 不得 import `domain` / `httpapi` / `api` / `store` | 基础设施开始认识业务概念。想换掉数据库或加第二个存储，得先改业务才能改底座 |
| L2 | `domain/**` 不得 import `httpapi` / `api`，也不得 `import "net/http"` | 业务逻辑被 HTTP 形状绑架：同一个规则没法被定时任务、CLI 或另一个端点复用 |
| L3 | `domain/<A>` 不得 import `domain/<B>` | 两个域粘成一个。改 A 要重新理解 B，测 A 要起 B 的一整套依赖 |
| L4 | `api/**`、`store/**` 不得 import 本仓库其它包 | 重新生成会把你的改动覆盖掉；而且生成物一旦有自己的想法，它就再也不是「契约的镜像」了 |
| L5 | `cmd/**` 不受限 | 装配层的职责就是「知道所有人」，限制它没有意义 |

`httpapi/**` 不受限（它就是要把业务、生成物、基础设施接到一起），但**它自己也不该写业务规则**
——这条门禁抓不到，靠 review。

## 为什么是这三条，不是更多

更细的分层（repository / service / usecase）在没有业务代码的时候是空转：多一层等于多一个
要维护的空壳，而它保护的「将来可能要换实现」在真换之前无法验证。**先立能挡住真实伤害的三条**：

- L1 挡「换基础设施要改业务」；
- L2 挡「业务规则离不开 HTTP」；
- L3 挡「两个域长成一个」。

其余的等出现第二个真实调用方（比如定时任务要复用某段业务逻辑）再加。

## 怎么加一个新域

```
backend/internal/domain/<domain>/
    <domain>.go      # 领域类型与规则
    service.go       # 编排：调 store、调 platform、返回领域结果
    *_test.go
```

1. 只依赖 `platform/*` 和 `store`（生成物）。
2. 不 import `net/http`、不 import `internal/api`、不 import 其它域。
3. 需要别的域的数据时，把「要什么」写成接口放在**使用方**（本域）里，由 `cmd` 装配时注入
   ——这是 Go 的老办法，好处是 `cmd` 一眼能看出谁依赖谁。
4. 外部输入（HTTP 请求体、消息、文件）在 `httpapi` 里就转成领域类型；`domain` 收的是
   校验过的值，不认识 `*http.Request`。

## 当前状态

`backend/internal/domain/` **还不存在**——三个端点现在都是「查一次库、转成响应」，
没有值得单独建模的业务规则。把这种直读代码硬掰成三层只会制造空壳。

所以这份约定现在是**给下一个包**准备的：`domain/` 里一出现代码，L2 / L3 立刻开始生效。
`platform/httpserver` 曾经 import 了生成物 `internal/api`（它在那里做路由），为了让 L1
不需要例外，路由已经移到 `httpapi/router.go` —— **能靠挪代码解决的事，不靠加例外解决**。

## 门禁的边界

`check-layering.mjs` 只读 import 路径。它**不能**判断：

- 这个包是不是真的只做这一层的事（`httpapi` 里完全可以写出业务规则而不违反任何规则）；
- 一次调用是不是绕了远路（`httpapi` 直接调 `store` 而不经过 `domain`，在今天是对的，
  在下个月可能就是错的）；
- 包内文件之间的职责划分。

一句话：**它证明「依赖方向没被写错」，不证明「分层是对的」。**

## 怎么跑

```bash
node scripts/check-layering.mjs     # 11 个 Go 文件，0 条违规
node --test scripts/check-layering.test.mjs
```
