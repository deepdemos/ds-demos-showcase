## 0. 三分钟版

DeepDemos Showcase 是 DeepSeek 民间科研成果的展示站：作者投稿自己的作品（网页、压缩包、Godot 游戏、图片、三维模型或外链），审核后发布到公开作品库，读者可以浏览、筛选、搜索、评分、看榜单。

**现在处于什么阶段**：从"能跑通一条投稿→审核→发布的闭环"走到了"一个有内容分发能力的作品站"。作者能管理自己的作品（改稿、版本历史、回滚、下架、删除与恢复），读者能按分类/模型筛选、按最新/热度/随机排序、看六种榜单、在详情页看到相关作品与站内表现，管理员能审核、发布、管渠道、导入模型目录。**还没有**社区（评论、关注、收藏）、通知、作者主页。

| 维度 | 数字 |
| --- | --- |
| 数据库表 / 视图 | 88 / 8 |
| 迁移 | 基线 10 个 schema 文件 + 27 条增量迁移 |
| API 端点 | 44 个（契约里 71 个模型、38 个枚举） |
| 前端页面 | 14 个路由 |
| 控件库 | 12 个控件 / 33 个登记项（Dev Room 全量演示） |
| 手写代码 | 后端 Go 13.5k 行 + 测试 16.0k 行；前端 TS 7.0k 行 + 测试 3.6k 行 |
| 测试 | 后端 5 个包全量集成测试；前端 24 个文件 / 173 条用例；e2e 12 条 |
| 文档 | 36 篇设计/流程文档 + 60 条已知松点台账 |

三个最能说明状态的事实：

1. **一条作品从投稿到对外可见，每一步都有集成测试和反向验证钉着**——不是"写完了"，是"删掉那段逻辑，测试会红"。
2. **契约是唯一事实源**：`api/openapi.yaml` 先改，Go 与 TypeScript 两侧代码都从它生成，文档里写的端点数量有门禁比对。
3. **75% 的工作量花在"防回退"上**：13 道脚本门禁、7 道 CI 必过检查、60 条记录在案的取舍。这也是为什么这个仓库看起来起得慢。

## 1. 现在能做什么

这一节不含技术词，按人的视角写。

| 角色 | 现在能做的事 |
| --- | --- |
| **访客** | 浏览作品库（分页、按分类/模型筛选、按最新/热度/随机排序）；搜索标题与简介；看作品详情（作者、发布时间、分类、模型声明、浏览与下载数、评分）；看六种榜单（平均分 / 5 分票 / 1 分票 / 净票 / 评分人数 / 综合热度，可切全部 / 近 7 天 / 近 30 天）；给作品打 1–5 星（匿名也可以，一人一票）；看模型页（档案、站内表现、第三方基准） |
| **作者** | 注册、验证邮箱、登录、找回密码；投稿（六种作品类型）；看自己作品的状态（待审 / 已上线 / 已下架 / 已删除）；改稿（内容不立刻对外生效，审核通过才切换）；看版本历史并回滚；下架、重新上架、删除、恢复；看自己作品的"作品动态"（谁在什么时候做了什么）；管理已上架的渠道 |
| **审核员 / 管理员** | 看待审队列；通过或驳回（要写理由）；发布到渠道、改可见性、撤下渠道；导入模型目录（上游同步 + 人工挑选字段）；看审计记录 |
| **运维** | 一条 `docker compose up -d` 起完整环境（含数据库、迁移、存储卷），可选 `--profile tls` 挂 Caddy 自动证书；也可以用 nginx + systemd 的裸机部署 |

**还没做**：通知（审核结果、有人评分）、作者主页（从作品点进一个人的全部作品）、评论、收藏、关注、浏览历史页、成长积分、题目/提示词实体、多实例部署。

## 2. 目标与预期

### 2.1 项目目标

1. **把民间成果变成能被浏览、被检索、被比较的内容**——不是一堆截图和帖子，而是有分类、有模型声明、有榜单的作品库。
2. **让作者的投稿成本足够低、修改成本足够低**——一次投稿应该在两分钟内完成，改错别字不应该触发重新审核 24 小时。
3. **让审核是"把关"而不是"阻塞"**——已发布作品的改稿不影响线上，审核通过才切换。

### 2.2 分阶段预期

| 阶段 | 预期 | 状态 |
| --- | --- | --- |
| 一、能用 | 投稿、审核、发布、公开列表的最小闭环 | ✅ 已完成 |
| 二、作者愿意用 | 改稿、版本历史、回滚、上下架、删除恢复、状态可见 | ✅ 已完成 |
| 三、读者愿意逛 | 分类与模型筛选、搜索、排序、榜单、相关作品、推荐、评分 | ✅ 已完成 |
| 四、社区 | 通知、作者主页、评论、收藏、关注 | 🚧 未开始（作者主页与通知已排进下一批） |
| 五、运营 | 模型目录同步与导入、渠道管理、审计、部署与 TLS | ✅ 已完成（部署部分） |

### 2.3 成功判据

不用"完成度百分比"，用能检验的句子：

- 新作者从注册到作品上线，**不需要读任何文档**（有作者指南，但正常路径不该需要它）。
- 作者改一个错别字，**线上内容一个字节都不变**，直到审核通过。
- 任一作品的"对外可见"只有一个判据——**同一件作品在列表、详情、榜单、相关作品里出现与否必须一致**（这条曾经裂成过三份实现，现在收进数据库视图）。
- 删掉任意一段业务逻辑，**至少一条测试会红**。
- 一件作品从投稿到发布，**每一步都能在审计里查到是谁做的**。
- 部署到一台干净机器，**两条命令内能对外服务**（`docker compose up -d`；要 https 再加 `--profile tls`）。

## 3. 系统结构

### 3.1 分层

```
cmd/            进程入口：api / migrate / admin-grant
  → httpapi/    路由、参数校验、响应编解码（不认识 SQL）
  → domain/     业务规则与事务边界（按域分包：demo / identity / model …）
  → kernel/     跨域的纯机制（验证码、限流）
  → platform/   外部设施（config / storage / mailer / catalog）
```

约束由 `scripts/check-layering.mjs` 强制：上层可以依赖下层，**同层不同域之间不许互相 import**。这条线不是洁癖——它保证"改审核不会碰坏投稿"。

### 3.2 技术栈

| 层 | 选型 | 选择理由（一句话） |
| --- | --- | --- |
| 后端 | Go 1.27 + chi v5 | 单二进制、启动快、并发模型够用 |
| 数据库 | PostgreSQL 18 | 需要部分唯一索引、视图、触发器、`pg_try_advisory_lock` |
| 数据访问 | sqlc（生成）+ pgx v5 | SQL 手写、类型生成，不引入 ORM 的隐式行为 |
| 迁移 | 自建 `cmd/migrate`（基线冻结 + 只增迁移） | 已应用的迁移不许改，校验和入档 |
| 契约 | OpenAPI 3.0.3 + oapi-codegen + orval | 3.1 的 `type: [string,'null']` 上游生成器不支持 |
| 前端 | React 18 + Vite + TanStack Query 5 | 服务端状态统一交给 Query，不手写缓存层 |
| 样式 | Tailwind 4 + 自有控件库（Ring UI 只在库内用） | 页面不许直接用第三方控件，保证可替换 |
| 部署 | 二进制 + nginx + systemd；或 docker compose（可选 Caddy TLS） | 两种都进仓库并各有门禁 |

### 3.3 部署形态

- **容器**：`docker compose up -d` 起 db / api / web 三个服务，迁移在 api 入口脚本里跑；`--profile tls` 加 Caddy（自动证书或 `tls internal` 自签）。
- **裸机**：`deploy/nginx/` 与 `deploy/systemd/` 里的片段已进仓库并有门禁校验，但**没有在真机上跑过**（记录在松点 56）。
- 浏览器登录必须 https（会话 cookie 带 `__Host-` 与 `Secure`），这也是加 TLS 侧车的直接原因。

## 4. 数据模型

### 4.1 分组

| 组 | 主要表 | 说明 |
| --- | --- | --- |
| 身份 | `accounts` `users` `account_emails` `profiles` `sessions` `roles` `permissions` `role_permissions` | 账号与用户分离（一个账号可对应多个站点用户身份） |
| 作品 | `demos` `demo_revisions` `demo_revision_files` `blobs` `demo_channels` `demo_stats` `demo_timeline` `demo_views` `demo_ratings` | 内容寻址存储：同一文件不重复落盘 |
| 分类 | `classifications` `classification_dimensions` `demo_classifications` `demo_type_formats` `demo_types` | 分类挂作品，模型挂版本（这是刻意的） |
| 模型 | `models` `model_aliases` `model_offerings` `model_specs` `model_catalog_items` `model_source_sync` `demo_revision_models` | 目录镜像（8930+ 行）与本地事实分离 |
| 治理 | `audit_log` `audit_actions` `audit_entity_types` `permissions` | 审计只追加，不改不删 |
| 生命周期 | `gc_queue` | 恢复窗口在删除那一刻定型 |
| 设置 | `setting_keys` `site_settings` `user_preferences` | 复合外键强制白名单 |
| 浏览 | `demo_visible_channels`（视图） `demo_listed_channels`（视图） `demo_public_demos`（视图） | 可见性判据收进视图，避免第四份手写副本 |

### 4.2 三条关键不变量

1. **版本分离**：`demos.published_revision_id` 决定对外内容，`current_revision_id` 是作者手上的版本。作者改稿期间线上作品一个字节都不变——这是"审核不等于下线"的实现方式。
2. **可见性只有一处判据**：能不能被公开看到 = `demo_public_demos` 视图（已审核 + 已发布 + 未删 + 至少一个 listed 渠道）。列表、详情、榜单、相关作品、推荐全部走它。
3. **时间顺序约束**：所有对外语义的时间列都有 `CHECK` 约束（`updated_at >= created_at` 等），写入侧一律夹紧到 `GREATEST(now(), created_at)`。起因是一次真实的时钟回拨导致审核接口偶发 503。

### 4.3 迁移策略

- `db/schema/*.sql` 是**冻结基线**（等价 0000 号迁移），永不再改。
- 基线之后的一切变化进 `db/migrations/NNNN_*.sql`，**只增不改**，校验和存 `db/migrations/checksums.json`，`scripts/check-migrations.mjs` 比对。
- 29 条迁移里，有 3 条是"给线上已有数据补正"（分类词表、模型类型、外链类型），其余是结构与权限。

### 5.2 契约纪律

- `api/openapi.yaml` 是**唯一事实源**。改契约 → 重生成两侧（`gen:api:go` / `gen:api:web`）→ 再改实现。
- `api/surface.json` 是契约快照（71 模型 / 38 枚举 / 44 端点），`check-api-compat` 只防"删除或改窄"。
- `check-api-doc` 比对文档里写的端点数目与分组说明；`check-negative-cases` 要求每个端点至少一条反例且指向真实测试（46 端点 / 111 条）。

### 5.3 权限

10 个权限键挂在角色上，端点按权限键判：`entity.edit`（改自己的作品）、`demo.publish`（发布与渠道）、`demo.review`（审核）、`model.import`（模型目录导入）、`audit.read` 等。管理员角色默认全量。

## 6. 前端

### 6.1 页面（14 个路由）

作品库（筛选 + 排序 + 搜索 + 为你推荐）、作品详情、编辑、我的作品、投稿、模型页、排行榜、登录、注册、验证邮箱、找回密码、审核队列、模型导入、Dev Room（仅开发环境）。

### 6.2 控件库与 Dev Room

12 个控件（按钮、输入、文本域、下拉、复选框、文件选择、分页、评分、骨架、空态、错误态、主题切换），33 个登记项，全部在 `/dev-room` 演示所有变体。规则：页面不许直接用第三方控件，控件库是唯一出口，新增控件必须同时登记 Dev Room（CI 的 `ui-contract` 强制）。

### 6.3 约定

- **服务端状态统一走 TanStack Query**：没有手写缓存层，`queryKey` 必须包含所有影响结果的参数。
- **筛选条件进 URL**：分享链接能复现同一屏。
- **文案全中文**，代码标识符全英文。
- 页面级组件放 `features/`，路由放 `routes/`，两条路径都不许直接写原生 `<button>` / `<textarea>`（门禁扫描）。

## 7. 工程保障

### 7.1 CI 七道必过检查

| 检查 | 耗时 | 管什么 |
| --- | --- | --- |
| `backend` | ~2.5 min | 编译、vet、gofmt、全量集成测试（真 PostgreSQL） |
| `frontend` | ~40 s | tsc、eslint、prettier、vitest |
| `contract` | ~2 min | 契约与两侧生成物一致（`git diff --exit-code`） |
| `ui-contract` | ~20 s | 控件库导出 ↔ Dev Room 登记项一致；页面不许用原生控件 |
| `file-size` | ~20 s | 单文件 >500 警告 / >800 失败；顺带跑 10 道脚本门禁 |
| `pr-guard` | ~10 s | 关联 issue、单一类型、手写文件 ≤20、review 晚于最新 commit 且含结论段 |
| `e2e` | ~1.5 min | 真浏览器跑闭环、生命周期、模型页（已升为必过） |

### 7.2 脚本门禁

13 道，超过 200 条自测。挑几道说清"能证明什么、不能证明什么"：

| 门禁 | 能证明 | 不能证明 |
| --- | --- | --- |
| `check-migrations` | 迁移只增不改、校验和一致 | 迁移在真库上跑得通（那是 `verify-schema` 的事） |
| `check-api-compat` | 没删端点、没改窄字段 | 新端点有实现 |
| `check-negative-cases` | 每个端点有一条反例且指向真实测试 | 那条测试真的压住了判据（要靠反向验证） |
| `check-single-source` | 某个判据的文本副本数没增加 | 判据本身没被删掉（这条门禁按文本计数，删掉副本反而变绿） |
| `check-docs-refs` | 文档里提到的仓库路径都存在 | 文档说的是对的 |
| `check-shape-docs` | 代码 / 数据库 / 文档三方对"类型收哪些格式"说法一致 | 散文部分正确 |

### 7.3 测试分布

- **后端**：每个域一套集成测试打真库，覆盖投稿/改稿/回滚/生命周期/评分/榜单/搜索/模型导入/权限。
- **前端**：24 个文件 / 173 条用例，页面级用 Testing Library，控件级单独测。
- **e2e**：12 条，覆盖"注册→投稿→审核→发布→可见"与生命周期、模型页。
- **反向验证**是一等公民：每批修 bug 都要先让测试红一次，确认红在对的断言上，再修。

### 7.4 文档体系

36 篇设计文档（需求 19 域、各域数据结构、开发流程、部署、运行手册，含本篇）+ **已知松点台账（60 条）**。松点是一条一条登记的"我们知道它不牢靠、但当前选择先接受"的地方，每条写明：怎么坏的、什么时候会咬人、修的时候该怎么做。

## 8. 现状评估

### 8.1 做得扎实的

- **数据一致**：可见性、时间顺序、版本分离三件事都有数据库级别的约束或视图兜着，不靠"记得这么写"。
- **契约驱动**：进入代码之前先有类型，前后端不会各自理解一套。
- **可回退**：版本历史与回滚是作者可用的功能，不是只有运维能做。
- **部署进仓库**：三种部署形态各有文件与门禁，不是"当时那么跑的"。

### 8.2 已知缺口

**功能缺口**（用户能感知）：通知、作者主页、评论/收藏/关注、浏览历史页、运营后台（精选、批量治理）、分类自助新增词条。

**技术债**（不会立刻咬人，但都记着）：

| 编号 | 问题 | 什么时候咬人 |
| --- | --- | --- |
| 45 | 长期凭据只有 30 天会话 cookie，没有 PAT | 有人要写脚本上传作品时 |
| 51 | 模型目录镜像只能靠 psql 灌一条 | 需要多来源目录时 |
| 56 | nginx + systemd 配置没在真机跑过 | 第一次裸机上线时 |
| 58 | 容器 TLS 只在自签模式验证过，真域名 + ACME 没跑 | 第一次配真域名时 |
| 60 | 内置三维查看器没带 draco/basis/meshopt 解码器 | 作者导出压缩过的 glb 时 |
| 46 | `check-single-source` 按文本计数，能靠删副本变绿 | 有人想"让 CI 变绿"时 |

**架构限制**（设计上就接受的）：搜索是全表 `ILIKE`（一万件以内够用，再往上要重建检索）；单实例部署（`pg_try_advisory_lock` 已经把多实例的定时任务锁住了，但会话与限流还是单机内存）；论坛外置。

### 8.3 做过的取舍（举例）

- **分类挂作品、模型挂版本**：分类是运营口径，改分类不该产生新版本；模型是作者声明，属于某一版内容。
- **审核通过才切换线上**：作者改稿期间旧版本继续服务，代价是对外内容可能落后于作者手上的版本。
- **榜单六口径都放 `demo_stats`**：不新建表，代价是统计列与业务列混在一张表里。
- **删除即刻定型恢复期**：`purge_after` 写进 GC 队列，不按"当前配置"重算——承诺一个自己做不到的恢复期更糟。

## 9. 下一步

已经批准、按顺序做：

1. **作者主页**（`/u/{username}`）：从作品点进作者，列出他的公开作品。DEMO-043 里"从详情继续到作者"的落点。
2. **通知**：审核结果、有人评分。需要一张表、一个未读数、一个列表页。
3. **列表与搜索的索引**：实测 5000 件时是 `Seq Scan` + top-N 排序（4–10 ms），作品上万再动；届时先加 `(created_at desc)` 与部分索引，再考虑换检索方案。

之后候选（按价值）：运营后台（精选与批量治理）、收藏与浏览历史、评论（需要先定审核策略）、多来源模型目录、PAT。
