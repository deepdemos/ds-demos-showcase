# 部署

这一篇解决「把仓库搬到一台空机器上，能不能跑起来」。答案在 2026-11-09 之前是**不能**：
仓库里没有反向代理配置、没有服务单元、没有一份写明必需环境变量的清单，
生产能跑起来靠的是当值的人记得住。现在这些都在 `deploy/` 下。

> **边界（先读）**：
>
> - **容器这条路（§10）实测跑起来过**：2026-11-10 在 WSL 的 docker 29.1.3 上
>   `docker compose up -d --build` 起齐 db / api / web，迁移自动应用、管理端登录、
>   模型目录同步 8965 条、SPA 与安全头都验过（清单见 §10.4）。
> - **宿主机 nginx + systemd 那条路（§5–§7）仍然没有在真机上执行过**：开发机上没有装 nginx，
>   `nginx -t` 与 `systemctl start` 都没跑过。能保证的只有 `scripts/check-deploy.mjs`
>   静态检查的那几条（见 §6），其余以部署机上第一次 `nginx -t` + §7 验证清单为准。

## 1. 组成

| 组件 | 跑在哪 | 由谁提供 |
|---|---|---|
| `web/dist`（静态站） | nginx 的 `root` | `npm run build`（前端） |
| Go API | 127.0.0.1:8080 | `deploy/systemd/deepdemos-api.service` |
| PostgreSQL 18 | 同机或内网 | 发行版的 postgres 包 |
| nginx | 80 / 443 | 发行版的 nginx 包 + `deploy/nginx/deepdemos.conf` |

前端与 API **同域**：`/api/`、`/healthz`、`/preview/`、`/download/` 反代给 Go，其余是静态文件。
同域不是风格选择——会话 cookie 是 `__Host-` 前缀、`SameSite=Lax`，跨域要么改 cookie 属性，
要么每次请求都要预检，两条都不划算。

## 2. 目录与账号

```bash
sudo useradd --system --home /srv/deepdemos --shell /usr/sbin/nologin deepdemos
sudo install -d -o deepdemos -g deepdemos /srv/deepdemos/storage
sudo install -d -o root -g deepdemos -m 0750 /etc/deepdemos
```

`storage` 是作品文件的根（`STORAGE_ROOT`）：里面是 `blobs/<前两位>/<sha256>` 与清单引用的对象。
**不要**把它放在临时目录或容器可写层——内容寻址的对象是作品的唯一副本。

## 3. 环境变量（`/etc/deepdemos/api.env`，0640，root:deepdemos）

| 变量 | 必需 | 说明 |
|---|---|---|
| `DATABASE_URL` | 是 | `postgres://user:pass@host:5432/deepdemos?sslmode=disable`（同机可 disable；跨机要开 TLS） |
| `STORAGE_ROOT` | 是 | 默认 `./var/storage`，生产必须显式给绝对路径 |
| `PORT` | 否 | 默认 `8080`，与 nginx `upstream` 一致 |
| `VERIFICATION_SECRET` | **是** | 邮箱验证码的签名密钥。**配了数据库却不配它，进程会直接退出**：多实例各发各的码，用户看到的是「验证码总是错」 |
| `IP_HASH_SECRET` | 是 | 匿名访客键（浏览去重、评分去重）的 HMAC 密钥；换掉等于把所有人变成新访客 |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASS` / `SMTP_FROM` | 生产是 | 不配就退化成日志模式（验证码写进日志），只能在开发用 |
| `MAIL_LOG_CODES` | 否 | `1` = 把验证码打进日志。**生产不要开**，那等于把验证码公开 |
| `MODEL_CATALOG_URL` | 否 | 模型目录镜像的地址，默认 models.dev；测试里指到本地假源 |
| `CSRF_MODE` | 否 | 跨站检查档位：`off` / `log` / `enforce`，默认 `log`。**首次上线必须先用 log 跑一轮**（见 §5.1） |

两个密钥用 32 字节随机值：

```bash
printf 'VERIFICATION_SECRET=%s\n' "$(openssl rand -hex 32)" | sudo tee -a /etc/deepdemos/api.env
printf 'IP_HASH_SECRET=%s\n'       "$(openssl rand -hex 32)" | sudo tee -a /etc/deepdemos/api.env
sudo chmod 0640 /etc/deepdemos/api.env
```

**密钥丢了会怎样**：`VERIFICATION_SECRET` 丢了 → 已经在路上的验证码全部作废，重发即可；
`IP_HASH_SECRET` 丢了 → 所有匿名访客的浏览/评分去重键变化，同一个人当天能再投一次票。
两个都不是「换个值就行」的开关，写进变更记录。

## 4. 数据库

```bash
# 建库与角色（示例）
sudo -u postgres psql -c "CREATE ROLE deepdemos LOGIN PASSWORD '…';"
sudo -u postgres psql -c "CREATE DATABASE deepdemos OWNER deepdemos;"

# 迁移：基线是 db/schema 下的冻结文件，之后全部变化在 db/migrations
DATABASE_URL=… ./deepdemos-api-migrate up      # cmd/migrate
# 种子：分类词表、模型样例、开发用作品（生产只跑前两个，见各文件头注释）
DATABASE_URL=… ./deepdemos-api-migrate seed
```

迁移只增不改：已应用的迁移文件改了校验和，`migrate up` 会拒绝启动。
真要改表结构，加新迁移。

**第一个管理员**只能由命令行创建（没有「先到先得」的注册口子）：

```bash
DATABASE_URL=… ./deepdemos-admin-grant \
  -email admin@example.com -username admin -display 管理员
```

密码从 `ADMIN_GRANT_PASSWORD` 读；不设就随机生成并打印一次。

## 5. nginx

```bash
sudo cp deploy/nginx/deepdemos.conf                  /etc/nginx/conf.d/
sudo cp deploy/nginx/security-headers.conf           /etc/nginx/conf.d/deepdemos-security-headers.conf
sudo nginx -t && sudo systemctl reload nginx
```

两件事按实际情况改：

1. `root /srv/deepdemos/web;` 指向 `npm run build` 的产物目录。
2. `ssl_certificate` 两行指向你的证书。**还没有证书时**：把整个 `listen 443` 的 server 块注释掉，
   只留 80（先别配 `return 301 https`，否则站点直接不可用）。

安全头单独成文件不是洁癖：nginx 的 `add_header` 在 location 里是**整体覆盖** server 级的，
哪个 location 自己加了缓存头却忘了 include，CSP 就静默消失。

### 5.1 跨站检查（CSRF）怎么开

本站只有一个客户端（同域前端），所以跨站检查用的是标准库
`http.CrossOriginProtection`：浏览器发 `Sec-Fetch-Site`，标准库据此判跨站；
老浏览器不发这个头时退回比对 `Origin` 与 `Host`。没有 token，也没有每张表单一个随机数。

三档，来自 `CSRF_MODE`：

| 档位 | 行为 | 什么时候用 |
|---|---|---|
| `log`（默认） | 判定、写日志、**放行** | 首次上线；接新流程（OAuth 回调、论坛 SSO）之后观察一轮 |
| `enforce` | 判定、写日志、回 403 `forbidden` | 确认日志里没有误判之后 |
| `off` | 完全不看 | 只在排查「这个 403 是不是它拦的」时临时用 |

观察期看哪一行日志：

```bash
journalctl -u deepdemos-api -f | grep '跨站请求检查未通过'
```

日志里带 `method` / `path` / `sec_fetch_site` / `origin` / `host` / `mode`。
**没有这条日志、却有用户说提交失败**，说明问题不在 CSRF 这层。

判定口径来自 OWASP 的 CSRF 备忘单：Fetch Metadata 优先、`Origin` 兜底、
SameSite cookie 只算纵深防御、token 留给「要兼容老浏览器或有跨站调用方」的场景。

## 6. 门禁能证明什么

`scripts/check-deploy.mjs`（CI 的 `file-size` job 里跑）检查的是**结构与关键行**：

- `deploy/nginx/deepdemos.conf` 存在，且 `/api/`、`/healthz`、`/preview/`、`/download/` 四段反代都在；
- SPA 回退 `try_files … /index.html` 在；
- 上传上限 `client_max_body_size` ≥ 契约的 200 MiB；
- `security-headers.conf` 里有 CSP、`nosniff`、`Referrer-Policy`，且 CSP 含 `script-src 'self'`
  与 `frame-ancestors`；
- systemd 单元有 `EnvironmentFile=` 与 `ExecStart=`。

它**证明不了**：语法正确、能启动、头真的发出去了、上传真的能过 200 MiB。
这些只能靠 §7 在部署机上验。

## 7. 部署后验证清单

```bash
# 1) 进程活着、库连得上（healthz 返回 200 且 body 里 database ok）
curl -sS -o /dev/null -w '%{http_code}\n' https://HOST/healthz

# 2) 契约端点通
curl -sS https://HOST/api/v1/demos | head -c 200

# 3) SPA 深链不被 404（刷新 /demos/<slug> 仍然是页面，不是 nginx 404）
curl -sS -o /dev/null -w '%{http_code}\n' https://HOST/demos/not-a-real-slug

# 4) 安全头真的发出去了
curl -sSI https://HOST/ | grep -i -E 'content-security-policy|referrer-policy|x-content-type-options'

# 5) 静态产物是长缓存、入口不是
curl -sSI https://HOST/assets/$(ls web/dist/assets | head -1) | grep -i cache-control
curl -sSI https://HOST/ | grep -i cache-control

# 6) 大包上传不被 nginx 挡住（用一个真包，别用 /dev/null）
curl -sS -o /dev/null -w '%{http_code}\n' -F 'title=t' -F 'description=d' -F 'demoType=web' \
     -F 'package=@big.zip' -H "Cookie: __Host-demo_session=…" https://HOST/api/v1/demos
```

第 3 条最容易漏：少了 `try_files … /index.html`，站内跳转都正常，**只有刷新**才 404。

## 8. 回滚

- 代码：上一版二进制 + 上一版 `web/dist`（静态产物按 `assets` 的哈希天然多版本共存，回滚只是换 `index.html`）。
- 数据库：迁移只增不改，回滚代码不回滚表结构——旧代码必须能读新表。
  真要退掉一个迁移，写一条反向迁移，别手改 `schema_migrations`。
- 配置：`nginx -t` 通过前不要 reload；reload 失败 nginx 会保留旧配置继续服务。

## 10. 用 docker compose 部署（推荐，已实测）

一条命令把三件事起齐：`db`（postgres 18）+ `api`（Go 二进制 + 迁移）+ `web`（nginx + 静态产物 + 反代）。
适合一台干净机器上「先跑起来」，也适合把整套环境复制到另一台机器。

```bash
cp deploy/docker/env.example .env     # 改掉口令与两个 secret
docker compose up -d --build
docker compose ps                     # db / api 都是 healthy 才算起来
```

对外只有一个端口：`WEB_PORT`（默认 8080 → 容器内 nginx 的 80）。
**api 与 db 都不发布端口**——反代与 API 在同一 compose 网络里，把 8080 暴露出去等于绕过安全头与限流。

### 10.1 文件分工

| 文件 | 做什么 | 为什么单独一个 |
|---|---|---|
| `docker-compose.yml` | 三个服务、两处数据卷、健康检查、依赖顺序 | 部署入口；`.env` 由它读 |
| `deploy/docker/api.Dockerfile` | 多阶段编译 `api` / `migrate` / `admin-grant`，非 root 运行 | 运行镜像里要有迁移器，否则「起服务」与「建表」是两步人工操作 |
| `deploy/docker/web.Dockerfile` | pnpm 构建 → nginx 静态托管 | 静态资源的扩缩容节奏与 API 不同 |
| `deploy/docker/nginx.conf.template` | 容器版反代：上游是 `api:8080` | 官方 nginx 镜像会 `envsubst` 渲染 `templates/`，镜像与部署环境无关 |
| `deploy/docker/entrypoint-api.sh` | 等库 → 跑迁移 → 起服务 | 全新部署 `up -d` 一次可用，不必记「先 migrate」 |
| `deploy/docker/env.example` | 环境变量样例 | 口令与 secret 不能进仓库 |

宿主机版（§5 的 `deploy/nginx/deepdemos.conf` + `deploy/systemd/`）与容器版的路由分工、缓存策略、
安全头必须一致，差别只有两处：上游是容器名而不是 `127.0.0.1`，TLS 交给外层（反代 / LB / Cloudflare）。

### 10.2 三个必须知道的坑（都是实测踩出来的）

1. **postgres 18 的数据卷要挂在 `/var/lib/postgresql`（父目录），不是 `.../data`**。
   挂错的表现不是报错，而是容器起来又立刻退出，日志里说「检测到旧版本残留的数据」。
2. **国内构建机需要 Go 模块代理**。`proxy.golang.org` 会 31 秒超时；Dockerfile 里
   `ARG GOPROXY=https://goproxy.cn,direct` 已经是默认值，海外构建机可以
   `--build-arg GOPROXY=direct` 覆盖。
3. **`pnpm-workspace.yaml` 必须和 `package.json` 一起进依赖层**。里面写着 `allowBuilds`（core-js），
   少了它容器里的 pnpm 会以 `ERR_PNPM_IGNORED_BUILDS` 失败——本地能装、镜像装不了，就是这一行的差别。

### 10.3 登录 cookie 要求 HTTPS（容器版只开 80）

会话 cookie 是 `__Host-demo_session`，带 `Secure`。**浏览器在 `http://` 下不会存它**，
所以直接开 `http://IP:8080` 能看页面、却登不进去（curl 手工带 `Cookie:` 头可以，实测过）。
生产必须由外层终止 TLS：

```nginx
# 外层反代（或 Caddy / Cloudflare）
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host              $host;
    proxy_set_header X-Forwarded-Proto https;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_read_timeout 300s;
    client_max_body_size 220m;
}
```

Caddy 只要两行：`example.com { reverse_proxy 127.0.0.1:8080 }`（它自己申请证书）。

### 10.4 容器版验证清单（2026-11-10 全过）

```bash
docker compose ps                                   # db / api = healthy，web = running
docker compose logs api | tail -5                    # 「应用迁移… 没有待应用的迁移」「api listening」
curl -sS -o /dev/null -w '%{http_code}\n' http://HOST:8080/healthz
curl -sS http://HOST:8080/api/v1/demos | head -c 120
curl -sS -o /dev/null -w '%{http_code}\n' http://HOST:8080/demos/not-a-real-slug   # SPA 深链 200
curl -sSI http://HOST:8080/ | grep -i -E 'content-security-policy|x-content-type-options'
curl -sS -o /dev/null -w '%{http_code}\n' http://HOST:8080/preview/nope/            # 404 且是中文 HTML 兜底页

# 空库没有账号，第一个管理员必须在容器里建
docker compose exec -T -e ADMIN_GRANT_PASSWORD='…' api ./admin-grant \
  -email admin@example.com -username admin -display 管理员
```

实测结果：迁移自动应用（基线 + 22 条）、模型目录同步 8965 条、管理端审核队列 200、
`/api/v1/models` 与榜单 200、`/` 返回 SPA 且带 CSP、`/preview/nope/` 走 HTML 兜底页。

### 10.5 容器版的边界

- `db-data` 与 `storage` 两个命名卷是**唯一**的数据；`docker compose down -v` 会一起删掉。
  备份用 `docker run --rm -v deepdemos_db-data:/data alpine tar czf - /data > db.tgz`，
  或者把卷换成宿主机目录（`./var/db:/var/lib/postgresql`）。
- 单机单实例。多实例（共享存储、迁移只能一个人跑、`pg_try_advisory_lock` 抢锁）还没做，见松点 57。
- 镜像没有签名与 SBOM；供应链按「构建机可信」处理。

### 10.6 开 TLS（浏览器登录的前提）

会话 cookie 是 `__Host-demo_session`：**带 `Secure`，浏览器在 http 下根本不存**。
所以「用浏览器登进去」这件事在 http 上是做不到的（curl 手工带 Cookie 可以，之前那些
手测就是这么做的）。容器版为此带了一个 Caddy 侧车，证书与续期都归它，nginx 那层只管
静态站与反代。

``bash
# 生产：DOMAIN 必须是你实际访问的地址（证书按它签发，SNI 也必须对上）
DOMAIN=deepdemos.example.com ACME_EMAIL=ops@example.com \
  docker compose --profile tls up -d

# 本地 / 内网自签：换成内网 Caddyfile，证书由 Caddy 自己的 CA 签
DOMAIN=192.168.15.155 CADDYFILE=deploy/docker/Caddyfile.internal \
  TLS_HTTP_PORT=8081 TLS_HTTPS_PORT=8443 docker compose --profile tls up -d
``

要点：

- `--profile tls` 是分档的：不加这个参数，Caddy 服务根本不会起，前面的 §10.1 完全不受影响。
- 证书存在 `caddy-data` 卷里（`/data/caddy`）。换机器只迁数据时记得连它一起迁，否则会重新申请。
- 自签模式下浏览器第一次会提示不受信任，点继续即可；要让 curl 认它：

  ``bash
  docker compose cp caddy:/data/caddy/pki/authorities/local/root.crt ./caddy-root.crt
  curl --cacert caddy-root.crt https://localhost:8443/healthz
  ``

- **SNI 必须对上**：`DOMAIN=localhost` 时直接访问 `https://127.0.0.1:8443` 会在 TLS 握手
  报 `tlsv1 alert internal error`（Caddy 没有匹配 `127.0.0.1` 的站点）。要么把 `DOMAIN`
  写成实际访问的地址，要么用 `curl --resolve localhost:8443:127.0.0.1`。

实测（`DOMAIN=localhost` + 自签 + 8443）：`/` 200、`/healthz` 200、`/api/v1/demos` 200、
`/preview/nope/` 404 且带 `sandbox` CSP、**登录 200 且 cookie 被保存**（`#HttpOnly_localhost`），
带 cookie 访问 `/api/v1/admin/reviews/demo` 200。

注意 `docker compose logs caddy` 里如果出现
`required variable DOMAIN is missing a value`，是那一次 `up` 没带 `DOMAIN`——Caddy 起不来，
但 db/api/web 照常，容易误判成「TLS 没生效」。
