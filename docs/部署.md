# 部署

这一篇解决「把仓库搬到一台空机器上，能不能跑起来」。答案在 2026-11-09 之前是**不能**：
仓库里没有反向代理配置、没有服务单元、没有一份写明必需环境变量的清单，
生产能跑起来靠的是当值的人记得住。现在这些都在 `deploy/` 下。

> **边界（先读）**：这些配置文件**没有在真实 nginx / systemd 上执行过**。
> 开发机上没有装 nginx（也没有 docker），所以 `nginx -t` 与 `systemctl start` 都没跑过。
> 能保证的只有 `scripts/check-deploy.mjs` 静态检查的那几条（见 §6），
> 其余一律以部署机上第一次 `nginx -t` + §7 验证清单为准。

## 1. 组成

| 组件 | 跑在哪 | 由谁提供 |
|---|---|---|
| `web/dist`（静态站） | nginx 的 `root` | `npm run build`（前端） |
| Go API | 127.0.0.1:8080 | `deploy/systemd/deepdemos-api.service` |
| PostgreSQL 18 | 同机或内网 | 发行版的 postgres 包 |
| nginx | 80 / 443 | 发行版的 nginx 包 + `deploy/nginx/deepdemos.conf` |

前端与 API **同域**：`/api/`、`/healthz`、`/preview/`、`/download/` 反代给 Go，其余是静态文件。
同域不是风格选择——会话 cookie 是 `__Host-` 前缀、`SameSite=Lax`，跨域要么改 cookie 属性，
要么每次请求都要预检，两条都不划算。

## 2. 目录与账号

```bash
sudo useradd --system --home /srv/deepdemos --shell /usr/sbin/nologin deepdemos
sudo install -d -o deepdemos -g deepdemos /srv/deepdemos/storage
sudo install -d -o root -g deepdemos -m 0750 /etc/deepdemos
```

`storage` 是作品文件的根（`STORAGE_ROOT`）：里面是 `blobs/<前两位>/<sha256>` 与清单引用的对象。
**不要**把它放在临时目录或容器可写层——内容寻址的对象是作品的唯一副本。

## 3. 环境变量（`/etc/deepdemos/api.env`，0640，root:deepdemos）

| 变量 | 必需 | 说明 |
|---|---|---|
| `DATABASE_URL` | 是 | `postgres://user:pass@host:5432/deepdemos?sslmode=disable`（同机可 disable；跨机要开 TLS） |
| `STORAGE_ROOT` | 是 | 默认 `./var/storage`，生产必须显式给绝对路径 |
| `PORT` | 否 | 默认 `8080`，与 nginx `upstream` 一致 |
| `VERIFICATION_SECRET` | **是** | 邮箱验证码的签名密钥。**配了数据库却不配它，进程会直接退出**：多实例各发各的码，用户看到的是「验证码总是错」 |
| `IP_HASH_SECRET` | 是 | 匿名访客键（浏览去重、评分去重）的 HMAC 密钥；换掉等于把所有人变成新访客 |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASS` / `SMTP_FROM` | 生产是 | 不配就退化成日志模式（验证码写进日志），只能在开发用 |
| `MAIL_LOG_CODES` | 否 | `1` = 把验证码打进日志。**生产不要开**，那等于把验证码公开 |
| `MODEL_CATALOG_URL` | 否 | 模型目录镜像的地址，默认 models.dev；测试里指到本地假源 |

两个密钥用 32 字节随机值：

```bash
printf 'VERIFICATION_SECRET=%s\n' "$(openssl rand -hex 32)" | sudo tee -a /etc/deepdemos/api.env
printf 'IP_HASH_SECRET=%s\n'       "$(openssl rand -hex 32)" | sudo tee -a /etc/deepdemos/api.env
sudo chmod 0640 /etc/deepdemos/api.env
```

**密钥丢了会怎样**：`VERIFICATION_SECRET` 丢了 → 已经在路上的验证码全部作废，重发即可；
`IP_HASH_SECRET` 丢了 → 所有匿名访客的浏览/评分去重键变化，同一个人当天能再投一次票。
两个都不是「换个值就行」的开关，写进变更记录。

## 4. 数据库

```bash
# 建库与角色（示例）
sudo -u postgres psql -c "CREATE ROLE deepdemos LOGIN PASSWORD '…';"
sudo -u postgres psql -c "CREATE DATABASE deepdemos OWNER deepdemos;"

# 迁移：基线是 db/schema 下的冻结文件，之后全部变化在 db/migrations
DATABASE_URL=… ./deepdemos-api-migrate up      # cmd/migrate
# 种子：分类词表、模型样例、开发用作品（生产只跑前两个，见各文件头注释）
DATABASE_URL=… ./deepdemos-api-migrate seed
```

迁移只增不改：已应用的迁移文件改了校验和，`migrate up` 会拒绝启动。
真要改表结构，加新迁移。

**第一个管理员**只能由命令行创建（没有「先到先得」的注册口子）：

```bash
DATABASE_URL=… ./deepdemos-admin-grant \
  -email admin@example.com -username admin -display 管理员
```

密码从 `ADMIN_GRANT_PASSWORD` 读；不设就随机生成并打印一次。

## 5. nginx

```bash
sudo cp deploy/nginx/deepdemos.conf                  /etc/nginx/conf.d/
sudo cp deploy/nginx/security-headers.conf           /etc/nginx/conf.d/deepdemos-security-headers.conf
sudo nginx -t && sudo systemctl reload nginx
```

两件事按实际情况改：

1. `root /srv/deepdemos/web;` 指向 `npm run build` 的产物目录。
2. `ssl_certificate` 两行指向你的证书。**还没有证书时**：把整个 `listen 443` 的 server 块注释掉，
   只留 80（先别配 `return 301 https`，否则站点直接不可用）。

安全头单独成文件不是洁癖：nginx 的 `add_header` 在 location 里是**整体覆盖** server 级的，
哪个 location 自己加了缓存头却忘了 include，CSP 就静默消失。

## 6. 门禁能证明什么

`scripts/check-deploy.mjs`（CI 的 `file-size` job 里跑）检查的是**结构与关键行**：

- `deploy/nginx/deepdemos.conf` 存在，且 `/api/`、`/healthz`、`/preview/`、`/download/` 四段反代都在；
- SPA 回退 `try_files … /index.html` 在；
- 上传上限 `client_max_body_size` ≥ 契约的 200 MiB；
- `security-headers.conf` 里有 CSP、`nosniff`、`Referrer-Policy`，且 CSP 含 `script-src 'self'`
  与 `frame-ancestors`；
- systemd 单元有 `EnvironmentFile=` 与 `ExecStart=`。

它**证明不了**：语法正确、能启动、头真的发出去了、上传真的能过 200 MiB。
这些只能靠 §7 在部署机上验。

## 7. 部署后验证清单

```bash
# 1) 进程活着、库连得上（healthz 返回 200 且 body 里 database ok）
curl -sS -o /dev/null -w '%{http_code}\n' https://HOST/healthz

# 2) 契约端点通
curl -sS https://HOST/api/v1/demos | head -c 200

# 3) SPA 深链不被 404（刷新 /demos/<slug> 仍然是页面，不是 nginx 404）
curl -sS -o /dev/null -w '%{http_code}\n' https://HOST/demos/not-a-real-slug

# 4) 安全头真的发出去了
curl -sSI https://HOST/ | grep -i -E 'content-security-policy|referrer-policy|x-content-type-options'

# 5) 静态产物是长缓存、入口不是
curl -sSI https://HOST/assets/$(ls web/dist/assets | head -1) | grep -i cache-control
curl -sSI https://HOST/ | grep -i cache-control

# 6) 大包上传不被 nginx 挡住（用一个真包，别用 /dev/null）
curl -sS -o /dev/null -w '%{http_code}\n' -F 'title=t' -F 'description=d' -F 'demoType=web' \
     -F 'package=@big.zip' -H "Cookie: __Host-demo_session=…" https://HOST/api/v1/demos
```

第 3 条最容易漏：少了 `try_files … /index.html`，站内跳转都正常，**只有刷新**才 404。

## 8. 回滚

- 代码：上一版二进制 + 上一版 `web/dist`（静态产物按 `assets` 的哈希天然多版本共存，回滚只是换 `index.html`）。
- 数据库：迁移只增不改，回滚代码不回滚表结构——旧代码必须能读新表。
  真要退掉一个迁移，写一条反向迁移，别手改 `schema_migrations`。
- 配置：`nginx -t` 通过前不要 reload；reload 失败 nginx 会保留旧配置继续服务。
