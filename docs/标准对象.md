# 标准对象

跨域共用的概念在这里定义**一次**，域文档只引用、不重抄。它不是域的目录，也不是导论——它是**字典**：查一个概念到底有几个值、谁能改、在哪一列上。

**为什么存在**：账号状态曾经同时出现在身份域 DDL、身份域状态机图、治理域迁移表、生命周期账号轴四处，其中三处是旧值——注册流程按它写的 DDL 根本插不进去。这不是个人疏忽，是「同一件事有好几份事实源」的必然结果。判据只有一条：**两个及以上域必须读到同一值域时，它才是标准对象**；只在一个域内用的枚举留在那个域里，搬过来只是搬家。

## 分册

按**性质**切，不按域切。一册一类，互相之间没有先后依赖。

**状态 vs 枚举的界线**：有迁移边（谁能在什么前置条件下从哪个值到哪个值）的是状态，放第一册；只是一组取值、写入后不再「流动」的是枚举，放第二册。目录表（`roles` / `permissions` / `audit_actions` …）一定在第二册——它们的「值」是数据行，加值靠 `INSERT`。

## 怎么用

**引用写法**：`标准对象 §ST-1`（册内可省「标准对象」）。域文档里**允许**保留形态图、端点表、权限 key、自保护规则、论证——这些是「怎么用」；**不允许**再抄一份完整取值集合或一份完整 CHECK，那是第二份事实源。

**权威切分**：本文件负责「取值域 / 迁移边 / 不变量 CHECK / 目录表 DDL 与种子」；域文档负责「端点 / 谁能改 / 为什么这么定 / 本域视角的投影图」。两边冲突时**以本文件为准**，并在域文档里改成指针。

**门禁**：`scripts/check-objects.mjs`（CI 的 `file-size` job 内跑）三条断言——重复枚举（旁边 7 行内无锚点则报）、值集走样（与权威共享 ≥2 个取值但集合不同则报）、引用键格式与登记表成员。它只管「形态」，不管「语义」：迁移边漏画、端点写错，它一律不报。

## 不登记什么

- **只在一个域内用的枚举**：`credential.kind`、`platform_forms`、`blob.kind`（等它被第二个域读到再搬）。
- **取值就是业务数据的表**：`classifications`（用户可增可删，值域不封闭）。
- **域内的操作规则**：自保护五条、批量上限 200、二次确认文案——它们是策略不是取值。
- **可变常量**：上限、阈值、保留期这类「值本身会变」的东西登记在 [`运行手册-可变常量.md`](运行手册-可变常量.md)，运行时可改的再进设置域 `setting_keys`。**本文件登记取值域，手册登记可变常量，两者不重叠**——同一个数不会既在 EN-x 又在手册里。
- **未设计的域**：公告 / 论坛 / 搜索等，等那个域设计时把需要共享的部分登记进来。（`settings` 已于 v2.2 登记为 `EN-9`。）
