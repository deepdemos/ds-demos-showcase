# 作品形态接入清单

这份文件回答一个问题：**作者能投什么，投上来之后平台怎么处理**。

它有三份对照物，缺一不可：

- 代码：`backend/internal/domain/demo/shapes.go` —— 格式词汇的唯一出处
  （`singleFileKinds` 决定哪些扩展名能投、`ZipFormatOf` 决定 zip 是哪一种包）；
- 数据：`db/migrations/*.sql` 里 `demo_type_formats` 的登记 —— 哪个类型收哪些格式；
- 本文件：给作者与审核看的表格。

门禁 `scripts/check-shape-docs.mjs` 会比对这三者：代码认识的格式必须在这里写到，
数据库里每对（类型, 格式）必须出现在对应行，本文件也不许写代码不认识的格式。

## 类型与格式

| 类型 | 收哪些格式 | 入口文件 | 预览与下载 |
| --- | --- | --- | --- |
| web（网页作品） | `single:html`、`single:svg`、`zip:html` | 单文件：这份文件本身就是入口；zip：根目录的 `index.html` | 直接打开；单文件里没有别的资源 |
| zip（压缩包作品） | `zip:html` | 根目录的 `index.html` | 与 web 的 zip 完全一样，区别只在作者怎么描述它 |
| godot（Godot 游戏） | `zip:godot` | 根目录的 `index.html`，且包内同时有脚本（`.wasm` / `.asm.js`）与资源包（`.pck`） | 作为网页打开；导出时的资源路径必须是相对路径 |
| image（图片） | `single:png`、`single:jpg`、`single:webp` | 这一份图片就是全部内容 | 直接显示图片本身 |
| model（三维模型） | `single:glb` | 这一份 `.glb` 就是全部内容 | 平台内置查看页；原始字节在地址后面加 `?raw=1` |
| link（外链） | `url` | 不上传文件，只给一个外部地址 | 暂未开放：清单里留了位，投稿入口还没有 |

## 格式记法

| 记法 | 含义 | 落库 |
| --- | --- | --- |
| `single:<kind>` | 单文件作品 | `demo_revisions.single_file = <kind>`，`entry_path = index.<ext>` |
| `zip:html` | 普通 HTML 站点包 | `single_file` 为空，`entry_path = index.html` |
| `zip:godot` | Godot 导出的 Web 包 | 同上，审核时按 Godot 包看待 |
| `url` | 外链，没有上传文件 | 暂无 |

`.htm` 与 `.jpeg` 是同一回事的另一种写法：它们分别落到 `html` 与 `jpg`，
预览时给的 Content-Type 不会因为扩展名写法不同而分叉。

## 加一种格式要改哪三处

1. `backend/internal/domain/demo/shapes.go` 的 `singleFileKinds`（或 zip 识别规则）；
2. 一条新迁移，往 `demo_type_formats` 插（如果要让某个类型收它）；
3. 本文件的表格，以及对应的作者指南。

形态矩阵用例 `TestIntegrationSubmitShapeMatrix` 会随 `SubmitShapes()` 自动多一行，
所以「新格式预览打不开」这件事不会没人测。
