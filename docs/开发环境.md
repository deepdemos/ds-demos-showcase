# 本地开发环境

> 这份文件回答一个问题：**在一台干净的机器上，把这个站跑起来要几步。**
>
> 不写「我这台机器上是什么路径」——那不是通用事实（见 `AGENTS.md` 安全红线）。

## 需要什么

| 组件 | 版本 | 用途 |
| --- | --- | --- |
| Go | 1.27+ | API 与迁移器 |
| Node.js | 24+ | 仓库工具（门禁脚本）与前端 |
| pnpm | 11+ | 前端（`web/`）；根目录用 npm |
| PostgreSQL | **18**（与 CI 一致） | 唯一数据库 |

`90-extensions.sql` 需要 `pg_trgm`。真库装上 `postgresql-contrib` 即可；PGlite（WASM 版）
没有 contrib，`verify-schema.mjs` 会跳过那个文件并在回执里写明——**跳过不等于验过**。

## 数据库跑在哪

三种都行，按手边有什么选：

1. **本机装了 PostgreSQL 18** —— 最省事；
2. **Docker** —— `docker run -d -p 5432:5432 -e POSTGRES_PASSWORD=postgres postgres:18`；
3. **Windows + WSL2 里有 Ubuntu** —— 见下，Windows 上没有原生 PG 时这条最省事。

### WSL2 里跑 PostgreSQL

```bash
# 在 WSL 里（一次性）
sudo apt-get update && sudo apt-get install -y postgresql postgresql-contrib

# 想要和 CI 完全一致的 18：加 PGDG 源（Ubuntu 24.04 自带的是 16）
sudo install -d /usr/share/postgresql-common/pgdg
sudo curl -fsSL -o /usr/share/postgresql-common/pgdg/apt.postgresql.org.asc \
  https://www.postgresql.org/media/keys/ACCC4CF8.asc
echo 'deb [signed-by=/usr/share/postgresql-common/pgdg/apt.postgresql.org.asc] https://apt.postgresql.org/pub/repos/apt noble-pgdg main' \
  | sudo tee /etc/apt/sources.list.d/pgdg.list
sudo apt-get update && sudo apt-get install -y postgresql-18
sudo pg_createcluster 18 main -p 5433 --start   # 与自带的 16 错开端口

# 建库与角色
sudo -u postgres psql -p 5433 -c "CREATE ROLE deepdemos LOGIN PASSWORD 'deepdemos' CREATEDB;"
sudo -u postgres psql -p 5433 -c "CREATE DATABASE deepdemos OWNER deepdemos;"
```

**让 Windows 连得上**：WSL2 的 `localhost` 转发不一定对 PostgreSQL 生效（实测不通），
所以让 PG 监听所有地址，并从 Windows 用 **WSL 的 IP** 连：

```bash
# WSL 里
sudo sed -i "s/^#\?listen_addresses.*/listen_addresses = '*'/" /etc/postgresql/18/main/postgresql.conf
echo 'host all all 0.0.0.0/0 scram-sha-256' | sudo tee -a /etc/postgresql/18/main/pg_hba.conf
sudo pg_ctlcluster 18 main restart

# Windows 上取地址（每次 WSL 重启可能变）
wsl hostname -I
```

> `pg_hba` 那条 `0.0.0.0/0` 只适合开发机。**别把这份配置带进任何真实环境。**

**WSL 会空闲自动关机**，PG 跟着停。要它常驻，另开一个终端跑
`wsl -d <发行版名> -- sleep infinity`，或者把 PG 换成上面第 1、2 种。

## 把库推倒重来

改过 `db/schema/` 或 `db/migrations/` 之后，本地库的 `schema_migrations` 校验和会对不上
（`0014 的校验和与已应用的不一致——已合入的迁移不能改，请新增一条`）。开发库与测试库都可以
清空重来，代价是库里的手工数据没了——这些数据本该来自种子文件。

```bash
# 1) 停掉 API（它连着库，DROP 会等锁）
taskkill //F //IM api.exe

# 2) 清空 schema。**必须用 postgres 用户**：public 的属主是 postgres，
#    deepdemos 只是被授权，自己 DROP 会报 "must be owner of schema public"
wsl -d Ubuntu24.04.3 -- bash -lc "sudo -u postgres psql -p 5433 -d deepdemos   -c 'DROP SCHEMA public CASCADE; CREATE SCHEMA public; GRANT ALL ON SCHEMA public TO deepdemos;'"

# 3) 重建（在 backend/ 下）
DATABASE_URL='postgres://deepdemos:deepdemos@127.0.0.1:5433/deepdemos?sslmode=disable'   go run ./cmd/migrate up

# 4) 灌开发种子（幂等，可以反复跑）
wsl -d Ubuntu24.04.3 -- bash -lc "PGPASSWORD=deepdemos psql -h 127.0.0.1 -p 5433   -U deepdemos -d deepdemos -f /mnt/d/.../db/seeds/0001-dev-demos.sql"
```

测试库同理，只是库名换成 `deepdemos_test`、不灌种子（集成测试自己造数据）。

**种子现在会写版本行**（迁移 0014 起）：只写 `demos` 行、不写 `demo_revisions` 的作品会被
`published_revision_id IS NULL` 挡在列表外——「有审核态但没内容」是残缺数据，不是可以存在的状态。

## 跑起来

```bash
# 1) 建表（第一次）
cd backend
DATABASE_URL='postgres://deepdemos:deepdemos@<PG地址>:5433/deepdemos?sslmode=disable' \
  go run ./cmd/migrate up

# 2) 灌开发种子（可反复跑，30 条作品，含 6 条边界行）
DATABASE_URL='...' go run ./cmd/migrate seed

# 3) 起 API
DATABASE_URL='...' go run ./cmd/api        # 监听 :8080

# 4) 起前端（另开一个终端）
cd web
npm install          # 本机 pnpm 装不上时用 npm，见下
npx vite             # 默认 5173；端口被排除段占用时换一个，见下
```

`web/vite.config.ts` 已经把 `/api` 代理到 `http://127.0.0.1:8080`，所以前端不需要配
`VITE_API_BASE`。

### 第一个管理员

审核（`/admin/reviews`）要求 `accounts.role` 是 `admin` 或 `moderator`。生产上「第一个管理员」没有别的来源：
`POST /admin/users/{id}/role` 要求调用方**已经是**管理员，所以它产生不了第一个。用运维命令：

```bash
cd backend
DATABASE_URL='...' ADMIN_GRANT_PASSWORD='至少十个字符'   go run ./cmd/admin-grant -email you@example.com -username you -display 你的名字
```

- 账号已经在 → 只提权，**不碰口令**；目标角色已是当前角色 → 什么都不写（幂等，重跑安全）。
- 账号不存在 → 走注册那条路建号（accounts / users / profiles / account_emails / password_credentials 五张表一起写），再提权。
- `-role` 可以是 `roles` 表里任何登记过的角色，拼错会当场报 `identity: 角色未登记`。
- 封禁（`banned`）与已注销（`deleted`）的账号不会被提权：提权的输入是邮箱，而邮箱会写错，封禁账号往往正是出过事的那个人。
- 口令推荐走 `ADMIN_GRANT_PASSWORD` 环境变量：命令行参数会进 shell 历史。

注意 `accounts.role` **没有外键**指向 `roles`（见 [`已知松点.md`](已知松点.md) 第 29 条），所以角色名的合法性只在这条命令里校验。

## 两个本机常见坑

**`pnpm install` 报 `ERR_PNPM_EPERM: rename esbuild_tmp_… -> esbuild`**
pnpm 的包导入机制在某些 Windows 文件系统上会失败（换 `core-js` 一样报，清 `node_modules`、
改 `package-import-method=copy`、改 `node-linker=hoisted` 都无效）。
**改用 `npm install --no-save` 能装上**，装完 `npx tsc` / `npx eslint` / `npx vitest` 都能跑。
`node_modules/` 已在 `.gitignore` 里，不会误提交。

2026-11-04 又实测出第三条路，比换包管理器省事——**手工把残留的临时目录挪到位**。pnpm 的
导入是「先拷到 `xxx_tmp_<pid>_<n>`，再 rename 成 `xxx`」，Windows 上第二步会被拒；而此时
临时目录其实已经拷完了：

    # 看哪个 tmp 是完整的（有 package.json，条目数和正式包一致）
    ls node_modules/.pnpm/core-js@3.51.0/node_modules/
    rm -rf node_modules/.pnpm/core-js@3.51.0/node_modules/core-js
    mv  node_modules/.pnpm/core-js@3.51.0/node_modules/core-js_tmp_*         node_modules/.pnpm/core-js@3.51.0/node_modules/core-js
    pnpm install --offline        # 这一次会正常建链接，几秒结束

注意别只删 `node_modules/core-js`（顶层那个是链接），要动 `.pnpm/<包>@<版本>/node_modules/` 里的实体。

**vite 起不来并报 `EACCES ... listen 127.0.0.1:5173`**
Windows 的 Hyper-V 会预留若干 TCP 端口段（`netsh interface ipv4 show excludedportrange protocol=tcp`），
5173 可能正好落在里面。换一个不在排除段的端口即可：`npx vite --port 6080`。

## 前端能本地验证的证据边界

| 能证明 | 不能证明 |
| --- | --- |
| `tsc` / `eslint` / `vitest` / `check:ui` 通过 | 页面**看起来**对不对——那要真的打开看一眼 |
| 页面能挂载、墓碑分支能走到 | 真机的可见性、滚动、窄屏布局 |

`prettier --check` 在本机会多报几个文件：`core.autocrlf=true` 让工作区是 CRLF，而 CI
检出是 LF。`prettier --write` 处理过的文件会变成 LF，与 CI 一致。

## 第一个管理员

生产环境「第一个管理员从哪来」没有注册入口——`POST /admin/users/{id}/role` 要求调用方
本身就是管理员。用运维命令建：

```bash
cd backend
DATABASE_URL='postgres://…' ADMIN_GRANT_PASSWORD='…'   go run ./cmd/admin-grant -email you@example.com -username you -display 你的显示名
```

- **幂等**：账号已在就只提权，不重置口令；角色已经是目标值就什么都不做（回执写「无需改动」）。
- 账号不存在时才会建号，所以 `-username` / `-password` 只在建号那一次需要。
- 口令走 `ADMIN_GRANT_PASSWORD` 而不是命令行参数：命令行会进 shell 历史与进程列表。
- 命令建出来的账号**直接被激活**（`status='active'`，邮箱标记为已验证）——它证明「这个人」的
  方式不是收验证邮件，而是能跑这条命令。
- 被封禁（`banned`）与已注销（`deleted`）的账号拒绝提权，需要先解封。

## 邮箱验证流程（本地怎么走通）

注册后账号落在 `pending`，收不到邮件就没法登录。本地没配 SMTP 时：

```bash
MAIL_LOG_CODES=1 PORT=8080 … ./api 2>&1 | tee api.log
```

`MAIL_LOG_CODES=1` 会把邮件正文（含验证码）打进日志。e2e 用例就是这么拿码的
（`E2E_API_LOG` 指向同一个文件）。**生产上绝对不要打开**：日志会被采集、转发、留存。

没配 SMTP 时，注册响应的 `verificationSent` 是 `false`，验证页会出现「账号已经建好了，
但验证信没发出去」的黄条——**这是实话**：`logMailer` 的 `Send` 返回 `ErrNotConfigured`，
不是「假装发出了」。日志里仍然有正文，所以本地/e2e 照样拿得到码；这两件事不矛盾，
一个是给用户看的事实，一个是开发环境的旁路。配了真 SMTP 之后黄条自然消失。

`MAIL_LOG_CODES` 之外，本地也能直接查：

```bash
wsl -d Ubuntu24.04.3 -- bash -lc "PGPASSWORD=deepdemos psql -h 127.0.0.1 -p 5433   -U deepdemos -d deepdemos -c \"select purpose, created_at from verification_codes order by id desc limit 5\""
```

（表里只有 HMAC 哈希，**看不到明文码**——那是设计，不是缺功能。）

## 浏览器端到端冒烟（e2e）

`web/e2e/` 下是 [`e2e`](https://e2e.com/docs/web) + `@e2e-dev/web` 驱动的真 Chromium 冒烟。
它补的正是上面那张表右列：页面在真浏览器里点得动吗。dev 代理漏配导致预览 iframe 永远空白
（PR #218）这类缺陷，`tsc` / `eslint` / `vitest` 一个都抓不到。

前提是**服务已经跑着**——`web/e2e.config.ts` 里只写 `app.url`、不写 `app.command`。runner
自己拉服务与「服务已在跑」两种模式在 CI 下会撞 `APP_ALREADY_RUNNING`，把整个 job 打断。

    # API 与前端都起着（见上），并灌过开发种子
    pnpm --dir web test:e2e
    # 前端不在 7000 时
    APP_URL=http://127.0.0.1:6080 pnpm --dir web test:e2e

用例分两组，对数据的影响完全不同：

| 文件 | 覆盖 | 写库吗 |
| --- | --- | --- |
| `web/e2e/smoke.e2e.ts` | 六个页面各自能打开、跳转落点对、`/preview` 代理没漏配 | 不写 |
| `web/e2e/closed-loop.e2e.ts` | 注册 → 验证邮箱 → 登录 → 投稿 → 待审 → 通过 → 发布 → 公开可见 → 下载，一条走完 | **写**，且会留下账号与作品 |

闭环用例要从 API 日志里读验证码（`verification_codes` 只存 HMAC 哈希，库里拿不到明文），
所以起 API 与跑用例都要多给一个环境变量：

    MAIL_LOG_CODES=1 ./api > api.log 2>&1 &
    E2E_API_LOG=$PWD/api.log pnpm --dir web test:e2e

不设 `E2E_API_LOG` 时闭环用例**直接失败并说明原因**，不静默跳过——一条悄悄跳过的用例
等于把「注册这条路还能不能走通」重新交回给人工发现。

- 冒烟那条依赖 `db/seeds/0001-dev-demos.sql`（种子作品都没有封面，卡片带「无封面」标记）。
- **闭环那条需要库里有一个管理员**。本地先跑一次：

      cd backend
      DATABASE_URL='postgres://deepdemos:deepdemos@192.168.15.155:5433/deepdemos?sslmode=disable'         ADMIN_GRANT_PASSWORD='e2e-admin-password'         go run ./cmd/admin-grant -email admin@e2e.local -username e2e-admin -display 测试管理员

  账号名与口令可用 `E2E_ADMIN_EMAIL` / `E2E_ADMIN_PASSWORD` 覆盖；CI 里由 workflow 现建。
- **闭环那条会真的写库**：没有删除端点，跑完那条作品会留在库里。对着开发库跑无所谓，
  **别对着有数据的库跑**。用例标题带 `runId` 后缀，所以反复跑不会互相满足。
- 产物在 `web/.e2e/`（已 gitignore）：`report.json`、`junit.xml`、`summary.md`；失败用例另有 `results/<用例>/trace.md` 与截图，逐步骤指出断在哪。
- 配置里刻意不写 `agents`：agent 断言要模型 key，且判断是概率性的，这种东西不该进门禁。
- 用例里没有 `.locator()` 这类 CSS 选择器：`screen` 只提供 `getByRole/getByLabel/getByText/...`。
  要按「队列里第几条」定位，只能先 `getByRole('listitem').allTextContents()` 算序号再 `.nth()`。

## 邮件（验证码）

代码只依赖 SMTP，所以**换邮件服务商只改环境变量、不改代码**。

| 变量 | 说明 |
| --- | --- |
| `SMTP_HOST` | 服务商的 SMTP 地址。**为空则不发送**，每封信只打一条 WARN |
| `SMTP_PORT` | 空则 587。**465 自动走隐式 TLS**，其余走 STARTTLS |
| `SMTP_USER` / `SMTP_PASS` | 认证凭据。`SMTP_USER` 为空则不做认证（仅供本机假服务器） |
| `SMTP_FROM` | 发件地址。配了 `SMTP_HOST` 就必须配它，否则启动直接失败 |
| `MAIL_LOG_CODES` | 设 `1` 时把邮件正文（含验证码）打进日志。**仅本地开发用** |

### 三种场景

**① 不想装任何东西（默认）**：什么都不配。邮件不会真的发出，日志里会出现
`未配置 SMTP，邮件没有真的发出`。想看到验证码就加 `MAIL_LOG_CODES=1`。

**② 本地想看真邮件长什么样**：起一个 Mailpit，把它当 SMTP 服务器：

```bash
docker run -d --name mailpit -p 1025:1025 -p 8025:8025 axllent/mailpit
```

然后：

```bash
SMTP_HOST=127.0.0.1 SMTP_PORT=1025 SMTP_FROM=noreply@local.test go run ./cmd/api
```

打开 <http://localhost:8025> 就能看到所有发出的邮件。**它不外发、不污染发信域名信誉**。

**③ 真发出去**：填一家邮件服务商的凭据。国内收件人多用阿里云 / 腾讯云的邮件推送
（万封十几块），海外多用 Resend / SES。**国内服务商通常要求发信域名已备案**。

### 一条安全约束

`MAIL_LOG_CODES` 默认关闭是刻意的：验证码进日志等于给任何能看日志的人一条登录通道。
生产环境不要开；没配 SMTP 时它会一直告警，那是在提醒你「邮件其实没发」。
