# 组织者用：P1 验收设计

版本：v0.1（设计稿，测试程序尚未实现）  
日期：2026-10-07  
对应公开需求：[P1-参赛需求.md](./P1-参赛需求.md)

## 1. 用途与发放边界

本文件用于组织者编写独立验收、解释结果和保存证据。具体保留数据、测试代码和期望结果不发给参赛模型。

当前文件保存在策划仓库，不具有技术访问隔离。正式发题必须创建独立空工程，按材料白名单复制公开需求和开发数据；不得让选手以本站仓库或整个评测文档目录为工作区。

全部测试预期都来自 P1 的公开规则。保留样例改变数据和同类场景，不增加公开文档之外的功能。发现需求歧义先修订并统一处理，不以组织者个人偏好补判。

## 2. 独立验收的输入与输出

输入：

- 冻结版本的公开 P1 需求及运行记录。
- 已保存的参赛源码快照与交付命令。
- 已验证的数据包、公开运行样例和保留数据。
- 相同浏览器、视口、资源限制、超时与网络条件。

输出：

- 每个场景的 PASS / FAIL / INFRA_ERROR / NOT_RUN。
- 首次和修复后结果分别保存。
- 场景组成绩、门槛结果及未执行原因。
- 请求响应、日志、截图、录屏、复现步骤和数据/源码版本标识。

INFRA_ERROR 表示测试设施或输入样例的问题，经复查确认后统一重跑。参赛实现按已公布条件未能启动、命令无效或运行超时属于对应交付失败。尚未覆盖的行为标为 NOT_RUN，不默认通过。

## 3. 候选场景组与权重

以下为初版建议，预演后、正式发题前公布冻结权重和场景清单。每个业务场景同组等权，场景里多个断言共同确认行为，不因增加断言扩大权重。

| 场景组 | 权重 | 对应需求 | 观察结果 |
|---|---:|---|---|
| G01 导入与持久化 | 15 | P1-R01、P1-R02 | 可导入、重复安全、重启后独立运行 |
| G02 列表与分页 | 15 | P1-R03、P1-R06、P1-R07、标签接口 | 数据、排序、分页、标签统计 |
| G03 搜索与筛选 | 20 | P1-R04、P1-R05、查询参数协议 | 字面搜索、单标签、交集与校验 |
| G04 详情与资源信息 | 10 | P1-R08、详情接口 | 真实元数据、有效链接、未知作品 |
| G05 预览运行与隔离 | 20 | P1-R11、资源协议 | 作品能运行，主站和路径边界正确 |
| G06 浏览器任务与状态 | 10 | P1-R09、P1-R10、P1-R12 | 界面行为、URL、移动操作 |
| G07 错误与纯文本呈现 | 5 | P1-R10、错误协议 | 缺封面、文本安全、失败恢复 |
| G08 独立交付 | 5 | P1-R12、第 8 节 | 干净构建、导入、启动与停机 |
| 合计 | 100 | — | 不包含审美分 |

计算：组得分 = 组权重 × 通过业务场景数 / 该组已冻结场景数。完整结果需执行全部应执行场景；存在基础设施问题或未执行项时暂不发布总分，不能把未执行场景静默当成通过或自动归零。

若参赛交付无法启动而使业务任务不可达，对应任务失败，保存根因和影响范围，明确这不是独立测试设施故障。

## 4. 业务场景清单

### G01 导入与持久化

| 编号 | 操作 | 期望与证据 |
|---|---|---|
| G01-01 | 新建空 DATA_DIR，运行导入命令 | 退出 0，打印包标识/数量；health 和实际 API 反映输入记录 |
| G01-02 | 对同一目录再导入同一包 | 数量、标签计数和详情不重复；原始输入哈希不变 |
| G01-03 | 停服务，移走输入包，取消 DATASET_DIR，再启动 | 原数据、封面和网页资源可读取；不能依靠原包重新拼数据 |

只在新的空 DATA_DIR 中更换内容包，不秘密要求已经有数据的库执行未规定的替换、删除或迁移语义。

### G02 列表与分页

| 编号 | 操作 | 期望与证据 |
|---|---|---|
| G02-01 | 查询全部作品和已规定列表字段 | 元数据按 manifest 对应；total、字段类型、空值正确 |
| G02-02 | 使用含相同 created_at 的样例查询 | 时间降序，相同时间 slug 升序；使用确定数据计算期望 |
| G02-03 | 用不同合法 page_size 翻完整列表及超出末页 | 固定输入下不重不漏；total 不随页码变化；超出末页空数组 |
| G02-04 | 查询标签列表，并在带查询条件的页面切换条件 | 所有标签对的不同作品计数正确、唯一、排序正确；不随搜索缩小 |

记录里的 tags 按集合比较，不额外要求源数组顺序；标签列表的排序则按公开接口要求验证。

### G03 搜索与筛选

| 编号 | 操作 | 期望与证据 |
|---|---|---|
| G03-01 | 搜标题、只出现在描述的词、ASCII 大小写、中文、首尾规定空白 | 标题或描述包含整个字面子串；空查询和清空符合默认行为 |
| G03-02 | 查询已知/未知合法标签、带冒号的 value | 单标签精确匹配；以首冒号拆分；未知合法值无结果 |
| G03-03 | 同时搜索与单标签 | 结果为交集，排序与 total 正确 |
| G03-04 | 查询字面百分号/下划线/引号，非法或重复参数，未知参数 | 字面规则正确；非法已知参数 422；未知参数忽略 |

边界值使用公开限额及明确语法。不能在此要求 Unicode 模糊搜索、分词、拼音或 P3 多标签。

### G04 详情与资源信息

| 编号 | 操作 | 期望与证据 |
|---|---|---|
| G04-01 | 已存在 slug 的 API 与页面直接打开、刷新 | 元数据完整；URL 和页面对应真实作品；cover/preview URL 实际可 GET |
| G04-02 | 请求不存在 slug | API 404 DEMO_NOT_FOUND；页面未找到状态和返回路径可操作 |

上面列表输出等价字段被核对；不同内部表名、文件结构和技术栈不进入判分。

### G05 预览运行与隔离

| 编号 | 操作 | 期望与证据 |
|---|---|---|
| G05-01 | 单 HTML、多目录 CSS/JS/图片、模块与本地 fetch 样例 | 页面和规定运行结果成立；入口/资源请求日志可核对 |
| G05-02 | 公开存储样例按说明操作并刷新作品 | 作品存储可用；状态按样例基准保留 |
| G05-03 | 点击作品获得焦点，按样例键盘操作，再操作站点退出入口 | 作品收到用户输入；主站必需操作仍可完成 |
| G05-04 | 受控隔离样例尝试读写主站 DOM/存储和非手势顶层跳转 | 不能读写主站哨兵或跳离；正常预览同时可用 |
| G05-05 | 请求未知资源及越出作品允许目录的路径 | 返回公开协议规定状态；不提供数据库/配置/目录内容或测试哨兵文件 |

存储使用测试浏览器干净 profile，避免前一选手留下状态影响下一位。每个运行样例提前验证，并公开其必要能力和操作。

隔离测试使用专门常量哨兵，位于测试范围内；不读取真实秘密或探测生产站点。测试自动化读取 iframe 内状态用于观察，不等于网页获得了跨源访问权限。

P1 不要求 Pointer Lock、原生全屏、WebGL 等未列为公开必要能力的复杂场景。真实样本如需要这些能力，在输入准备时排除或升级公开范围，统一发题。

### G06 浏览器任务与状态

| 编号 | 操作 | 期望与证据 |
|---|---|---|
| G06-01 | 浏览器从列表完成搜索、选择标签、分页、打开详情 | 可见卡片、顺序和 API 数据一致；操作都影响真实后端 |
| G06-02 | 第二页改条件，复制 URL、刷新、后退、清空条件 | 已提交查询状态恢复；改条件/清空回第一页 |
| G06-03 | 在 390×844 完成同一核心旅程 | 必需控件可点、作品可进入和退出；不以特定布局审美扣分 |
| G06-04 | 测试代理延迟一个列表请求，再恢复 | 有可理解加载状态；最终显示对应请求结果 |

不要求 UI 输入实时触发搜索，按公开按钮/Enter 行为操作。DOM 定位使用公开约定，不能仅因某框架默认结构不同判失败。

### G07 错误与纯文本呈现

| 编号 | 操作 | 期望与证据 |
|---|---|---|
| G07-01 | 打开无封面作品及含尖括号等字面文本的元数据 | 缺封面有合理呈现；文本可读且不执行注入代码 |
| G07-02 | 未找到/空结果页面，测试代理返回一次标准错误后恢复 | 对应状态明确，清空/返回/重试可操作；不把旧结果误报为新请求成功 |

代理注入错误验证的是客户端失败处理，不能据此宣称已验证后端内部事务回滚。P1 也没有新增发布写事务。

### G08 独立交付

| 编号 | 操作 | 期望与证据 |
|---|---|---|
| G08-01 | 干净副本按 submission.json 构建、导入并启动 | 所有命令可按运行记录执行，无个人绝对路径或隐式现站依赖 |
| G08-02 | 验证 RUNBOOK/DELIVERY，停止并再次启动 | 描述与工程相符，持久目录/监听方式明确，进程可清理 |

只按公布的 OS、运行时和依赖网络条件运行；不临时更换操作系统来制造额外失败。

## 5. 交付门槛

最终交付仍存在下列问题时，标记对应门槛未通过，并保留各场景和原始分数：

1. 无法按约定从干净环境启动且原因属于参赛实现。
2. 移走原内容包、重启后丢失已导入的元数据或资源。
3. 预览内容能够越过公开主站边界，或静态服务泄漏不应公开的文件。
4. 替换作品脚本、硬编码教学样例结果、代理原站，导致交付不能处理同格式新内容。
5. 输入包被改写，或关键结果只能依靠组织者亲自改业务代码完成。

疑似绕过规则需要复核源码、访问记录及实际行为，记录证据；不能只凭一次异常请求指控作弊。

“未通过门槛”表示这份交付不满足既定 P1 条件，不宣称模型在所有工程任务上都无能力。

## 6. 数据与预期结果的准备

准备两类材料：

- 开发包：正常内容和公开运行样例，供选手自行检查。
- 保留包/条件：同一 schema、同一业务规则的新数据及同类运行样例，独立新 DATA_DIR 运行。

查询、排序、分页和标签统计的期望从 manifest 和公开规则独立生成；不要调用参赛接口来生成答案。人工复核至少包括并列时间排序、字面搜索、跨字段搜索和标签计数。

数据包记录标识、文件清单及哈希；所有选手使用相同版本和相同保留测试条件。运行样例先在参考静态托管环境验证，参考环境只作为组织者工具，不作为参赛源码。

真实作品自身问题、网络缺依赖、运行时缺失和测试脚本故障均先复查；必要时所有受影响选手一起重测。

## 7. 首次、反馈和最终保留验收

1. 选手提交，保存不可变首次工程快照和交付自述。
2. 对首次快照独立执行验收，保存结果；保留测试详情不进入反馈。
3. 用公开/诊断检查产生同粒度反馈：需求规则、失败操作、观测现象及必要日志，不给实现补丁。
4. 在冻结修复预算内修改，保存修复后工程快照。
5. 对两份快照分别在重置环境上运行相同最终保留验收；保留首次/修复后成绩。
6. 统计费用、时间、人工介入，整理关键成功和失败片段。

反馈轮次初版设为一次，具体预算在运行记录中确定。组织者若亲自修业务代码，另记为人工辅助交付，不能并入无辅助结果。

## 8. 结果与证据记录

每条记录包含 run_id、模型/提供方、DSH 配置摘要、阶段、提交版本、数据包版本、场景号、输入、期望、实际、状态和证据路径。

保存：

- API 请求、HTTP 状态及去除敏感信息后的响应。
- 构建、导入、服务和浏览器错误日志。
- 关键用户任务的完整录屏与失败截图。
- 程序停止/重启前后的校验。
- 组织者反馈及人工介入的时间和内容。
- 首次和修复后可重放源码。

代码行数、测试标记、页面风格和模型自称“全部完成”不能替代验收。

## 9. 人工审美展示

相同数据、视口和任务下匿名展示：

- 桌面列表、搜索/筛选结果、详情和空结果。
- 手机列表与预览进入/退出。
- 短标题/长标题、有封面/无封面、请求失败状态。
- 完整浏览旅程录屏与可体验实现。

文字点评和人工选择独立呈现，不混入上面的工程分。浏览器任务成败属于工程行为，两种结果均保留。

## 10. 开发验收程序前的核对

- P1 需求与本设计中每个场景可相互追溯。
- 输入包及运行样例准备完成、参考环境结果成立。
- 数据集和期望生成规则被独立复核。
- 运行记录、权重、超时、反馈与预算冻结。
- 公开发题包和组织者验收目录已物理隔离。
- 在已知正确与已知错误的测试实现上验证验收程序，发现误判先修测试。

当前没有编写或执行这些测试。下一阶段按已冻结文档实现机器验收，并用预演校正可执行性。
