# P1 参赛需求：可浏览的作品库

文档版本：v0.1（可审阅的发题稿，尚未冻结开跑）  
日期：2026-10-07  
对象：通过同一 DSH 环境参赛的 AI 模型。  
阶段目标：从空工程实现一个能导入、查找、阅读并运行真实网页作品的网站。

## 1. 一页任务说明

你将获得统一的内容包、运行环境和本阶段需求。请独立完成前端、后端和持久化，使匿名访客能完成：

**进入作品库 → 搜索或选择一个标签 → 浏览分页结果 → 打开作品详情 → 在网页作品中完成一次操作。**

本阶段功能：

| 功能 | 对应清单 |
|---|---|
| 导入统一内容，保留作品标识和关系 | A01 |
| 基础入口、真实作品列表与卡片 | A02 基础导航、A03 |
| 关键词搜索、单标签筛选、最新排序与分页 | A04、A05 单标签、A06 最新排序 |
| 详情与直接访问 | A07 |
| 网页预览、相对资源、指定模块/存储/键盘样例 | A08、A09 指定样例 |
| 加载、空结果、错误和手机操作 | A12、Q05 |
| 服务端持久化、内容隔离、可复查交付 | Q01–Q04、Q06 |

本阶段处理公开 web 网页作品，输入中已经提供解包后的目录。上传、注册登录、评分、论坛、下载、外链作品和完整模型/题目系统在后续阶段发题。新增这些功能不替代本阶段要求，也不获得额外工程分。

后续 P2 会增加作者发布，P3 会把单标签扩展为同键 OR、跨键 AND 的组合筛选。本阶段只验收下文规定的单标签协议，保持工程能够继续演进。

P3 将明确升级“重复 tag 参数”的含义。该项 P1 的 422 预期届时按新协议替换，其他仍有效的 P1 行为继续回归，不能同时要求新旧互斥规则。

当前采用自主设计：信息清楚、操作可完成。技术栈和内部模块组织可以在发题运行环境允许的范围内自行选择。外部数据、HTTP 接口及交付协议统一。

## 3. 内容包协议

### 3.1 文件布局

```text
DATASET_DIR/
  manifest.json
  works/<slug>/index.html
  works/<slug>/...原始 CSS、JS、图片、数据文件...
  covers/...封面文件...
  runtime-checks.md
```

manifest.json 使用 UTF-8 JSON。目录布局示意不要求所有入口都叫 index.html：实际入口由 entry_file 指定。

输入保证：

- manifest 结构合法，slug 唯一，文件路径安全且实际存在。
- 作品类型都是 web；数量为 1–1000，首轮计划约 50 件。
- 作品为可静态托管网页，所需依赖在内容包中；验收运行不依赖第三方 CDN。
- 每件作品所需本地资源都位于自己的 works/<slug>/ 目录中，保留内部子目录；本阶段不要求跨作品资源引用。
- 运行样例事先在基准浏览器验证。需要的能力和操作由 runtime-checks.md 公开说明。
- 有意用于检查隔离的受控作品也会说明目标行为。
- 封面是 PNG、JPEG 或 WebP；缺封面用 null。
- 输入文件不能被修改；导入时把需要的资源复制到 DATA_DIR 或其受管理的子目录。

### 3.2 manifest 顶层

| 字段 | 类型 | 规则 |
|---|---|---|
| schema_version | string | 固定为 deepdemos-p1/1 |
| dataset_id | string | 本次内容包的标识 |
| records | array | 本次需要导入的全部作品 |

### 3.3 每条作品记录

| 字段 | 类型 | 规则 |
|---|---|---|
| slug | string | 1–64 个 ASCII 字符；小写字母、数字及分隔用连字符；唯一且稳定 |
| title | string | 非空，最多 200 个 Unicode 码点；作为纯文本 |
| description | string | 可为空，最多 5000 个 Unicode 码点；作为纯文本 |
| demo_type | string | 固定为 web |
| created_at | string | UTC，固定格式 YYYY-MM-DDTHH:mm:ssZ |
| author | object | username、display_name 两个纯文本字符串；匿名署名使用 username=public |
| tags | array | 元素为 key/value 字符串对象；可为空，同一对不重复 |
| cover_file | string 或 null | 相对 DATASET_DIR 的封面路径 |
| entry_file | string | 相对 DATASET_DIR 的入口路径，位于 works/<slug>/ 内 |

标签 key 为小写字母起始、后接小写字母/数字/下划线/连字符，最长 32。value 为 1–64 个 Unicode 码点，可包含中文和冒号，无首尾空白。key/value 匹配区分大小写。

字段示例：

```json
{
  "schema_version": "deepdemos-p1/1",
  "dataset_id": "p1-example-v1",
  "records": [
    {
      "slug": "demo-a",
      "title": "Orbit Game",
      "description": "键盘躲避小游戏",
      "demo_type": "web",
      "created_at": "2026-10-03T12:00:00Z",
      "author": {
        "username": "author-a",
        "display_name": "作者甲"
      },
      "tags": [
        {
          "key": "model",
          "value": "alpha"
        },
        {
          "key": "category",
          "value": "game"
        }
      ],
      "cover_file": "covers/demo-a.webp",
      "entry_file": "works/demo-a/index.html"
    }
  ]
}
```

以上只说明一条记录的格式，不是完整内容包。额外输入字段可以忽略；不要因未约定字段改变本阶段规则。

## 4. 业务规则

| 规则 | 内容 |
|---|---|
| P1-R01 导入 | 提供可执行导入命令。成功时导入全部记录和资源；退出码为 0，打印 dataset_id 和导入数量。失败时非 0 并说明原因。 |
| P1-R02 持久化与重复导入 | 同一包重复导入不新增重复作品/标签关联；在新建空 DATA_DIR 中可导入另一份同格式包。导入成功后移走输入包、重启服务，已导入内容与资源仍可用。 |
| P1-R03 公开列表 | 全部输入作品为公开作品。列表内容来自后端；slug、标题、作者、标签、描述和创建时间与输入对应。 |
| P1-R04 搜索 | q 首尾去掉 ASCII 空格、Tab、CR、LF；空串视为无搜索。按标题或描述中包含整个 q 的字面子串匹配，ASCII 英文字母不区分大小写，其他字符按字面。百分号、下划线、引号和尖括号不作查询运算符。最长 200 个 Unicode 码点。 |
| P1-R05 单标签 | tag 不传或传空串视为无筛选；非空时使用 key:value，按第一个冒号拆分，key/value 遵守第 3 节语法和限额。必须精确匹配一对标签；搜索与标签同时存在时取交集。未知但格式合法的标签返回空结果。重复 tag 参数或非法格式返回 422。 |
| P1-R06 排序 | sort 缺省为 newest；仅允许 newest。按 created_at 降序，同一时间按 slug 的 ASCII 字典序升序。其他 sort 返回 422。 |
| P1-R07 分页 | page 缺省 1、page_size 缺省 12；只接受 ASCII 十进制正整数字符串，page 为 1–1000000，page_size 为 1–48。分页前先搜索/筛选/排序；total 是过滤后全部作品数。超出末页返回 items=[]，保留 total 和请求的页码。非法值返回 422。 |
| P1-R08 详情 | 详情由 slug 查找，展示完整标题、作者署名、描述、标签和预览；可复制链接并直接打开或刷新。不存在的作品返回明确的未找到状态。 |
| P1-R09 查询状态 | 提交搜索、改变标签、清空条件时将 page 重置为 1；URL 保存 q、tag、sort、page。复制 URL、刷新和浏览器后退恢复对应条件与结果。 |
| P1-R10 文本和异常 | 元数据按纯文本展示，不能作为 HTML/脚本执行。加载有提示；空结果说明当前无匹配内容并可清空条件；请求失败说明失败并提供重试；无封面有占位呈现。 |
| P1-R11 运行与隔离 | 作品入口和相对资源可加载，公开样例要求的模块、fetch、本地存储和用户点击后的键盘操作可用。作品与主站使用不同源，作品不能读写主站 DOM/存储，不能无用户操作把顶层页面跳走。 |
| P1-R12 可操作交付 | 桌面 1440×900、手机 390×844 均能搜索、筛选、打开详情、进入和退出预览。交付可按第 8 节从干净环境构建、导入、启动。 |

page/page_size 的纯数字形式允许前导零，响应输出对应整数。负数、小数、正号、空串和非数字值非法。q、tag、sort、page、page_size 重复传入均返回 422。未知查询参数忽略。

title/description 的大小限制是输入保证，不要求本阶段实现发布表单。未知作品与缺资源要处理；损坏 ZIP、非法元数据批量回滚等上传/导入扩展任务在后续明确发题。

## 5. 统一 HTTP 接口

主站 APP_ORIGIN 提供下列接口。路径和已列字段固定，额外返回字段允许，不得替代既定字段。

### 5.1 健康检查

GET /api/v1/health

构建、导入并启动成功后返回 200 JSON：

```json
{"status":"ok","dataset_id":"p1-example-v1","count":4}
```

count 是已导入作品数量；示例中的 4 对应第 9 节演示记录，不对应上面的单记录格式示例。

### 5.2 作品列表

GET /api/v1/demos?q=...&tag=...&sort=newest&page=1&page_size=12

返回 200 JSON：

```json
{
  "items": [
    {
      "slug": "demo-a",
      "title": "Orbit Game",
      "description": "键盘躲避小游戏",
      "demo_type": "web",
      "created_at": "2026-10-03T12:00:00Z",
      "author": {
        "username": "author-a",
        "display_name": "作者甲"
      },
      "tags": [
        {
          "key": "model",
          "value": "alpha"
        },
        {
          "key": "category",
          "value": "game"
        }
      ],
      "cover_url": "<APP_ORIGIN>/media/demo-a.webp"
    }
  ],
  "total": 1,
  "page": 1,
  "page_size": 12
}
```

items 中每项必须含：slug、title、description、demo_type、created_at、author、tags、cover_url。无封面 cover_url=null，否则为 APP_ORIGIN 上可 GET 的绝对 URL。

total、page、page_size 和标签 count 均为整数，tags 按集合核对、不要求输入数组顺序；已约定的分页和标签列表排序仍需满足。响应内容类型为 application/json。

列表返回完整 description，前端卡片可以合理截断；详情必须能读取完整描述。列表或标签接口中的额外元数据不能替代真实资源加载。

### 5.3 作品详情

GET /api/v1/demos/<slug>

返回与列表作品相同的字段，并增加 preview_url，为 PREVIEW_ORIGIN 上可直接 GET 的绝对入口 URL。实际响应不得保留上文的尖括号占位符。

存在返回 200；不存在返回 404、error.code=DEMO_NOT_FOUND。

### 5.4 标签列表

GET /api/v1/tags

返回 200 JSON：

```json
{"items":[{"key":"category","value":"game","count":2},{"key":"model","value":"alpha","count":3}]}
```

实际 items 包含整个已导入数据集的全部标签对，count 为带该标签的不同作品数，与当前搜索条件无关。同一标签对只出现一次；按 key，再按 value 的 Unicode 码点序升序。上例仅说明结构，不是第 9 节的完整期望列表。

### 5.5 错误协议

非法查询返回 422、error.code=INVALID_QUERY；不存在的 API 路径返回 404、error.code=NOT_FOUND；内部服务失败返回 500、error.code=INTERNAL_ERROR。message 为非空、可理解的文字，不要求逐字一致。

```json
{"error":{"code":"INVALID_QUERY","message":"page 必须为正整数"}}
```

预览/封面不存在返回 404，可为资源错误页；越界路径返回 400 或 404。预览只能读取当前作品允许的资源目录，封面只能读取导入的封面；不得返回数据库、配置、其他私有文件或目录列表。

## 6. 浏览器页面与公开定位约定

- / 可以展示首页，也可以跳转至 /demos；作品库要有可发现入口。
- /demos 承载列表及查询状态。页面使用 page_size=12，不要求页面上提供调节控件。
- /demo/<slug> 承载详情。直接访问、刷新和从列表返回都可用。
- 详情的作者只是署名信息，本阶段不要求实现账号主页。
- 详情应嵌入作品预览，并提供清楚的返回/退出途径；可以采用用户点击后再挂载的方式。
- 主站与预览 URL、静态资源路径按运行变量生成，不能绑定某个选手本机绝对路径。

为统一浏览器功能验收，使用以下可见元素定位属性。它们只约定机器定位方式，不约定布局、组件库、字体或颜色。

| 定位标记 | 语义 |
|---|---|
| data-testid=search-input | 实际可输入的搜索控件 |
| data-testid=search-submit | 提交搜索的实际可点击控件 |
| data-testid=tag-filter | 原生 select 或标准 combobox；选项可按 key:value 识别，另有“全部” |
| data-testid=clear-filters | 清空搜索与标签、回到第一页 |
| data-testid=demo-card，data-demo-slug=<slug> | 每张真实作品卡，DOM 顺序与列表显示顺序一致 |
| data-testid=demo-link | 卡片中打开详情的链接 |
| data-testid=pagination-prev / pagination-next | 上/下一页控件，边界状态可识别 |
| data-testid=demo-title | 详情标题 |
| data-testid=preview-frame | 实际装载作品的 iframe |
| data-testid=preview-open | 若采用点击进入/加载预览，则标记该控件；自动加载时不要求 |
| data-testid=request-retry | 请求失败状态的重试控件 |

交互控件应有可理解的文字或可访问名称。使用自定义 combobox 时提供相应角色和可访问选项；不要把测试标记放在与实际动作无关的隐藏元素上。

URL 使用与接口相同的 q、tag、sort、page 含义，可省略默认值。输入后通过按钮或 Enter 提交；不要求每次敲键自动搜索。后退时恢复此前已提交状态。

打开预览后，用户真实点击作品区域再进行键盘操作；不要求自动抢占焦点。页面其它区域仍应能操作。

## 7. 作品托管与隔离

运行记录会提供 APP_ORIGIN 和 PREVIEW_ORIGIN，二者使用不同源。预览域只服务作品资源及必要的公开静态资源，不提供主站业务 API、目录浏览或任意文件读取。

作品原始文件保持内容不变，按照其目录和资源引用加载。不得为迎合样例而改写作品脚本、替换互动结果或修改输入包。

预览应有沙箱限制，同时允许公开样例所需能力；本阶段重点是正常运行、主站 DOM/存储隔离、非手势顶层跳转限制和路径边界。不同作品之间的独立存储空间没有在 P1 约定，不因此追加秘密扣分条件。

P1 的必要运行能力是单 HTML、多文件资源、ES module/本地 fetch、localStorage 和用户点击后的键盘操作；本阶段不要求 Pointer Lock、原生全屏或 WebGL 等额外能力。需要这些能力的真实作品留到后续任务，或在冻结输入前统一升级公开范围。

不同源由协议、主机、端口共同确定；浏览器限制需与具体预览能力一起设计。参见 [MDN 同源策略](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Same-origin_policy)和 [MDN iframe sandbox 说明](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe#sandbox)。验收检查真实行为，不能仅凭配置中存在 sandbox 就宣告通过。

## 8. 运行与交付协议

运行变量统一由组织者注入：

| 变量 | 含义 |
|---|---|
| DATASET_DIR | 本次只读内容包根目录；仅导入时需要 |
| DATA_DIR | 本次持久化目录；构建/导入/服务启动均可访问 |
| PORT | 主站监听端口 |
| PREVIEW_PORT | 预览服务监听端口 |
| APP_ORIGIN | 测试浏览器访问主站的绝对 origin，不含路径 |
| PREVIEW_ORIGIN | 测试浏览器访问预览的绝对 origin，不含路径 |

可以一个进程监听两个端口，也可以多个进程。必须按发题 OS 和运行时可执行；依赖网络与缓存规则统一规定。

根目录交付：

1. 全部实现源码、依赖清单及锁文件（生态支持时）。
2. RUNBOOK.md：构建、导入、启动、停止、数据位置，以及已知限制。
3. submission.json：可由执行器运行的构建、导入和服务命令。
4. DELIVERY.md：已完成项、未完成项、自测结果与限制，按本需求规则编号对应。

submission.json 的协议：

- build：对象，cwd 为工程内相对目录，argv 为非空字符串数组；无需构建则为 null。
- import：对象，cwd/argv 同上；通过环境变量读取内容包和数据目录，退出码遵守 P1-R01。
- start：非空数组，每项有唯一 name、cwd、argv。执行器并行启动全部项目，继承上述运行变量。
- argv 作为实际程序及参数执行，不自动展开 shell 字符串；若需要 shell，显式列入所选 OS 已提供的 shell 程序和参数。
- 命令不得依赖开发者个人绝对路径，也不得修改 DATASET_DIR 或启动新的 AI 开发会话。
- start 不后台自脱离：执行器应能停止这些进程及其子进程。服务就绪由健康检查和实际 HTTP 访问确认。

本阶段无需实现公开 Web 导入入口。启动时不允许用原始 DATASET_DIR 临时重新构建数据来替代已完成的持久化导入。

具体 OS、运行时版本、硬件、启动/动作超时、开发预算和一次修复预算由发题运行记录补齐并冻结；未补齐时不开始正式测试。
