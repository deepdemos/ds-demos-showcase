# DeepDemos AI 全栈开发评测：功能清单

版本：v0.3（范围建议稿）  
日期：2026-10-07  
项目位置：功能清单初稿已完成；现进入第 ③ 步，P1 需求与验收设计初稿已整理。尚未正式发题或测试。

## 1. 先看这一页

完整评测围绕六个开发任务阶段展开：

| 开发阶段 | AI 要交付什么 | 代表性用户操作 |
|---|---|---|
| A. 浏览作品 | 能查找、阅读和运行真实作品的作品库 | 找作品 → 筛选 → 打开详情 → 运行 |
| B. 发布与归属 | 作者能发布、更新作品，保留生成过程 | 注册登录 → 上传 → 查看发布结果 → 更新 |
| C. 互动与治理 | 用户能互动，管理员能管理内容和账号 | 收藏/评分/讨论 → 通知 → 审核处理 |
| D. 能力观察与知识治理 | 补齐模型、题目、提示词比较和后台治理 | 按模型/题目比较 → 挑战题目 → 审批归属 |
| E. 规模与需求变更 | 已有产品能承受真实规模并继续演进 | 导入完整快照 → 混合访问 → 升级旧数据 |
| F. 故障与交接 | 能修复事故、部署、恢复并交接维护 | 复现故障 → 修复 → 重测 → 新环境启动 |

A–D 是网站业务功能；E–F 是额外设置的工程能力任务。通用交付要求贯穿已经发放的阶段。

首轮预演建议只选 A、B 的精简闭环，再追加一次小变更。完整业务候选仍保留在下文，预演范围不等于最终评测范围。

观众用介绍见[网站与考题介绍片段](./网站与考题介绍片段.md)：用实际操作介绍原站主要能力，再单独说明本轮 P1–P3 考题和验收方式。

**当前需要形成的是功能范围，详细字段、接口、状态机、阈值和计分规则将在下一步需求文档中规定。以下验收描述是方向，尚不作为直接计分合同。**

## 2. 清单依据和状态说明

调查依据是当前工作区的前端路由、后端路由、模型和专项文档。本次没有启动服务或核验现网全部功能。

- “仓库功能”：存在对应实现线索，运行效果和线上是否部署仍需后续核验。
- “评测补充”：为测试从零实现、部署和维护能力而新增的任务，不宣称现站已实现。
- “扩展建议”：已有功能或能力线索保留在清单，建议在主线之后安排，尚未决定延期。
- “遗留/未来”：历史兼容项或未落地想法，不能直接当作现有完整功能发题。

核对时修正了三点：

1. 新评论已迁到论坛。旧评论接口保留读取，新建和删除接口返回 410；新实现应区分“作品讨论”和“旧评论兼容”。
2. 作品包括 web 网页、zip 文件包和 link 外链，不能把所有作品都要求为可内嵌网页。
3. 普通标签筛选当前是同一键多个值 OR、不同键之间 AND；旧 README 的“多标签 AND”不足以说明完整行为。

后续冻结范围应对照选定的线上版本，记录本地新增、线上缺失和文档过期项。

## 3. 角色与主要边界

| 角色 | 主要行为 | 必须说明的边界 |
|---|---|---|
| 访客 | 浏览、搜索、运行公开作品；按开放规则匿名上传/评分 | 不能修改他人作品、查看他人私密收藏或使用后台 |
| 登录用户/作者 | 发布自己的作品、更新、收藏、讨论、关注 | 登录身份不意味着可以管理其他作者的数据 |
| 管理员 | 审核、用户管理、策展、知识治理和站点设置 | 管理动作要有清楚影响范围和必要的审计 |
| 机器作者/AI 代传 | 通过接口提交作品与生成记录 | 代传所用身份和信任策略要明确；不能默认取得管理员权限 |

角色不是固定技术实现要求。账号凭据、预览内容和第三方资源的访问边界由需求约定，测试通过实际行为检查。

| A08 | 网页预览与资源加载 | 打开单 HTML 或含入口页的多文件 ZIP 作品 | HTML、CSS、JS、图片、相对资源路径可用；与主站保持规定隔离 | 纳入代表样例 |
| A09 | 交互作品运行能力 | 操作需要模块、存储、键盘、全屏或指针锁的作品 | 按样例所需能力运行；退出和输入归属明确 | P1 选模块/存储/键盘样例；其他后续 |
| A10 | 作品下载 | 下载网页或文件包，并在详情识别作品类型 | 下载内容与作品一致；外链按公开规则处理 | 后续 |
| A11 | 标签浏览和探索 | 查看标签说明、父子关系、分类入口及关联作品 | 展示关系和数量正确；链接进入对应作品集 | 后续 |
| A12 | 加载、空结果与异常状态 | 等待加载、访问不存在作品、遇到请求失败 | 状态可理解、可继续操作；桌面和手机能完成核心任务 | 纳入已实现页面 |

A08 先测试正常托管；A09 再扩大到复杂运行能力。测试前确认代表作品在基准环境可运行，避免把作品自身缺陷归到站点实现。

随机列表的验收使用明确的随机/分页协议，不直接套用稳定排序的“不重不漏”要求。

## 5. B：发布与归属

| 编号 | 功能 | 用户操作或系统任务 | 可验收结果 | 预演建议 |
|---|---|---|---|---|
| B01 | 注册账号 | 提交账号密码、尝试重复用户名或无效输入 | 成功创建可登录账号；重复和非法输入明确处理 | 纳入 |
| B02 | 登录、退出与会话 | 正确/错误登录、刷新、退出后尝试写入 | 身份和会话行为符合约定；退出后失去对应权限 | 纳入 |
| B03 | 账户设置 | 修改展示名、简介、头像和密码 | 数据更新正确；新旧密码及其他会话处理有明确规则 | 后续 |
| B04 | 登录用户发布网页 | 上传一份单 HTML，填写必填信息 | 作品归属当前作者；发布状态明确；按开放策略可浏览和预览 | 纳入 |
| B05 | 匿名发布与 public 归属 | 未登录时上传，再查看公开用户作品 | 匿名作品归属和展示一致；不能冒充账号作者或任意编辑 | 后续，保留现有业务 |
| B06 | 作品描述与素材 | 填标题、介绍、模型声明、提示词；上传封面 | 已提供信息正确保存和展示；必填缺失可处理；模型未知有约定兜底 | 基础字段与可选封面 |
| B07 | 多文件 ZIP 与单 SVG 发布 | 上传包含静态资源的网页包或 SVG | 包和入口处理正确；文件限制明确；异常不留下错误的成功结果 | ZIP 纳入，SVG 后续 |
| B08 | 普通文件包发布 | 上传没有网页入口的 ZIP 文件包 | 作为文件包展示与下载；不错误承诺网页可运行 | 后续 |
| B09 | 外链作品 | 提交外部网址并访问作品 | 作为外链呈现；网址校验明确；区别于服务端托管作品 | 后续 |
| B10 | 作品更新与删除 | 作者更新描述/资源，或执行删除；另一用户尝试相同操作 | 权限正确；更新呈现新内容；删除及关联数据按冻结规则处理 | 纳入更新；删除后续 |
| B11 | 版本时间线 | 查看创建、更新和更新说明 | 顺序和归属正确；失败更新不生成误导性的成功记录 | 后续 |
| B12 | 生成会话日志 | 发布带 sessions 的作品，查看 Markdown/DSH JSONL 记录 | 记录关联正确、可阅读；无记录有空态；内容安全呈现 | 后续 |
| B13 | AI 代传通道 | 阅读提交指南，通过 URL/API 代传作品 | 正常请求能发布；身份、资源抓取限制和错误结果明确 | 后续 |
| B14 | 重试与重复内容 | 重发同一请求或再次上传相同内容 | 按幂等和去重规则处理，不产生意外重复或孤儿记录 | 后续 |
| B15 | 保留旧版作品 | 更新时选择保存旧版，再分别访问新旧内容 | 当前作品与旧版关系正确，旧内容符合公开保留约定 | 后续 |

上传流程从第一次发题就需要明确文件、路径、资源大小和失败清理规则。完整协议及阈值在需求包中规定。

预演为了跑通流程，可使用明确的自动批准配置；进入内容治理阶段再引入待审流程。这种阶段差异需写入需求，不能临时改变验收预期。

## 6. C：互动与基本治理

| 编号 | 功能 | 用户操作或系统任务 | 可验收结果 |
|---|---|---|---|
| C01 | 用户与匿名作者主页 | 访问作者页、public 聚合页和作者作品 | 作品归属、公开资料和统计符合约定，不泄漏账户秘密 |
| C02 | 关注与名单 | 关注/取关作者，查看粉丝和关注名单 | 不重复计数；双方关系和名单一致；禁止的行为明确 |
| C03 | 作品评分 | 登录或匿名评分、改分、撤销评分 | 同一评分主体的记录和聚合一致；合法区间和匿名身份规则明确 |
| C04 | 作品排行榜 | 切换评分/热度口径、时间范围和分页 | 排名对应公布公式；样本不足和未评分作品处理明确 |
| C05 | 默认收藏 | 收藏、取消收藏、重复操作后刷新 | 默认收藏归属本人、私密；重复操作及计数正确 |
| C06 | 多收藏夹 | 新建、改名、删除收藏夹，增删作品 | 收藏关系持久化；默认夹限制、重复和上限规则明确 |
| C07 | 收藏夹公开分享 | 将自建收藏夹公开，另一用户打开链接，再改回私密 | 公开可读、私密不可读；其他用户始终不能修改 |
| C08 | 浏览历史 | 匿名浏览、登录浏览、关闭记录、清空历史 | 本机和账号记录按约定处理；“停止记录”和“删除旧记录”分开 |
| C09 | 作品关联讨论与发帖 | 从作品进入讨论，登录后创建关联主题 | 主题关联正确；新用户待审与公开可见状态明确 |
| C10 | 回复与互动 | 回复主题/回复、点赞或感谢、遇到锁定主题 | 回复归属正确；互动切换不重复；锁定时按规则阻止新回复 |
| C11 | 举报与处理 | 举报主题/回复，管理员处理举报 | 目标和原因正确；重复举报规则明确；处理结果可追溯 |
| C12 | 站内通知 | 收到回复/@提及/审核等通知，查看并标记已读 | 只发给规定接收者；链接可用；未读和已读状态一致 |
| C13 | 作品审核与公开可见性 | 管理员通过/拒绝/下架，访客再查找或打开作品 | 列表、详情、预览、下载和日志遵守一致的公开访问规则 |
| C14 | 用户状态与管理权限 | 管理员调整角色或封禁，再验证受影响账号 | 普通用户无法管理；已有会话下的权限变化符合约定 |
| C15 | 站点基本设置 | 管理员调整发布审核策略等设置 | 配置持久化，影响范围清楚；公开端不泄漏私有配置 |

C09–C10 是当前业务的新发言路径。历史评论读取单列为 L01。

C07 已有实现线索，可作为一次逐步开放的需求变化：先发私人收藏需求，后发公开分享需求。是否选它为正式追加题，在规则冻结时统一决定。

C03–C04 的评分是站内作品业务；与本企划对参赛 AI 的工程计分分别定义。

| 编号 | 功能 | 用户操作或系统任务 | 可验收结果 |

| D11 | 模型/题目合并与归属 | 预览合并影响、确认合并、按支持规则撤销 | 关系和统计正确迁移；重复引用和不支持操作明确处理 |

| D15 | 巡检、类型细分与归属工作台 | 查看异常，按支持动作生成候选并处理 | 已支持修复形成闭环；不支持动作清楚拒绝；原始关系可追溯 |
| D16 | 论坛发现与高级管理 | 按类别、标签、关联作品、关注流搜索；置顶/锁定/审核 | 查询范围正确；管理状态与公开端同步 |
| D17 | 首页策展与公告 | 设置精选顺序/主展示位，发布和撤下公告 | 已公开内容按约定展示；公告与作品/论坛链接正确 |
| D18 | 运营统计 | 查看访问、在线、作品、用户及治理统计 | 指标窗口、去重和采样规则公布；计数可核对 |

D 阶段较重，可以在预演后继续细拆需求包。功能保留不意味着一次性把所有治理工具放入同一道题。

## 12. 第一次预演：具体范围

### 12.1 预演目的

先检验需求、DSH、验收和留档能否连成完整流程。使用约 50 件代表内容，跑通一个模型后再用第二个模型验证可比性。此时不发布稳定模型排名。

### 12.2 三个小任务

| 顺序 | 任务包 | 包含的功能 | 可以现场演示的结果 |
|---|---|---|---|
| P1 | 可浏览的作品库 | A01、A03、A04、A05 单标签、A06 最新排序/分页、A07、A08、A09 指定样例、A12；基础导航 | 导入 → 搜索 → 筛选 → 打开作品 → 成功运行 |
| P2 | 作者发布与更新 | B01、B02、B04、B06 基础字段/可选封面、B07 网页 ZIP、B10 更新；明确自动批准策略 | 新建账号 → 上传 → 第二个浏览器查看 → 更新资源 → 看到新内容 |
| P3 | 一次小需求变更 | 建议将 P1 的单标签筛选升级为同键 OR、跨键 AND 的组合筛选 | 新旧筛选均正确，已发布作品、预览和登录功能回归通过 |

P3 的最终语义从 P1 起就列为后续演进方向，避免因早期歧义造成无意义返工。正式多轮比赛的发题节奏另行规定。

升级协议时明确替换旧预期。例如 P1 重复 tag 参数返回 422，P3 将允许组合；回归保留仍有效的旧行为，不能同时要求两套互斥规则。

每个任务结束保存首次提交和反馈后提交。先验证所需 API、文件及浏览器行为，评分权重在流程稳定后制定。

### 12.3 预演完成条件

- 两个模型都能按同一输入和环境开始，成功与失败都有结果可记录。
- 验收覆盖真实操作和持久化，能识别页面演示与真实服务之间的差异。
- 反馈内容和修复预算可统一执行。
- 录屏能够展示同一任务中的成功、失败和复验。
- 数据、依赖和测试设施的问题与参赛实现的问题可区分。
- 能据此估计完整赛季的时间、费用和人工工作量。

## 13. 真实内容样本规范

当前只规定选样方向，尚未抓取、复制或制作数据包。样本编号和导入格式在需求阶段落实。

| 样本类别 | 选样目的 | 用于哪些功能 |
