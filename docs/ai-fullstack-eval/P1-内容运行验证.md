## 2. 怎样检查的

使用独立的新浏览器配置与每作品新建的浏览器上下文，在本机用 HTTP 托管下载副本。每个作品只映射自己的资源根目录；关闭缓存并绕过 Service Worker，阻断公网请求，记录请求、HTTP 错误、脚本异常、页面状态与截图。

实际环境为 Edge 154.0.4258.62、1440×900 视口、WebGL 2 可用、NVIDIA RTX 5070 Ti Laptop GPU。原先在受限环境里启动浏览器遇到 GPU 进程错误；另行验证浏览器环境后才开始内容检查。该设施错误没有归给作品或参赛模型。

首次观察等待 5 秒。6 个作品的浏览器取证命令超时，随后改用导航返回的 frame ID 并延长等待，5 个完成取证；“黑洞”和仍然超时的“观星模拟器”又做了 45 秒预热复查，最终都能取证。各轮记录保留，不能把这些等待时间直接当作作品加载耗时或选手性能成绩。

启动观察与实际玩法分开记录。截图证明当时页面呈现的状态；菜单、加载提示、canvas 或动画回调计数本身，都不能证明完整玩法正确。本轮没有遍历每个游戏的全部功能。

## 4. 代表操作：有明确动作和可见结果

代表作品在与主页面不同端口的来源中，通过 `sandbox="allow-scripts allow-same-origin"` 的 iframe 加载。只对这些具体操作下结论。

| 能力 | 原始作品 | 实际操作与结果 |
|---|---|---|
| 单 HTML、键盘 | ASCII FPV | 点击预览开始；按 C 关闭碰撞用于短时检查；按住 Z 约 1.1 秒，速度增加；按 P 后暂停。截图和游戏状态对应 |
| 多文件、localStorage | HTML 杀戮尖塔 | 新上下文没有存档；输入短种子 `P1SAVE01` 并点击开始；刷新后“继续游戏”可用；继续后恢复相同种子 |
| 本地 ES module、3D 呈现 | 科幻太空船 | iframe 内加载本地入口、Three.js 与附加模块，截图呈现飞船；未观察到外部请求或脚本异常 |
| 父页面与存储分离 | 上述代表作品 | 从预览读取 `parent.document` 得到 `SecurityError`；杀戮尖塔的存档留在预览来源，主页面 localStorage 为空 |

存档首次检查的种子字符串超过作品输入框的 16 字符上限，被正常截断，导致检查预期不成立。改用 8 字符合法种子后复查通过；首次失败记录保留。这是检查条件的问题，没有算成作品存档失败。

这组操作没有验证恶意顶层跳转、所有文件路径攻击、Pointer Lock、原生全屏、手机端或全部浏览器。父页面访问失败也不能单独证明整个安全边界通过。

## 6. 冻结与发题前还缺什么

1. **对齐公开范围。** P1 v0.1 尚未要求 WebGL，这批热门内容包含大量 3D 作品。建议预演统一提供并明确支持 WebGL 2，保留代表性作品；SVG 入口也需写清类型与托管要求。Pointer Lock、原生全屏另行核对，不能秘密增加扣分条件。
2. **补受控样例。** 本轮没有观察到足以确认本地 fetch 能力的实际请求；模块加载不能代替 fetch 检查。还需明确本地 fetch、非手势顶层跳转、路径边界等受控样例。
3. **形成独立发题包。** 按最终范围从原始包复制选定内容，附运行步骤与哈希，核对干净环境复现；当前选样表不是可直接作为 DATASET_DIR 的包。
4. **落实统一环境与 DSH 记录。** 固定运行时、浏览器/GPU、超时、依赖获取、隔离和预算，再实现独立验收并预演。

本轮只新增运行证据、查询参考和评测文档，使用临时浏览器与 HTTP 检查设施；没有修改既有业务代码或原始作品，没有调用参赛模型，没有运行比赛。
