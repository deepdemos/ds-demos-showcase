# DeepDemos 全站业务需求

版本：v1.0（全量业务核对稿，尚未冻结）  
日期：2026-10-14  
用途：向被测模型说明真实业务，让模型自行分析业务并决定实现方案。

本文件只陈述业务需求、角色权限、信息要求、处理规则和可观察结果。不规定技术栈、系统分层、模块拆分、数据库或表结构、接口形式、部署拓扑、视觉风格、页面布局和具体交互控件。

需求依据当前工程中的功能实现及公开功能核对整理。涉及运行设置的规则，应使用同一份明确的业务参数；不能把历史文档中的过期描述当成当前规则。第 32 节的待确认事项在明确前不作为隐含考核条件。

## 1. 业务目标与范围

- **BIZ-001**：平台收集、发布和展示用户使用 AI 制作的网页作品、文件包及外部链接作品，让访客能够发现、体验、下载和讨论这些作品。
- **BIZ-002**：平台保留作品作者、模型声明、提示词、生成条件、会话记录和更新过程，帮助用户理解作品来源和制作经过。
- **BIZ-003**：用户能够围绕模型、题目、提示词和分类浏览作品，比较相同题目或提示词下的不同成果。
- **BIZ-004**：平台支持账号用户、匿名发布者、自动化代传者和管理员参与，各自具备明确的操作边界。
- **BIZ-005**：管理员能够审核内容、维护词表与模型题目归属、处理社区问题、安排公开展示内容，并查看管理操作记录。
- **BIZ-006**：平台已有上千件真实作品，需求覆盖真实内容的长期保存、可访问性和信息一致性。当前内容数量是业务背景，不是固定的容量上限或性能门槛。
- **BIZ-007**：上传作品中的游戏、动画和网页程序作为用户提供的内容接收。平台提供托管和体验能力，不要求重新制作这些作品的内容。
- **BIZ-008**：本站作品的用户评分、热度和模型统计属于平台业务，和外部评测活动对 AI 的工程能力评价分别处理。

## 2. 参与者与权限

| 参与者 | 可以完成的业务 | 主要边界 |
|---|---|---|
| 未登录访客 | 浏览公开内容、体验作品、下载允许下载的内容、查看榜单与公开资料；按规则匿名发布和评分 | 不能使用账号收藏、账号历史、关注、发帖回复或管理权限 |
| 正常账号用户 | 登录、管理自己的资料与作品、收藏、记录账号历史、关注、评分、讨论和举报 | 无权修改他人的作品、私人收藏、账号历史或通知 |
| 作品作者 | 更新、删除自己账号名下的作品，说明修改内容，可保留旧版本 | 作者权限来自实际归属，不能通过修改署名取得 |
| 匿名发布者 | 提交作品，可填写匿名署名，取得提交结果与作品访问入口 | 匿名署名不是账号；不能以署名取得后续编辑或删除权 |
| 自动化代传者 | 按公开发布说明提交作品、资源和生成信息，进行重试及结果查询 | 按其实际账号或匿名身份取得权限；信任发布凭证不授予管理权 |
| 管理员 | 内容审核、作品管理、账号管理、社区治理、词表及实体治理、运营与管理记录查看 | 必须遵守业务合法性和引用关系限制，不能以管理权限制造错误归属或虚假成功 |
| 暂停、封禁或注销状态账号 | 按公开访客规则浏览可公开内容 | 不能以不可用账号身份执行要求正常登录的操作 |

- **ROLE-001**：同一用户可以同时是访客、作者和社区参与者，管理员也可以正常参与这些业务。
- **ROLE-002**：知道某件作品、收藏夹、通知或管理记录的标识，不等同于取得对它的修改权限。
- **ROLE-003**：对需要账号身份的操作，必须依据当前账号状态和当前权限判断，不能只沿用页面打开时的判断。
- **ROLE-004**：无法完成身份确认的背景业务，不应把正在浏览公开作品的访客无故带离当前内容。
- **ROLE-005**：实际保存的作者归属、公开展示的署名和管理员权限须分别表达，不能混为一项。

## 3. 公开范围与跨业务规则

- **VIS-001**：作品至少区分待审核、已上架、已拒绝三种业务状态，并能向提交者说明当前结果。
- **VIS-002**：常规公开作品列表、公开搜索、作品排行榜和公开发现内容只纳入已上架且允许在当前展示范围出现的作品。
- **VIS-003**：主站允许通过已知作品访问入口查看尚未上架的已提交作品，包括详情、可体验内容、可下载内容和生成记录；这不意味着该作品已经进入公开目录。
- **VIS-004**：主站中被拒绝的作品当前仍具有已知入口可读的业务语义；拒绝不等同于删除。最终是否沿用该规则见第 32 节。
- **VIS-005**：获得作品访问入口不授予编辑、删除、审核或变更归属权限。
- **VIS-006**：独立只读展示站只允许访问已上架且明确获准在该站展示的作品。非入选内容不能因知道其入口而被访问。
- **VIS-007**：管理员可以查询待审核、已拒绝等管理范围内容，普通用户不能通过公开列表条件枚举这些内容。
- **VIS-008**：收藏夹、账号浏览历史和通知各有独立的可见规则，不能沿用作品的已知入口可读规则。
- **VIS-009**：公开汇总不能泄露账号凭据、私人收藏、个人历史、他人通知或管理处理信息。
- **VIS-010**：审核、展示授权和账号权限发生变化后，后续读取应反映有效业务状态；不同访问入口不能无故互相矛盾。
- **VIS-011**：作品、模型、题目或标签的业务关联发生变更后，对应查询、数量、比较结果和管理记录应保持一致。
- **VIS-012**：不确定、未填写、尚无评分和确实为零的数据须区分表达，不能用零或确认信息冒充缺失数据。
- **VIS-013**：被拒绝、失败、部分成功、无需变化和处理完成应分别表达；系统不能将没有执行的动作描述为已成功。

## 4. 首页、内容发现与站点介绍

- **HOME-001**：访客能够从站点主要入口发现作品库、探索内容、排行榜、讨论区和作品发布能力。
- **HOME-002**：访客能够浏览管理员精选作品，并分辨精选内容和普通内容。
- **HOME-003**：精选作品具有明确的展示顺序，其中可以指定一件主要展示作品。
- **HOME-004**：首页能展示近期发布的作品，并允许继续浏览更多近期内容。
- **HOME-005**：平台能从允许公开的作品中提供随机发现内容；随机发现不能绕过作品状态或展示范围限制。
- **HOME-006**：平台能提供未证实模型相关作品的发现入口，并明确其模型信息尚未确认。
- **HOME-007**：访客能查看站点公告、站点介绍、内容规模、近期活动和访问概况。
- **HOME-008**：公开内容不足、无精选内容或附加统计暂时不可用时，仍能正常进入可用的核心业务。
- **HOME-009**：提供的作品、模型、题目和作者发现入口，应能进入相应对象或内容集合。

## 5. 作品库、搜索、筛选和排序

- **LIB-001**：作品浏览信息包含可识别的标题、作品类型、封面或缺封面说明、作者及相关模型和标签信息。
- **LIB-002**：访客能够打开作品详情，复制或分享可继续访问该作品的入口。
- **LIB-003**：作品库支持关键词搜索；当前检索范围包括作品标题、简介和标签文本。
- **LIB-004**：用户能够清除搜索条件，恢复对应范围内的作品集合。
- **LIB-005**：无匹配内容时应明确说明，并允许修改或移除条件继续查找。
- **LIB-006**：标签包含类别和具体值。一个作品能够有多个标签，但同一个类别和值的组合不重复计入。
- **LIB-007**：同一标签类别下选择多个值表示满足任意一个；不同类别同时选择表示必须同时满足。
- **LIB-008**：例如选择模型 A 和模型 B，再选择游戏类型，结果应为 A 或 B 制作、同时属于游戏类型的作品。
- **LIB-009**：支持按作者、模型、题目及作品已有的生成轮数、生成耗时、运行平台等条件查找。
- **LIB-010**：数值条件支持适用的精确值、范围或上下界筛选；不合法条件应被拒绝，不能无提示忽略。
- **LIB-011**：支持按最新发布、浏览热度、随机发现以及有提示词内容的业务需要切换作品顺序或集合。
- **LIB-012**：最新发布按作品创建时间由近到远；浏览热度按作品浏览计数由多到少。并列内容应保持可理解且稳定的顺序。
- **LIB-013**：随机发现仍须遵守全部筛选和公开范围条件；同一轮浏览的后续内容不能因重新抽样出现不必要的重复。
- **LIB-014**：作品库能够以作品信息或第一轮提示词为主要阅读内容进行切换，并保持同一批筛选条件。
- **LIB-015**：列表支持分批浏览后续内容，提供当前结果总数；总数与实际筛选条件一致。
- **LIB-016**：修改搜索、筛选或排序后，应从相应新结果开始浏览，不继续使用旧结果的位置导致遗漏。
- **LIB-017**：刷新、返回或分享当前浏览条件时，用户能够恢复可理解的查找状态。
- **LIB-018**：作品类型不同应有可辨识的能力说明，不把文件包或外链描述为保证可以直接运行的网页作品。
- **LIB-019**：长标题、中文、特殊字符和缺封面内容仍可识别和访问，不以虚构内容掩盖信息缺失。
- **LIB-020**：读取失败、结果加载中和没有结果是不同情况，应能区分并允许再次尝试。

## 6. 作品详情、体验和下载

- **DEMO-001**：详情展示作品标题、简介、作者、类型、模型声明、标签、发布时间、有关更新信息和业务统计。
- **DEMO-002**：已提供的第一轮提示词、模型不确定性说明、视频链接、生成条件、会话记录和版本信息应归于对应作品。
- **DEMO-003**：未提供的附加信息应如实留空或说明缺失，不能自动编造提示词、生成日志或制作耗时。
- **DEMO-004**：用户能够从作品信息继续查看相关作者、模型、题目和标签内容。
- **DEMO-005**：用户能够查看相同提示词作品、关联题目作品及相关推荐；相关内容仍遵守有效公开范围。
- **DEMO-006**：用户能够查看当前作品的评分信息、自己的评分状态及适用的收藏状态。
- **DEMO-007**：用户能够进入该作品关联的讨论，并分辨作品本身与讨论内容。
- **PRE-001**：网页作品可在站内体验，也能够进入专门的作品体验状态，减少站点其他操作对作品的干扰。
- **PRE-002**：单 HTML、单 SVG 和包含多个静态资源的网页作品包，均应按各自内容正确提供体验。
- **PRE-003**：作品引用的样式、脚本、图片、字体等随作品接收的资源应可访问，目录关系不能因平台托管而失效。
- **PRE-004**：作品的模块加载、相对资源读取和生成图形所需能力应在允许的运行条件下可用。
- **PRE-005**：作品需要浏览器保存进度或设置时，正常刷新后仍应能按作品自身逻辑读取；平台不承诺替作品增加原本没有的跨设备进度同步。
- **PRE-006**：用户主动进入作品后，作品需要的键盘和鼠标操作应有效；站点快捷操作不能错误截获作品输入。
- **PRE-007**：需要鼠标控制视角的作品应能在许可条件下使用其操作能力，用户也能退出该操作状态。
- **PRE-008**：用户能够扩大作品显示并恢复普通浏览，且有可用的退出方式。退出方式不能依赖已被作品占用的某一个按键。
- **PRE-009**：用户能够重新开始一次作品加载或尝试重新打开失败的作品。
- **PRE-010**：加载中、已经完成页面加载和疑似加载失败需合理表达；单纯显示“已加载”不能伪造作品实际可运行的结果。
- **PRE-011**：作品程序不得读取主站私有资料、登录凭据或利用平台授权擅自执行站内管理操作。
- **PRE-012**：第三方资源失效、原始作品损坏和平台资源提供失败须能作为不同原因处理，不凭空补出原始作品功能。
- **PRE-013**：移动设备能够按作品支持的操作方式进入和退出体验；作品本身仅支持键盘时，应说明其操作条件。
- **DOWN-001**：网页作品和文件包作品支持下载其对应内容；外部链接作品提供外链访问，不提供虚假的本站下载包。
- **DOWN-002**：单文件作品能够下载原有格式文件，多文件作品能够下载对应作品包，内容不能串到另一作品。
- **DOWN-003**：作品更新后，后续体验和下载应取得相应有效版本；普通浏览和评分不应被误认为修改了作品内容。
- **DOWN-004**：缺少文件、目标已删除或当前无权访问时，应明确失败，不返回伪成功或无关文件。
- **DOWN-005**：浏览和下载分别产生相应业务计数，不能因一次请求被重复计算成大量操作。

## 7. 作品发布

### 7.1 发布信息与内容类型

- **PUB-001**：登录用户和按规则允许的匿名发布者均能提交作品。
- **PUB-002**：发布时必须提供作品标题、作品类型、该类型所需的内容，以及模型声明。
- **PUB-003**：可提供简介、第一轮提示词、其他标签、模型不确定性依据、封面和介绍视频链接。
- **PUB-004**：可提供生成轮数、生成耗时、运行平台等生成条件；这些条件不得与作品内容或作者身份混淆。
- **PUB-005**：网页作品接受单个 HTML、单个 SVG 或有可识别入口的网页 ZIP；当前网页包以 `index.html` 为标准入口。
- **PUB-006**：文件包作品接受 ZIP，允许没有网页入口，但不得因此被承诺为可站内运行的作品。
- **PUB-007**：外链作品必须提供有效的 HTTP 或 HTTPS 外部地址，不要求上传本站托管文件。
- **PUB-008**：外链类型与文件上传等互斥输入组合应被拒绝，不能存成含义冲突的作品。
- **PUB-009**：网页 ZIP 中的目录与资源关系应保留；作品附带的生成日志应可识别为该作品的生成记录。
- **PUB-010**：标题不能以空白代替有效内容。缺失必填项、错误作品类型、损坏文件或不符合接收条件的内容应给出原因。
- **PUB-011**：封面可以不提供；提供封面时需要有效图片，平台能提供适合不同阅读场景的清晰封面内容。
- **PUB-012**：介绍视频属于可选外部展示信息，第三方不可用不能使作品主体无法浏览。

### 7.2 模型声明与不确定性

- **PUB-013**：知道确切型号的发布者能够查找并选择已有型号，可查看名称、厂商及已有作品信息。
- **PUB-014**：只知道厂商、不知道型号时，允许以该厂商的未定型号声明发布。
- **PUB-015**：完全不知道模型时，允许明确声明未标注；不能迫使发布者编造确切型号。
- **PUB-016**：网传灰测或未证实型号应能以未证实信息声明，不能自动变成已经确认的真实型号。
- **PUB-017**：上述不确定声明可以附带说明或证据，后续治理应保留其来源。
- **PUB-018**：模型确认程度与作品是否已经发布、作品质量和作者是否可信分别表达。
- **PUB-019**：已有名称或别名能正确对应同一型号，不因不同写法无故创建重复型号。
- **PUB-020**：新出现的型号信息可形成待确认事项，管理员确认前不能把名称识别结果当成可靠归属结论。

### 7.3 标签建议与题目声明

- **PUB-021**：根据标题、简介或提示词，平台能够提供可选择的标签建议及其依据。
- **PUB-022**：发布者可以全部采纳、部分采纳、自行修改或跳过建议；建议不是强制输入。
- **PUB-023**：建议不能仅因展示给发布者就修改作品的正式信息；所采纳内容还须满足词表规则。
- **PUB-024**：固定词表没有所需值时，发布者能够申请新值，说明其含义，可关联到本次作品。
- **PUB-025**：发布者能够声明作品是在挑战一项已有题目，平台保留题目与作品的申请关联。
- **PUB-026**：发布者也能够随作品提议新题目，提供题名、说明和适用分类。
- **PUB-027**：自报挑战或提议题目应进入待确认过程，不能仅因作者选择就成为已确认的正式挂题。
- **PUB-028**：题目声明非法、目标不存在或缺少提议的必要信息时，提交不能伪装成已经成功建立题目关系。
- **PUB-029**：相似题目建议只是辅助判断，不代表题面已一致或作品已经完成题目。

### 7.4 草稿、重试和重复内容

- **PUB-030**：填写过程中可返回修改已填信息，不应因此丢失已有文字和选择。
- **PUB-031**：未完成的新作品发布可保留文字与选择草稿，再次进入时允许继续或丢弃。
- **PUB-032**：草稿不能假装恢复尚未重新选择的作品文件或封面，需说明这些材料是否仍需提供。
- **PUB-033**：编辑已有作品与新建作品的草稿应区分，不能恢复成对错误作品的修改。
- **PUB-034**：草稿保存失败不得阻止正常提交；发布成功后不能继续把已完成提交当成未提交草稿。
- **PUB-035**：提交前能够核对即将发布的关键信息，提交后取得作品访问入口和实际处理状态。
- **PUB-036**：同一次成功提交的重试应能返回已经创建的作品，不意外产生第二件作品。
- **PUB-037**：同一账号作者再次提交相同内容时，按重复内容规则处理，并指出已有内容；不同账号不因作品字节相同就被强行归为同一作者。匿名提交使用匿名作者范围判断重复，匿名署名不同不等同于两个不同账号。
- **PUB-038**：管理员可按明确权限强制保留重复内容；普通发布者不能利用此能力绕过规则。
- **PUB-039**：失败提交不得留下对外声称已成功发布、实际没有作品内容的半成品。

### 7.5 发布身份与审核策略

- **PUB-040**：账号用户提交的作品归属于实际提交账号，不能以任意填写的署名冒充其他账号。
- **PUB-041**：匿名发布可填写展示署名，归于匿名发布范围；匿名作品集合可以统一浏览，但匿名署名不代表具有账号管理权。
- **PUB-042**：平台可以配置全局自动上架，以及在全局自动上架关闭时是否允许匿名作品直接上架。
- **PUB-043**：现行策略如下。表中均指正常有效提交，信任发布通道见下一条。

| 全局自动上架 | 允许匿名直接上架 | 登录提交结果 | 普通匿名提交结果 |
|---|---|---|---|
| 开启 | 任意 | 已上架 | 已上架 |
| 关闭 | 开启 | 待审核 | 已上架 |
| 关闭 | 关闭 | 待审核 | 待审核 |

- **PUB-044**：站点可发放用于匿名代传的信任发布凭证。有效凭证允许按信任通道直接上架；无效凭证不能取得该能力。
- **PUB-045**：信任发布凭证不等同账号身份；已登录提交仍使用该账号及登录发布策略。
- **PUB-046**：待审作品不发布为公开的新作品公告；作品实际上架后才按规则产生公开发布信息。
- **PUB-047**：待审核状态应让提交者知道内容已经接收但尚未加入公开目录；不能把接收成功和审核成功混为一项。
- **PUB-048**：需要管理员处理的新提交能够形成待办提醒。具有账号作者的作品在审核后能获得审核结果通知。
- **PUB-049**：普通匿名发布及按普通匿名身份进行的自动化发布有频率限制，作品接收有内容大小限制；超限说明应可理解，并允许在许可条件下再次提交。有效信任发布和账号发布不被无说明地套用普通匿名上传次数规则。

### 7.6 自动化代传与远程材料接收

- **PUB-050**：自动化发布者能取得作品类型、必要发布信息、可用词表、身份范围、限制和结果含义的发布说明。
- **PUB-051**：除直接提供内容文件外，发布者能提交可公开读取的远程作品文件地址，由平台接收该材料，并提供相同必要作品信息。
- **PUB-052**：远程材料可以附带可读取的封面地址；远程接收仍遵守作品类型、文件格式、体积、有效图片、身份、审核及重复内容规则。
- **PUB-053**：只接受支持的公开地址；无效地址、受限目标、重定向到不允许目标或无法下载的材料不能被当作已正确接收。
- **PUB-054**：远程接收失败或资源超限时说明失败，不留下可以被误认为正常发布的空作品或错误封面。
- **PUB-055**：自动化发布取得作品访问入口、审核状态及此次是否实际新建；网络重试仍按同一次提交规则处理。
- **PUB-056**：远程材料方式提交必须填写非空简介并至少提供一个有效标签，且包含模型声明；不能直接沿用普通文件提交中简介可选的条件。

## 8. 作者维护、版本与删除

- **OWN-001**：正常账号作者能够修改自己作品的标题、简介、提示词、标签、模型信息、封面、内容文件、作品类型及相应附加链接。
- **OWN-002**：更换内容或类型后仍须满足该类型接收规则；修改标签不能把必须的模型声明全部去掉。
- **OWN-003**：作者可以说明此次更新的内容，用户能够分辨作品创建和后续更新。
- **OWN-004**：更新不应无故改变作者归属或生成另一件完全无关的作品。
- **OWN-005**：提交非法的新包时，应拒绝更新并保留此前可用的作品内容；不能出现失败后旧作品也被破坏的结果。
- **OWN-006**：作品内容更新后，用户后续体验、下载和查看信息应得到一致的有效版本。
- **OWN-007**：作者能够选择在更新前保留旧版本，并分别访问新旧内容。
- **OWN-008**：旧版内容与当前作品应具有可识别关系，能从更新过程追溯，不和当前内容串用。
- **OWN-009**：时间线应包含创建、成功更新、更新说明以及适用的旧版入口；失败或没有变化的操作不得冒充成功更新。
- **OWN-010**：账号作者和管理员可删除有权管理的作品，其他人即使知道作品入口也不能删除。
- **OWN-011**：删除作品后，不再提供该作品的有效内容；相关收藏、账号历史和分类、模型、题目关系应按删除事实清理或失去有效引用。
- **OWN-012**：已经存在的申请或管理记录不能被改写成另一件作品的记录；删除后仍须能辨别目标已不存在。
- **OWN-013**：删除曾被收藏或浏览的作品不应因关联关系而无故失败。
- **OWN-014**：作品删除对相关论坛讨论、公告及历史旧版的保留规则须明确，未明确部分见第 32 节。
- **OWN-015**：匿名发布者没有账号作者的更新和删除权限；需要管理时按管理员处理规则执行。

## 9. 会话记录、提示词与作品关联

- **LOG-001**：作品可以带有多份生成会话记录，每份有可识别名称、时间和大小信息。
- **LOG-002**：用户能够查看记录列表并读取对应内容；空记录集合不是作品加载失败。
- **LOG-003**：支持阅读文本、Markdown 及已支持的生成会话记录格式；无法识别的记录应如实表达而非编造对话。
- **LOG-004**：记录与对应作品关联，不能通过更换记录名称读取别的作品或平台私有文件。
- **LOG-005**：生成记录的可读范围服从所属作品在当前站点的访问范围，频繁读取按资源保护规则处理。
- **LOG-006**：记录读取失败不应使已经能够查看的作品主体消失；用户应能识别是附加记录不可用。
- **LOG-007**：能够阅读 DSH 导出的 JSONL 会话轨迹，区分已提供的用户消息、模型回复、推理记录、工具使用及结果，显示已有的模型和预设信息；不把未知事件补写成实际对话。
- **PROMPT-001**：第一轮提示词原文可以阅读，展示时不能把不同作品的提示词互换。
- **PROMPT-002**：平台能找出使用同一提示词的其他已公开作品，并提供继续访问入口。
- **PROMPT-003**：相同提示词的判断统一换行形式并去掉首尾空白；除此之外的正文差异不能直接当作完全相同。
- **PROMPT-004**：没有提示词的作品不与其他没有提示词的作品组成“同提示词”结论。
- **PROMPT-005**：语义相近、归于同一道题和正文完全相同是三种不同关系，应明确区分。
- **PROMPT-006**：相关推荐可以根据共同标签等已有信息提供，并排除当前作品和不允许出现在推荐范围的内容。

## 10. 标签与探索

- **TAG-001**：标签以类别和具体值描述作品，每一类别可有名称、说明及重要程度，每一具体值可有解释、分组及适用状态。
- **TAG-002**：支持管理员预先维护可用值的标签类别、允许使用者填写值的标签类别，以及使用整数值的标签类别。
- **TAG-003**：固定候选值应供用户选择；缺少值时可申请，不能绕过管理直接把任意字符串变为正式固定值。
- **TAG-004**：自由值仍需满足有效文字规则；数值型标签需要合法整数，不能混入任意文字。
- **TAG-005**：标签类别内的值可以按分组浏览或查找，用户能理解不同类别和值的含义。
- **TAG-006**：标签可有同类父子关系；用户能查看上级、下级和对应作品集合。
- **TAG-007**：具体标签值的关联数量应能与所声明的统计范围对照，同一作品不因重复关联同一个值而多计数；标签类别汇总是否计独立作品见第 32 节。
- **TAG-008**：用户能够查看标签相关作品并继续组合查找，不丢失标签语义。
- **TAG-009**：已经退役的值应有明确状态，不能无提示作为正常的新发布候选；已有历史作品的相关信息仍可解释。
- **TAG-010**：作者归属和版本关系属于系统维护的信息，用户不能通过普通标签编辑伪造作者或旧版关系。
- **EXPLORE-001**：平台提供按模型、题目和描述性分类探索内容的能力，并可继续查看完整集合。
- **EXPLORE-002**：描述性分类覆盖已有类型、类别、玩法等词表，展示其对应公开内容及数量。
- **EXPLORE-003**：探索中的模型、题目和标签资料可查看简要信息，再进入完整内容；简要信息与完整内容必须对应。
- **EXPLORE-004**：探索汇总和所属展示站的可见范围一致，不能从另一个发现入口泄露范围外的作品。

## 11. 模型档案与模型统计

- **MODEL-001**：用户能够查找模型，按名称、已识别别名或厂商筛选，并查看模型说明。
- **MODEL-002**：模型应能表达已确认、待确认、未证实和已退役等业务状态，以及确切型号或不同不确定声明。
- **MODEL-003**：默认公开模型集合展示已确认和未证实模型，未证实信息必须标明；其他状态的额外可读范围见第 32 节。
- **MODEL-004**：模型名称与别名应能到达对应模型档案，不能无故被当成不同模型。
- **MODEL-005**：档案展示已有公开作品数量、评分资料、有效票数、常见类型与玩法、参与题目及近期作品。
- **MODEL-006**：用户能够继续浏览该模型的作品，并按已有类型、玩法及最新、评分、浏览热度等条件查找。
- **MODEL-007**：一个作品允许声明多个参与模型，各模型档案分别体现有效关联，单模型内不重复计作品。
- **MODEL-008**：模型集合支持按作品数、社区分、有效票数、最近登记和名称等业务顺序浏览，并支持后续内容查询。
- **MODEL-009**：确切型号的排名与未标注、厂商未定型号、灰测等兜底集合分别表达，不能让不确定信息冒充确切型号。
- **MODEL-010**：模型统计仅使用其关联的已公开作品；退役、合并和重新归属后相关统计须反映有效关系。
- **MODEL-011**：展示作品均分、模型社区分、有效票数与样本等级时，说明这些数值的含义，不能把不同指标混用。
- **MODEL-012**：模型社区分按有效票数加权，并用整体评分情况减轻极小样本造成的偏差，规则见第 31 节。
- **MODEL-013**：无评分证据的模型显示无评分，不以零分或整体先验分冒充其自身得分。
- **MODEL-014**：样本等级按有效票数区分无样本、低、中和较高；样本等级不等同型号已确认程度。
- **MODEL-015**：显示相同社区分时，优先考虑有效票数；排序不能依赖用户看不到的额外评分精度造成误导。
- **MODEL-016**：对已有型号的常见大小写、空白和分隔符差异，能按一致的名称识别规则处理；名称相似本身不等同于新型号已被确认。

## 12. 题目、挑战与同题比较

- **TASK-001**：用户能够查找题目，按类别、相关作品数量或最近登记浏览，查看题名、说明和关联作品。
- **TASK-002**：公开题目目录和详情只展示已确认可公开题目；待确认、隐藏和已合并题目按管理范围处理。
- **TASK-003**：题目没有单独说明但已有作品提示词时，能够给出用于理解任务的提示词摘录，并明确它来自作品内容。
- **TASK-004**：题目有可用代表作品时，可以展示该作品的代表图片，图片和作品归属一致；没有图片时不得伪造。
- **TASK-005**：同一道题可有多件作品，一件作品可关联多个题目；关联须经实际确认，不能凭文本相似直接视为已确认。
- **TASK-006**：题目中的模型比较包含各模型作品数、已评分作品的平均社区评分、已填写的平均生成轮数、平均耗时和代表性最佳作品。
- **TASK-007**：平均轮数和耗时只计算已经填写的记录；缺失记录不按零参与平均。
- **TASK-008**：同题比较中的模型分组、作品集合与数量须一致；已退役模型不参与当前有效比较。
- **TASK-009**：用户能从比较结果查看具体作品、提示词和生成记录，而不是只能看到一个汇总数字。
- **TASK-010**：题目下能够逐件展示模型声明、提示词摘要、生成条件和作品评分，并标明与基准提示词一致、不一致或缺失未知。
- **TASK-011**：没有提示词的作品标为一致性未知，不能算作已复现题面。
- **TASK-012**：基准提示词选取比较范围内出现最多的有效提示词；出现次数相同则采用更早登记的那一项。
- **TASK-013**：题目自身说明存在时优先作为题目说明；否则引用基准提示词，须显示说明来源。
- **TASK-014**：用户能够只查看与基准提示词一致的作品，或查看当前比较集合中的作品及差异。
- **TASK-015**：用户能够从题目开始提交挑战作品，所声明题目应随提交被正确保留，审批后归于原来的作品。
- **TASK-016**：根据标题、简介和提示词可提供可能相关的已有题目建议，但建议不等于正式挂题，也不等于作品已经通过题目评价。

## 13. 账号与个人资料

- **ACC-001**：用户能够注册账号，提供合法用户名和密码；已被使用的用户名不能再次注册。
- **ACC-002**：用户名、密码和资料文字的长度与格式限制见第 31 节；无效输入应说明原因。
- **ACC-003**：正确凭据能够登录，错误凭据或不可用账号不能取得有效账号操作权限。
- **ACC-004**：用户能够查看自己的当前登录状态，正常刷新后保持有效身份，并主动退出当前使用环境。
- **ACC-005**：用户能够修改自己的展示名、简介和头像，清除头像后仍有可识别的账号信息。
- **ACC-006**：修改展示名不改变真实账号归属，不把历史作品或互动转移到另一个账号。
- **ACC-007**：用户能够提供原密码并修改密码；原密码不正确时不能完成修改。
- **ACC-008**：修改后新密码可用于后续登录，旧密码不能继续用于新登录。其他已存在登录状态的处理见第 32 节。
- **ACC-009**：其他用户可以查看公开资料和公开作品，不能取得密码、私有设置或其他账号机密。
- **ACC-010**：用户能够分别控制账号侧是否继续记录浏览历史，以及是否删除已经保存的历史。
- **ACC-011**：账号资料、状态和权限的变更后，相关业务应使用当前有效资料，不继续误用已经失效的操作身份。
- **ACC-012**：登录失败或操作受限不能无故清除已经填写但尚未提交的作品内容。

## 14. 收藏与收藏夹分享

- **COL-001**：正常账号用户能将作品加入或移出自己的收藏。
- **COL-002**：用户有默认收藏夹，默认夹保持私密，不能改名、删除或转为公开。
- **COL-003**：用户能够创建多个自定义收藏夹，设置名称、说明和公开或私密状态。
- **COL-004**：创建时名称不能为空，同一用户不能新建同名收藏夹；上限见第 31 节。
- **COL-005**：自定义收藏夹支持改名、修改说明和可见性、删除，以及增删作品。
- **COL-006**：同一作品在同一收藏夹内不重复保存。重复执行加入操作不增加重复条目。
- **COL-007**：同一作品可以在同一用户的不同收藏夹中分别保存，各夹状态应正确区分。
- **COL-008**：用户能够获知某作品是否已在自己的收藏夹内；默认收藏和加入指定收藏夹不混用。
- **COL-009**：收藏夹展示名称、说明、作品数、更新时间及可用的代表内容，作品按加入时间由近到远浏览。
- **COL-010**：用户能分享公开自定义收藏夹，访客可读其允许公开的内容，但不能修改该夹。
- **COL-011**：改回私密后，其他人即使知道分享入口也不能继续读取私密收藏夹。
- **COL-012**：所有收藏夹只允许所有者执行个人维护操作；猜到收藏夹身份不能取得他人的管理权限。
- **COL-013**：收藏关系刷新后仍存在；删除收藏夹不删除原作品。
- **COL-014**：作品删除后的收藏关系应正确清理；已下架作品在公开收藏中如何呈现见第 32 节。

## 15. 浏览历史与隐私控制

- **HIS-001**：未登录访客可以查看本机近期浏览过的作品，不要求先注册账号。
- **HIS-002**：本机记录与账号记录是两种业务来源；用户能够分辨记录来自哪里。
- **HIS-003**：正常登录且开启账号历史时，浏览作品也形成账号历史，供该账号在其他设备查看。
- **HIS-004**：本机和账号记录共同展示时，相同作品按较近一次浏览去重，并按时间由近到远排列。
- **HIS-005**：再次浏览同一作品更新最近浏览时间，不不断产生相同作品的历史条目。
- **HIS-006**：本机和账号历史各有保留上限，超出时优先保留最近记录；当前上限见第 31 节。
- **HIS-007**：用户能够删除单项历史或清空历史；同时存在本机和账号记录时，当前操作涉及的来源要明确。
- **HIS-008**：关闭账号记录仅停止形成新的账号历史，不自动删除已有记录，也不等于清除本机记录。
- **HIS-009**：提供关闭并清空账号历史的业务操作，执行前应说明会删除已有记录。
- **HIS-010**：账号历史只由本人查看，个人公开主页不提供他人的浏览轨迹。
- **HIS-011**：匿名访客浏览作品时，账号历史记录失败不能强制中断公开浏览或要求登录。
- **HIS-012**：本机无法保存记录、账号历史暂时不可读或旧记录内容不可用时，仍允许继续正常浏览。

## 16. 作者资料、关注与社区声望

- **SOC-001**：用户可以查看作者公开资料、公开作品、相关社区贡献及公开收藏夹。
- **SOC-002**：匿名作者集合与账号作者资料应区别呈现，不能把所有匿名作品宣称为同一个真人账号的作品。
- **SOC-003**：正常账号用户可以关注或取消关注另一位允许被关注的用户，不能关注自己。
- **SOC-004**：重复关注状态不应形成重复关系，取消后双方关注和粉丝数量同步反映。
- **SOC-005**：用户能够查看公开关注名单和粉丝名单，并访问对应用户资料。
- **SOC-006**：关注产生的通知按通知规则发送；取消关注不应被误报为新增关注。
- **SOC-007**：社区内容可以获得点赞和感谢，作者的获赞、感谢和声望资料随有效互动变化。
- **SOC-008**：每个有效赞对应作者声望加 1，每个有效感谢加 2；取消或清理相应互动后回退对应影响。
- **SOC-009**：正常用户榜支持按声望、获赞、感谢、发帖、回复、作品和粉丝数量等口径浏览。
- **SOC-010**：用户榜只纳入正常账号；作品、主题和回复数量分别依据允许公开的有效内容统计。
- **SOC-011**：榜单口径与个人资料所呈现的同口径数据一致，不能重复计算同一关系。

## 17. 作品评分与作品排行榜

- **RATE-001**：正常登录用户和满足匿名评分规则的访客都能为已上架作品评分。
- **RATE-002**：评分采用 1 至 5 的整数，分别表达从较差到优秀的作品评价，不接收区间外或非整数分数。
- **RATE-003**：同一登录账号对同一作品只有一份当前有效评分，可以修改或撤销。
- **RATE-004**：匿名评分根据匿名参与主体识别，同一匿名主体对同一作品只有一份当前有效评分；不把匿名标识宣称为已核实真人身份。
- **RATE-005**：匿名主体与登录账号主体是不同评分身份；身份切换后的合并规则见第 32 节。
- **RATE-006**：用户能够获知自己当前给出的分数，以及作品均分、有效评分人数、各分数分布、5 分票和 1 分票数量。
- **RATE-007**：改分时更新原评分影响，不能增加新的评分人数；撤销时去掉其影响，不能留下负票数或错误均分。
- **RATE-008**：重复提交相同评分不得增加票数；同时提交、修改或撤销时，最终明细与汇总一致。
- **RATE-009**：无评分作品应明确没有评分证据，不能显示成用户实际给了 0 分。
- **RATE-010**：支持按平均分、5 分票数、1 分票数、5 分减 1 分净票、评分人数和综合热度查看作品榜。
- **RATE-011**：平均分、5 分票、1 分票和净票榜排除零评分作品；评分人数与综合热度榜可以包含零评分作品。
- **RATE-012**：综合热度为浏览次数 + 2 × 下载次数 + 有效评分人数，不是平均分。
- **RATE-013**：支持全部、最近 7 天和最近 30 天的作品范围。时间范围依据作品创建时间，不是只统计该时间段内新增的票。
- **RATE-014**：榜单只纳入当前已上架作品，数量、分页与所选榜单条件一致。
- **RATE-015**：并列排序规则、模型统计规则及当前数值参数见第 31 节。
- **RATE-016**：评分失败应保留之前有效分数，不能显示已经成功改分；频率受限时说明限制。

## 18. 论坛与作品讨论

### 18.1 浏览与发表

- **FORUM-001**：访客能够浏览允许公开的论坛主题及回复，正常账号用户能够发布主题和回复。
- **FORUM-002**：主题包含标题、正文、作者、分类、标签、发布时间及适用的关联作品。
- **FORUM-003**：主题可以讨论一般话题，也可以专门关联一件已上架作品；作品关联讨论须指向实际有效作品。
- **FORUM-004**：支持按关键词、分类、精确标签、关联作品、一般主题或作品讨论查找主题。
- **FORUM-005**：关键词查找覆盖主题标题和正文，标签查找按标签成员精确匹配，不能把近似子串当成同一标签。
- **FORUM-006**：能够只看精华、本人回复参与过的讨论、关注作者的讨论；未登录用户没有本人参与或关注集合。
- **FORUM-007**：主题支持最新、浏览最多、回复最多和讨论热度等顺序；最新集合中的置顶与精华内容按其优先级呈现。
- **FORUM-008**：现行讨论热度为公开回复数 + 浏览数 ÷ 50，并列时优先较新主题；不要把未实现的时间衰减宣传为现行公式。
- **FORUM-009**：主题与回复支持分批浏览，数量和实际可见内容相符。
- **FORUM-010**：正文支持已有的格式化文字与有效外链，内容展示不能变成对主站的未授权操作。
- **FORUM-011**：回复可以指向该主题中的一个有效公开回复，不能回复到另一主题或不存在的回复。
- **FORUM-012**：需要审核的用户发言先进入待审核，其他符合发表条件的用户发言可直接公开。
- **FORUM-013**：是否需要审核依据当前审核要求和信任等级判断；新注册账号默认属于需要审核范围。
- **FORUM-014**：待审核内容不计为已经公开的主题或回复；通过后计入公开内容，拒绝后不能冒充发表成功。
- **FORUM-015**：锁定主题停止接收新回复，但不因此自动删除已有公开讨论。
- **FORUM-016**：用户能够分辨正常、待审、被拒绝、已关闭讨论及已解决等适用状态。
- **FORUM-017**：旧作品评论记录可继续阅读；新增讨论使用论坛主题和回复，不要求恢复已经停止的新旧评论双轨写入。

### 18.2 互动与举报

- **FORUM-018**：登录用户可对公开主题或回复点赞、感谢，并获知总数与自己的互动状态。
- **FORUM-019**：同一用户对同一内容的同一种互动最多一个有效状态；再次切换可取消，不产生重复计数。
- **FORUM-020**：用户不能给自己的内容点赞或感谢，不能对不存在或不可见目标产生有效互动。
- **FORUM-021**：新增互动影响作者声望并形成适用通知；取消或删除相关互动回退相应统计。
- **FORUM-022**：正常用户能够举报公开主题或回复，提供理由。
- **FORUM-023**：举报目标必须实际存在且满足可举报范围，不接收指向不存在内容的举报。
- **FORUM-024**：同一用户对同一目标已有未处理举报时，不重复堆积同一举报。
- **FORUM-025**：发帖、回复、举报和外链使用按公开的频率及内容规则处理；被拒绝时说明原因。

## 19. 站内通知

- **NOTIF-001**：账号用户能够查看只属于自己的通知，按时间由近到远浏览，并查看未读数量。
- **NOTIF-002**：通知覆盖回复、被提及、收到互动、被关注、作品审核结果及管理员待审核提醒等已有事件。
- **NOTIF-003**：通知应包含可识别的事件类型、相关参与者、时间及适用的作品、主题或回复入口。
- **NOTIF-004**：自己的操作不应无必要地给自己产生回复、关注或互动提醒。
- **NOTIF-005**：同一次回复中的重复提及只产生适用的一份提醒；主题作者和被提及者重合时不重复提醒同一事件。
- **NOTIF-006**：用户能将单项或全部本人通知标记已读；重复标记不产生负的未读数。
- **NOTIF-007**：其他账号不能读取或修改本人的通知；知道通知身份不等于获得该通知。
- **NOTIF-008**：通知入口指向对应对象，不指向另一用户的私人资料；对象已删除或不可访问时能明确说明。
- **NOTIF-009**：收到通知不授予额外的内容、管理或修改权限。
- **NOTIF-010**：附加通知暂时不能产生时，已经成功的发表或互动不应被伪装成失败后诱导重复提交。

## 20. 公告、站点概况与致谢

### 20.1 公告与更新信息

- **ANN-001**：访客能够查看当前有效的站点公告、作品发布公告、作品更新信息和站点自身更新说明。
- **ANN-002**：公告包含标题、正文、类别、时间、适用的关联作品或主题，以及是否属于优先展示信息。
- **ANN-003**：公告区分草稿、已发布和已撤下；支持到达发布时间后公开以及超过有效期后不再公开。
- **ANN-004**：尚未发布、未来才发布、已经过期或撤下的公告不出现在当前公开公告集合中。
- **ANN-005**：优先展示公告先于普通公告，同组按较新时间优先；同一公告的公开详情与集合可见规则一致。
- **ANN-006**：管理员可以创建、编辑、撤下和删除公告，维护分类、优先级、发布时间、有效期及关联对象。
- **ANN-007**：关联主题和作品应实际存在，适用的公开主题必须已经允许公开；不能保存指向另一无关对象的错误关联。
- **ANN-008**：站点自身更新信息与作品更新信息应能区分，不把站点改动当成某件作品的新版本。
- **ANN-009**：没有独立详情的更新说明应如实表达，不能提供虚构的完整公告详情。
- **ANN-010**：自动作品公告产生于实际发布或成功更新，不由待审或失败操作冒充产生。

### 20.2 公开概况与访问统计

- **STAT-001**：平台公开介绍站点名称、说明和已有业务能力，自动化发布者也能获知适用的发布说明。
- **STAT-002**：公开内容概况包含允许公开的作品总数、按作品类型的数量、作者数量、近期新增作品、标签规模和社区内容数量。
- **STAT-003**：公开热门信息能反映已有模型、标签或内容集合，统计使用当前展示范围允许公开的信息。
- **STAT-004**：访问概况支持今日、昨日、累计和最近 7 天的访问量；日序列按实际时间排列。
- **STAT-005**：实时访问概况支持最近 1 分钟、最近 5 分钟访问次数和近期在线数量。
- **STAT-006**：现行在线口径为最近 2 分钟仍有活动的访问来源数量，不宣传为已核实真人数量。
- **STAT-007**：页面访问量、作品浏览量、下载量、账号数、作者数和在线来源数是不同指标，不能相互替代。
- **STAT-008**：累计计数应累加有效新事件，不能在刷新统计时用最近一批事件覆盖历史总数。
- **STAT-009**：统计可以有短时更新延迟，不能因为统计处理暂时失败破坏主要浏览或发布业务；具体更新窗口见第 32 节。
- **STAT-010**：公开统计不展示待审处理队列、账号私有信息或仅管理员可见的存储细节。

### 20.3 赞助与致谢

- **THANK-001**：访客能够查看有效的赞助与致谢对象及其公开留言。
- **THANK-002**：赞助信息可包含金额及是否公开金额的选择；未选择公开时不展示该条金额。
- **THANK-003**：赞助按金额及管理安排的次序展示，致谢按添加时间由近到远展示；缺少金额与零金额应区别处理。
- **THANK-004**：公开赞助总额按有效赞助记录汇总，当前包含未逐条公开金额的有效赞助；最终隐私口径见第 32 节。
- **THANK-005**：管理员能够新增、修改、停用和删除赞助或致谢记录，维护署名、类型、金额、留言和排序信息。
- **THANK-006**：致谢记录不被当成有赞助金额的交易记录；平台展示赞助信息不等于提供支付业务。

## 21. 内容审核、社区治理与账号管理

### 21.1 作品审核和管理

- **REVIEW-001**：管理员能查看待审核作品集合及各状态的作品，并查阅审核所需的内容与元信息。
- **REVIEW-002**：管理员可以通过或拒绝作品，处理后作品状态、公开目录和适用访问范围按当前规则变化。
- **REVIEW-003**：作品审核通过时产生实际公开发布信息；有账号作者时发送适用的审核结果通知。
- **REVIEW-004**：已处于目标状态的重复审核不得被记录为又完成了一次新的有效状态变化。
- **REVIEW-005**：管理员能够按状态、关键词和已有业务条件查找作品，查看待办数量与作品状态数量。
- **REVIEW-006**：管理员可以按作品维护权限修改或删除内容；状态变更与删除分别处理。
- **REVIEW-007**：管理员能够指定作品是否进入主站或关联展示站，维护作品的语言信息；更改授权应作用于对应访问入口。
- **REVIEW-008**：实际审核者、处理时间、目标、结果与适用原因应可追溯。

### 21.2 论坛治理

- **REVIEW-009**：管理员能查看所有适用状态的主题和回复，按主题、状态、分类、关联作品或关键词查找待处理内容。
- **REVIEW-010**：管理员能够通过或隐藏待审核的主题及回复。已经处理的内容不能被假称仍在审核中。
- **REVIEW-011**：首次论坛发言审核通过后，作者的论坛信任条件可提升至常规发言范围；这不等于授予管理员权限。
- **REVIEW-012**：回复审核通过后增加实际公开回复数，隐藏或删除时对应数量变化。
- **REVIEW-013**：管理员能够修改主题的标题、分类、标签及已有内容信息，并管理置顶、精华、锁定、已解决和公开状态。
- **REVIEW-014**：管理员能删除主题及其回复，或删除一条回复及受其删除影响的下级回复。
- **REVIEW-015**：删除下级讨论树时，回复数、互动和作者声望应按实际影响调整，不能只减一条却留下其他已删除互动计数。
- **REVIEW-016**：管理员能查看举报目标、理由、举报者、时间和当前处理状态，将举报标记为已处理或不予采纳，保留原举报理由和实际处理结果。
- **REVIEW-017**：已处理举报不能再次当成新举报处理；目标已不存在时仍应说明其状态，不把举报改指向别的内容。
- **REVIEW-018**：社区管理支持封禁相应账号；论坛封禁动作不能直接封禁管理员。其他账号治理入口的边界见第 32 节。
- **REVIEW-019**：社区处置应留下实际管理记录，不能将失败删除或失败封禁记成已经完成。

### 21.3 账号管理

- **USERADM-001**：管理员能查看账号、角色、状态、公开资料、登记时间和对应作品数量。
- **USERADM-002**：管理员可以在支持的范围内修改账号角色和状态，至少区分正常、暂停、封禁和注销状态。
- **USERADM-003**：普通用户不能通过个人设置取得管理角色或解除针对自己的管理限制。
- **USERADM-004**：账号角色和状态变化后，后续操作依据新权限；此前打开的页面不能成为继续越权的理由。
- **USERADM-005**：角色变更、封禁及其他管理状态变化须留痕，业务影响不得被隐瞒为普通资料修改。
- **USERADM-006**：账号数量、作者作品数和公开作者统计口径须明确；匿名署名不混计为具有账号身份的注册用户。
- **USERADM-007**：平台初次投入使用时应能取得有效的初始管理身份，以开展审核和运营维护；具体凭据与取得方式属于运行条件，不在本需求中指定默认账号或公开口令。

## 22. 首页精选与展示运营

- **FEATURE-001**：管理员能够把已上架作品加入或移出精选集合。
- **FEATURE-002**：不能把未上架作品加入首页精选，用精选入口绕过公开规则。
- **FEATURE-003**：管理员能调整精选作品之间的先后顺序，以及指定主要展示作品。
- **FEATURE-004**：重复加入已在精选中的作品不形成重复条目；移出或调整后剩余顺序明确。
- **FEATURE-005**：精选管理结果与首页实际公开内容一致，公开显示不能继续使用已经失效的选择。
- **FEATURE-006**：精选并不改变作品作者、模型归属或用户评分，不把管理员策展当作用户投票。

## 23. 标签词表治理

- **TAGADM-001**：管理员能查询标签类别与具体值，包含名称、解释、模式、重要程度、分组、层级、状态和引用情况。
- **TAGADM-002**：管理员可以新增或修改标签类别的有效业务信息，以及新增固定类别中的可用值。
- **TAGADM-003**：同一类别内具体值唯一，不能在已有值旁另建完全重复值。
- **TAGADM-004**：作者与版本关系类别为受保护信息，不能通过一般词表管理删除、改写或合并其身份含义。
- **TAGADM-005**：新固定值应属于已经存在的固定类别；自由值或整数类别不应被误当作必须预登记固定值的类别。
- **TAGADM-006**：父标签必须实际存在并属于同一类别，层级不能形成错误或循环关系。
- **TAGADM-007**：管理员能给一个值指定或清除分组，重命名一组，或清除一组的分组信息；清除分组不删除组内各值。
- **TAGADM-008**：管理员可以确认、退役或恢复适用标签值的业务状态，说明其处理依据。
- **TAGADM-009**：退役后新发布候选与历史关联应区别处理；恢复后新的合法选择应随之恢复。
- **TAGADM-010**：删除值或类别前需判断其作品引用、子标签与跨类别历史引用；存在禁止删除的依赖时应说明影响并拒绝。
- **TAGADM-011**：删除一个没有禁止依赖的类别时，处理其所属值，不能留下失去类别含义的残余信息。
- **TAGADM-012**：标签值合并必须先展示受影响作品、重复关联及源值变化，确认后再执行实际变更。
- **TAGADM-013**：当前标签合并只允许同类别中的有效源、目标，不支持跨类别合并或带子标签源值的合并；受保护类别不能合并。
- **TAGADM-014**：合并后原源值作品归于目标值，同一作品原本已有目标值时不重复计入，源值按合并规则处理。
- **TAGADM-015**：不存在的源值、没有变化或不支持的合并要如实说明，不伪造已迁移的作品数量。
- **TAGADM-016**：管理员能处理用户申请的新固定值，决定通过或拒绝，保留申请者、含义、时间及适用作品。
- **TAGADM-017**：申请通过后，正式词表及申请中指定的作品标签按实际审批结果更新；拒绝后不产生正式值或虚假作品标签。
- **TAGADM-018**：平台能获取外部型号词表并整理为待确认事项或已有型号分组信息；不因获取到名字就无审核地改写正式模型归属。
- **TAGADM-019**：词表更新、标签合并和模型名称治理后，发布时可选信息与已有作品展示应相互对应。

## 24. 模型治理、合并与归属确认

### 24.1 模型资料与名称

- **MODELADM-001**：管理员能查询全部状态模型，查看各状态数量、资料、别名、作品和引用情况。
- **MODELADM-002**：管理员能创建或修改模型名称、厂商、说明和适用公开标识，名称或标识已被占用时不得无提示覆盖另一模型。
- **MODELADM-003**：已经能通过规范名或别名找到的型号，不应再次建立相同的正式型号。
- **MODELADM-004**：模型改名或公开标识变更时，旧名称或旧标识应能按历史别名规则继续指向对应模型。
- **MODELADM-005**：管理员能增加或移除模型别名；规范名本身不能按普通别名删除。
- **MODELADM-006**：管理员可以确认待确认型号、标记未证实信息、退役或恢复模型，记录状态变化与原因。
- **MODELADM-007**：模型状态变化应作用于发布候选、档案、题目比较及与模型对应的词表信息，不只改一个位置的显示文字。

### 24.2 合并与撤销

- **MODELADM-008**：管理员能预先查看把一个模型合入另一个模型的影响，包括涉及的作品、名称和归属。
- **MODELADM-009**：不能合并到自身、已退役的不适用目标或形成循环的归宿；已经合并的源应使用其有效归宿处理。
- **MODELADM-010**：确认合并后，源模型的适用作品和名称指向目标，重复作品关联不重复累计；历史归宿可追溯。
- **MODELADM-011**：合并应同步影响作品模型显示、模型统计、可用词表、查找及有关题目比较。
- **MODELADM-012**：管理员能查看可撤销的模型合并，并先查看撤销能够恢复哪些关系。
- **MODELADM-013**：撤销只依据当时实际迁移记录处理。合并后已经被再次归属到别处的作品不得被强行覆盖回去。
- **MODELADM-014**：旧合并缺少完整迁移依据时，要说明恢复不可靠的部分；可以仅恢复源模型业务状态，不能猜测作品原属后假称完整恢复。
- **MODELADM-015**：恢复后源模型状态、可选词表和有效归属应一致，并保留此次撤销记录。
- **MODELADM-016**：有作品引用的模型不能直接删除，需要使用适用的退役或合并业务；无引用的可删除模型也需按相关关系限制处理。

### 24.3 不确定作品的归属

- **ATTR-001**：管理员能够集中查看未标注、厂商未定型号和灰测未证实模型下的作品，包含原始声明依据和相关提示词、标题等信息。
- **ATTR-002**：平台可以提供可能的确切型号建议和其依据，但建议本身不直接改变正式作品归属。
- **ATTR-003**：管理员能选定一件或多件作品，确认其归于一个已确认且未退役的确切型号。
- **ATTR-004**：不能把待确认归属的目标设置成另一个未确定兜底类型，然后假称完成确切型号确认。
- **ATTR-005**：完成确认后移除适用的不确定归属、增加正确模型信息，同时保留作品的其他标签和已有相关资料。
- **ATTR-006**：随后作者编辑作品的其他信息时，不应把管理员已经确认的型号无故退回之前的未知型号。
- **ATTR-007**：确认结果应反映在模型档案、作品查询、题目比较、有关数量及管理记录中。
- **ATTR-008**：管理员能获知未证实池的规模、适用的等待时间或最近确认时间，长期未处理项可以形成提醒；无法确定的时间应如实未知。

## 25. 题目治理与提示词整理

- **TASKADM-001**：管理员能查询任何适用状态的题目，查看题名、说明、分类、关联作品及管理历史。
- **TASKADM-002**：管理员可以直接创建题目、修改信息、确认候选、隐藏或合并题目。
- **TASKADM-003**：新建题目可以同时关联指定作品；题目与作品应实际存在，非法对象不得被静默丢弃后声称全部成功。
- **TASKADM-004**：管理员可以给已有题目批量关联作品或解除作品关联，重复关联不重复计数。
- **TASKADM-005**：已经隐藏或合并的题目不能继续作为正常目标接收新作品挂载。
- **TASKADM-006**：管理员能在管理范围查看题目关联的待审或被拒绝作品，但这些管理资料不进入公开同题比较。
- **TASKADM-007**：题目合并应先展示受影响作品和重复关联，确认后迁移至有效目标并保留源题目的归宿。
- **TASKADM-008**：不能合并到自身、形成循环、重复合并已有源或使用不适用状态的目标。
- **TASKADM-009**：有作品关联、其他题目归宿引用或待处理建议引用的题目不能被无提示直接删除，应说明依赖情况。
- **TASKADM-010**：平台能够对已有提示词作品提供完全同句和相似内容两类整理候选，展示作品数量、涉及模型及判断依据。
- **TASKADM-011**：完全同句遵守提示词统一规则；相似判断仅表示可能相关，不能冒充严格同一题面。
- **TASKADM-012**：管理员可以查看候选作品及其已经归属的题目，再决定建立新题、关联已有题或不采用。
- **TASKADM-013**：确认新题时能维护题名、说明和分类，并把选定作品关联到该题；原始作品信息不因整理而被编造改写。
- **TASKADM-014**：已经完成正式归属的内容不应继续反复作为未处理候选呈现；重新整理的结果应反映最新关系。
- **TASKADM-015**：当前题目治理包含合并，模型合并的撤销能力不能自动被宣称为题目也支持同样撤销。

## 26. 候选收件箱与审批

- **INBOX-001**：管理员能集中查看新模型、别名、模型合并、新题目、作品挂题、题目合并和类型调整等支持的候选。
- **INBOX-002**：候选记录说明来源、产生时间、目标、建议内容、依据、适用可信程度、当前状态和关联作品。
- **INBOX-003**：来源可区分规则推导、用户申请及已有的其他来源，不把机器推断冒充人工确认。
- **INBOX-004**：能按候选类型、处理状态和适用可信程度查找候选；低可信候选可另行查看，不无差别挤占常规待办。
- **INBOX-005**：同一未处理候选的重复产生应去重，重复扫描或重复申请不能制造虚假的待办增长。
- **INBOX-006**：管理员能通过或拒绝一项支持的候选；通过后完成对应真实业务变化，拒绝后不产生该变化。
- **INBOX-007**：通过候选时目标对象可能已存在或已改变，需按当前有效资料判断，避免重复创建或覆盖后续治理决定。
- **INBOX-008**：对应业务执行失败时不能把候选标成已完成，也不能留下“正式对象已变、候选仍等待再次处理”的误导结果。
- **INBOX-009**：已经处理的候选不可再次当作未处理候选执行；无需变化应说明实际情况。
- **INBOX-010**：不支持执行的候选类型、缺少必要信息或目标失效应明确拒绝，不生成虚假的处理成功记录。
- **INBOX-011**：管理员能批量处理支持的候选，每项分别反馈成功、失败或已处理原因；一项失败不使其他已成功项被隐藏。
- **INBOX-012**：批量处理和单项处理遵守相同权限、关系限制、状态规则和留痕要求。
- **INBOX-013**：待办概况能按类型统计，数量与实际可查看的集合具有相同筛选口径；不能展示某类待办数量后却找不到对应记录。
- **INBOX-014**：候选预览或查看本身不改变正式业务数据，用户自报挑战不因高置信度文字而绕过审批。

## 27. 数据巡检、类型细分与冲突处理

- **CHECK-001**：管理员能查看内容质量与治理概况，包含信息覆盖、待确认积压和重复冲突，不以标签总数量替代业务质量。
- **CHECK-002**：能够发现缺少作品类型、具有多个类型、仍为宽泛类型但可细分、缺提示词、模型声明不确定、固定词表缺说明、零引用值及疑似重名模型等已有问题。
- **CHECK-003**：检查结果包含实际数量、适用比例、样例、问题含义和当前可处理范围。
- **CHECK-004**：一个作品可能同时属于多种问题，问题次数之和不能无说明地当作有问题作品的独立数量。
- **CHECK-005**：类型细分建议依据已有标题、简介、提示词和词表给出候选类型、可用判断依据及可信程度。
- **CHECK-006**：没有判断依据时应明确没有建议，不能强行给缺资料作品补出不存在的信息。
- **CHECK-007**：管理员可以先查看建议及影响，再决定将适用建议放入待审批集合。
- **CHECK-008**：当前可形成操作候选的巡检补救包括缺少类型和可收敛的多个类型；其他仅提示的检查项不能假装存在自动修复功能。
- **CHECK-009**：管理员批准类型调整后，只调整本次明确涉及的类型信息，保留其他类别标签和作品内容。
- **CHECK-010**：把宽泛占位类型调整为更明确类型时，应清理适用占位关系，不无必要地留成“占位 + 具体类型”的重复结果。
- **CHECK-011**：已经达到目标状态的作品再被处理时，要说明无需变化，不生成重复调整和虚假效果。
- **CHECK-012**：型号重名或近似写法冲突应能提供可能指向同一型号的对象组，管理员确认前不得自动合并。
- **CHECK-013**：管理员能从问题继续访问相关作品、词表、归属或候选，处理结果反映在后续巡检中。
- **CHECK-014**：长期未确认的灰测或未证实内容应能形成治理提醒，不能自动把等待时间长视为已确认或已错误。

## 28. 管理记录查询与操作追溯

### 28.1 业务记录管理

- **DATA-001**：管理员能够查看平台允许管理的业务记录类别、记录数量及各类允许的操作。
- **DATA-002**：记录可按有效文字搜索、已允许条件筛选、排序和分批查看；不合法查询应说明而非无提示查询其他类别。
- **DATA-003**：能识别一条记录对应的业务对象，以及它与作品、用户、模型、题目等对象的引用关系。
- **DATA-004**：只读记录应说明不能直接改写的原因，不提供会伪装成功的写入能力。
- **DATA-005**：允许维护的记录支持其实际具备的新增、修改或删除；某类仅支持一部分操作时需明确。
- **DATA-006**：记录维护仍遵守正常业务中的名称、值域、引用、权限和统计规则，不能成为绕过业务约束的入口。
- **DATA-007**：管理员可在执行前查看修改或删除的校验结果、涉及引用、可能删除或失去关联的对象及其他业务影响。
- **DATA-008**：预览不实际改变记录，确认执行和预览结果必须区分。
- **DATA-009**：修改不能无提示改变记录身份、制造不存在对象的关联，或把无变化的提交当成有效变更。
- **DATA-010**：支持范围内可批量修改或删除，逐项报告结果；批量执行也遵守各项记录限制。
- **DATA-011**：口令等敏感凭据不作为可公开或任意维护的业务记录内容展示。
- **DATA-012**：成功变更后，对应正常业务查询、汇总和管理记录一起体现变化。

### 28.2 管理留痕

- **AUDIT-001**：作品审核、角色状态变更、社区删除封禁、实体资料与状态变更、归属、合并和适用词表维护等管理动作可追溯。
- **AUDIT-002**：记录能够说明操作者、时间、目标、动作、原因及适用的变更前后信息。
- **AUDIT-003**：管理员能按对象类别、对象、人员、动作和时间范围查找历史记录并分批查看。
- **AUDIT-004**：同一对象能够查看其适用的管理历史，确认当前状态是怎样产生的。
- **AUDIT-005**：失败、预览、没有变化的操作不伪装为已经成功完成的业务变更。
- **AUDIT-006**：批量操作留痕对应实际逐项结果，不只记录一条含糊的“全部完成”。
- **AUDIT-007**：管理记录不能被普通用户修改，不能因为目标被改名或删除而被移到错误对象上。
- **AUDIT-008**：历史依据不足时，如实说明其无法支撑的恢复结论，不补造历史迁移信息。

## 29. 运营设置与作品资源管理

- **OPS-001**：管理员能查看并修改全局自动上架、匿名直接上架及站点已有的运营文案模式等设置。
- **OPS-002**：只修改选定设置时，其他未提交设置保持原有值；修改后刷新仍保留有效配置。
- **OPS-003**：业务设置影响适用的后续发布或展示，不应无说明地重写历史作品状态。
- **OPS-004**：不同运营文案模式可改变站点已有名称或说明表达，不改变作品归属、评分、权限和内容本身。
- **OPS-005**：站点能够提供基本可用状态供运行检查，能识别核心业务资料暂时不可访问的情况，不向公开访客披露账号或其他私有配置。
- **FILEADM-001**：管理员能查看作品资源规模、文件或封面数量、占用量及当前资源服务能力的状态。
- **FILEADM-002**：已启用额外文件副本能力时，可发起补齐缺失作品资源与封面的操作，或按管理规则重新同步全部适用内容。
- **FILEADM-003**：管理员能查看资源同步是否在进行、处理进度、成功和失败数量、最近错误及开始结束时间。
- **FILEADM-004**：已有同类同步任务在运行时，重复发起应说明实际状态，不无限制制造重复任务。
- **FILEADM-005**：资源补齐和同步不改变作品作者、题目或模型归属，不把同步成功冒充作品审核通过。
- **FILEADM-006**：资源同步或附加副本不可用时，应说明受影响的能力；已经可用的核心作品内容不得被无理由清空。
- **FILEADM-007**：资源管理与同步操作只对管理员开放，其状态和存储细节不混入普通公开介绍。
- **FILEADM-008**：文件缺失、错误格式和目标无法读取时应说明失败，不以空包或其他作品文件伪装正确资源。

## 30. 关联只读展示站与通用使用要求

### 30.1 独立展示范围

- **SHOW-001**：平台具备关联的只读作品展示站，展示管理员选定的作品集合，主站与展示站的公开内容范围分别明确。
- **SHOW-002**：同一作品可获准在主站、展示站或两者中展示，不能仅因作品在主站存在就自动进入展示站。
- **SHOW-003**：管理员能够维护展示授权和语言标记，撤销授权后展示站不能继续读取该作品主体或资源。
- **SHOW-004**：展示站只提供允许的作品浏览、详情、体验、下载和公开概况，不提供主站的账号登录、上传、论坛或管理业务。
- **SHOW-005**：展示站的列表、直接作品访问、文件、生成记录和公开统计均应遵守展示范围；不得从另一入口绕过策展限制。
- **SHOW-006**：展示站采用其独立公开署名与适用语言资料，不泄露不需要公开的主站作者内部关系或保留标签。
- **SHOW-007**：展示站不以主站社区或流量统计冒充自己的业务规模；没有该能力的指标应明确表示无该能力。
- **SHOW-008**：展示站的资料呈现不自动回写或覆盖主站原有作品信息。

### 30.2 通用可用性、内容与边界

- **USE-001**：桌面和移动设备能够完成适用的浏览、查找、登录、发布及退出体验流程。
- **USE-002**：平台支持已有中英文界面信息切换，用户提供的作品、提示词、记录和讨论不自动被冒充为人工翻译内容。
- **USE-003**：加载、空集合、对象不存在、没有权限、输入错误和操作失败应能区分，并允许合理继续或重试。
- **USE-004**：公开内容分享入口可再次访问；无效或失效入口不能显示成另一件不相关的内容。
- **USE-005**：依赖第三方的视频、外链或其他资源不可用时，不把它的失效伪装成本站核心业务已成功完成。
- **USE-006**：持续保存的作品、账号资料、关系、设置和有效业务结果，在正常刷新、重新使用或服务重新运行后应符合其保留规则。
- **USE-007**：不能仅在当前浏览状态暂存成功结果，却对外宣称已经长期保存。
- **USE-008**：作品内容、生成记录和社区正文属于不可信输入，展示与体验不得授予其本不具备的账号或管理权限。
- **USE-009**：文件接收需限制非法路径、危险的资源消耗和无效内容，不能让上传访问平台其他用户或其他业务私有资料。
- **USE-010**：外部地址和论坛链接只接受支持的公开访问协议，不接受借站点访问内网、回环或受限制目标的地址；受限域名可被拒绝。
- **USE-011**：频繁重复提交或访问可以受限，应说明限制、实际是否处理及适用的再次尝试条件。
- **USE-012**：关联动作失败、重复操作或同时发生时，最终身份、关系、状态、数量和已完成结果应能相互对照。
- **USE-013**：任何入口完成相同业务动作，应受同一业务规则约束，不能因换一个维护入口绕过引用限制或统计维护。
- **USE-014**：不提供当前尚未实现的自动生成原始作品、账号第三方授权、自动真实性证明或任意联机服务作为既有功能承诺。
- **USE-015**：本文件不规定性能架构或人工审美标准；具体响应门槛、视觉方案和外部评测规则另行确定，不从现有页面外观推导隐含要求。

## 31. 明确的计算规则与现有业务参数

### 31.1 作品榜单并列规则

以下规则从左到右确定优先顺序，最后仍并列时按较晚登记作品优先稳定排列。

| 榜单 | 优先顺序 |
|---|---|
| 平均分 | 平均分较高 → 有效评分人数较多 → 5 分票较多 |
| 5 分票 | 5 分票较多 → 平均分较高 |
| 1 分票 | 1 分票较多 → 平均分较低 |
| 净票 | 5 分票减 1 分票较多 → 有效评分人数较多 |
| 评分人数 | 有效评分人数较多 → 平均分较高 |
| 综合热度 | 浏览数 + 2 × 下载数 + 有效评分人数较高 |

- **CALC-001**：作品平均分由当前有效评分之和除以有效评分人数得出；无有效评分时没有实际均分。
- **CALC-002**：上述评分人数是有效评分主体数，不是访问人数、评论数或已核实自然人数。

### 31.2 模型社区分与题目统计

- **CALC-003**：模型原始作品均分是其已公开、已评分作品均分的等权平均；不能与按全部有效票加权的社区分混用。
- **CALC-004**：模型社区分为 `(S + m × C) ÷ (v + m)`，保留两位小数。其中 `v` 为该模型作品的有效票数，`S` 为这些有效评分的分数总和，`C` 为参与模型统计的公开已评分作品在各模型归属下按票数加权的整体均分，`m` 为各有评分模型有效票数的中位数且不小于 1。
- **CALC-005**：同一作品归于多个模型时，在其各有效模型归属中参与模型统计；单个模型内同一件作品不重复计入。整体基准使用同一归属统计口径。
- **CALC-006**：模型没有有效票时没有社区分；有社区分的模型优先于无分模型，显示分相同时票数较多者优先，其余按稳定登记顺序处理。
- **CALC-007**：模型样本等级为：0 票无样本，1–9 票低，10–49 票中，50 票及以上较高。
- **CALC-008**：同题各模型的平均社区评分是该题下已评分作品均分的等权平均；平均轮数、平均耗时只使用已填写的有效值。
- **CALC-009**：同题模型比较优先平均社区评分较高，再按作品较多和模型名称稳定处理；代表最佳作品按有效作品评分选取，不能拿另一题目的作品充数。
- **CALC-010**：同提示词判断只统一换行及首尾空白。题目下基准提示词按当前比较集合中的出现次数选择，同次数优先更早登记的提示词；正文相似不能替代严格相同。

### 31.3 文字、集合与资源参数

这些是当前接收规则、输入长度和业务保留范围的核对值。实际运行配置尚未逐项确认；正式使用不同参数时需明示，不能把不同上限混为同一规则。

| 项目 | 当前核对值或规则 |
|---|---|
| 用户名 | 3–32 个字符，字母、数字、下划线 |
| 注册或新密码 | 8–128 个字符 |
| 展示名 | 最长 64 个字符 |
| 用户简介 | 最长 500 个字符 |
| 收藏夹名称、说明 | 名称最长 60 个字符，说明最长 200 个字符 |
| 每账号收藏夹 | 最多 20 个，默认夹属于账号的收藏夹集合 |
| 每收藏夹作品 | 最多 500 件 |
| 本机浏览历史 | 最近 100 件不同作品 |
| 账号浏览历史 | 最近 200 件不同作品 |
| 论坛主题标题、正文 | 标题最长 200 个字符，正文最长 20000 个字符 |
| 回复正文 | 1–10000 个字符 |
| 举报理由 | 1–500 个字符 |
| 模型名称、厂商、说明 | 名称最长 128、厂商最长 64、说明最长 1000 个字符 |
| 题名、题目说明 | 题名最长 200、说明最长 5000 个字符 |
| 模型不确定性说明 | 最长 500 个字符 |
| 普通接收作品文件 | 最大 200 MiB |
| 压缩包累计解压量 | 最大 500 MiB |
| 压缩包有效成员数 | 最大 2000 个 |
| 压缩包异常资源膨胀 | 累计解压量达到 4 MiB 后，不接受超过 100 倍的累计解压/压缩体积比 |
| 接收封面图片 | 不接受超过 4000 万像素的解码规模 |
| 单次支持的批量记录维护 | 最多 200 项；各项反馈实际结果 |

1 MiB 为 1048576 字节。上述记录保留数不要求永久保存被裁剪的最旧历史；收藏夹上限不等于站点作品总数上限。

作品标题、标签类别和值、标签说明等其他文字限制，现有不同入口的执行范围存在差异，需按第 32 节统一后使用，不在这里猜测一个全站一致上限。

### 31.4 频率限制的现有口径

| 业务动作 | 当前限制 |
|---|---|
| 登录尝试 | 同一账号名或同一网络来源，5 分钟内最多 10 次 |
| 普通匿名上传 | 同一网络来源每小时最多 20 次；信任发布按其专门规则处理 |
| 新固定标签值申请 | 同一网络来源每小时最多 10 次 |
| 匿名评分 | 同一网络来源每小时全站最多 60 次，同一作品最多 10 次 |
| 发布主题 | 同账号或同网络来源，每小时最多 10 次 |
| 发布回复 | 同账号或同网络来源，每小时最多 30 次 |
| 提交举报 | 同账号或同网络来源，每小时最多 20 次 |
| 会话记录查询与读取 | 同一网络来源每小时最多 60 次，按现行记录读取动作计入 |

- **LIMIT-001**：频率限制和输入拒绝须说明动作是否实际完成，不能让用户误以为成功后再重复提交。
- **LIMIT-002**：需要再次尝试时，用户能够获知适用的限制信息；频率限制不等于永久删除账号或已经发布的作品。
- **LIMIT-003**：资源和文字限制是接收业务的一部分，不得因使用另一个发布或管理入口而被无提示绕过。

## 32. 尚需统一或确认的业务规则

以下事项已经具有相应业务功能，但现有入口、历史说明或可观察边界不足以支持一项无歧义的全站要求。未明确前，不把某一种处理方式当作隐含正确答案。

| 编号 | 需要明确的业务规则 | 已核对的事实 |
|---|---|---|
| OPEN-001 | 未上架及拒绝作品是否继续沿用主站的已知入口可读规则 | 当前主站实际功能按第 3 节区分公开目录与已知入口；只读展示站更严格。旧文档曾把这两类访问混同 |
| OPEN-002 | 词表计数、标签类别汇总和公开作品数量的具体统计口径 | 当前词表具体值按所有已有作品关联计数，类别汇总是各值关联数量之和，可能含未上架关联或同作品多个值；探索分类使用公开作品范围 |
| OPEN-003 | 候选及退役模型的额外可读范围 | 默认公开模型集合不含这些状态，但现有状态查询和已知模型入口仍可能读取；不能直接套用题目候选仅管理员可读的规则 |
| OPEN-004 | 作品删除后历史讨论、公告、旧版本和已发送通知的最终保留方式 | 当前删除清理有效作品与相关收藏、账号历史及作品关联；部分历史文字链接或独立旧版仍可保留，不能宣称会全部一起删除 |
| OPEN-005 | 公开收藏中未上架或被拒绝作品如何呈现 | 收藏夹隐私和作品已知入口可读不同；现有收藏查询并未仅限已上架作品，不能默认其等同公开作品目录 |
| OPEN-006 | 修改密码或退出后，其他已经有效登录的使用环境是否立即失效 | 已核对新登录使用新密码、退出当前使用环境；未把全体登录强制失效作为已明确全站承诺 |
| OPEN-007 | 匿名评分身份变为登录账号后，原评分是否归并 | 当前两种主体分别识别，未发现自动归并这一业务能力；不能把同一个设备默认为同一个已核实真人 |
| OPEN-008 | 审核中回复的通知送达时点及可读内容 | 当前回复提交可产生通知，通知不授予读取审核中正文的权限；是否统一延后到公开须明确 |
| OPEN-009 | 作品浏览、下载、站点访问等统计允许延迟多久，以及失败事件是否计入 | 当前有延迟统计，未把短时旧数视为业务失败；不能凭一次瞬时读取要求所有指标立即完成 |
| OPEN-010 | 文本搜索的特殊字符语义、字符计数方式，以及不同入口的标题/标签长度是否统一 | 当前各处文字接收规则并非全部一致；不能沿用其他评测文档的字面子串规则冒充现站完整行为 |
| OPEN-011 | 管理员自降级、最后一个管理员、管理员被停用或封禁的统一保护规则 | 论坛封禁明确保护管理员，但其他账号状态维护入口不完全采用同一限制；不存在可直接宣称的全站统一保护策略 |
| OPEN-012 | 相似题目和类型整理的可信程度门槛，以及是否允许自动批准 | 当前推荐与审批分开，常规规则建议由管理员确认；不要求复现某个特定相似算法或自动批准推测 |
| OPEN-013 | 历史已公开媒体、生成记录中的敏感内容和既有浏览副本如何回收或脱敏 | 当前具备作品访问范围与站点身份边界，未证明能够收回已被访问者保存的所有副本或自动处理一切日志秘密 |
