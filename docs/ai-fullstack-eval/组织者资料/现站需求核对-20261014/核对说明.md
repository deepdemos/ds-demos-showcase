# 全站业务需求核对说明（仅组织者使用）

日期：2026-10-14。

本目录包含源码名称和现站实现线索，不提供给被测模型。模型的需求输入使用 [DeepDemos-全站业务需求](../../DeepDemos-全站业务需求.md)；不要同时附带旧架构说明、原站业务源码或规定既有技术栈/接口的 P1 参赛需求。

## 本轮做了什么

1. 只读核对当前前端路由、页面动作、后端 21 个业务路由模块、相关业务服务、资料校验和现有专项文档。
2. 提取 177 个后端公开/管理动作作为覆盖检查索引；动作数量不是需求条目数量，也不证明所有动作已通过运行验收。
3. 对 12 个公开读取功能做低频只读抽查，均返回 HTTP 200：作品、模型、题目、标签、探索、论坛、作品榜、用户榜、赞助、致谢、公告和 astra 展示站概况。
4. 公开站点信息在本轮读取时返回 1153 件作品（web 1082、zip 23、link 48）、237 位作品作者、218 个主题。仅说明当时公开口径，不作为冻结数据规模。
5. 未登录管理端，未注册账号、上传、评分、审核或删除生产内容，未查询私有服务器配置或数据库，未执行现站测试或调用参赛模型。

公开功能声明的读取尝试没有取得真实后端文档，不能把首页回退内容当成完整功能声明。完整功能条目以代码阅读与业务核对为主，公开抽查作为辅助；不能宣称全站管理流程已经线上实测。

## 特别核对过的规则

- **公开目录不等于所有已知作品入口。** 当前主站的详情、预览、下载和会话日志使用展示范围判定，允许已知入口读取未上架内容；astra 另外要求已上架。需求第 3 节保留该差异，第 32 节标记最终策略核对。
- **自动上架开关的真实组合。** 登录上传看全局开关；普通匿名上传看全局开关或匿名开关；有效匿名信任通道直接放行。并非两个相互独立的注册/匿名开关。需求第 7 节列出可观察结果。
- **匿名署名不是账号作者。** 现站支持 guest_name，旧人类指南仍描述固定 public；需求区分匿名集合、署名和账号权限。
- **新评论不继续旧写入。** comments 的新建、删除返回 410，论坛是现行新讨论业务。需求不恢复已经停止的旧评论写功能。
- **同键 OR、跨键 AND。** 当前筛选已升级，不能沿用 README 的笼统“多标签 AND”或 P1 的单标签精简规则。
- **质量榜的时间范围筛作品创建时间。** 不是只统计窗口内评分；质量榜排除零评分，热度公式为浏览 + 2×下载 + 评分主体数。
- **模型社区分不是原始作品均分。** 有票数加权与样本收缩，零票无分；需求声明业务计算，未限定查询或存储实现。
- **题目链条区分同题、同句、未知。** 同题不自动表示提示词相同，缺失提示词不算一致；基准取当前比较集合内最多出现的提示词。
- **模型撤销合并有历史证据边界。** 没有迁移记录不能猜作品原属；后来已改走的关系不得被撤销覆盖。题目并没有同等完整撤销功能。
- **候选批准与执行是一项业务结果。** 执行失败不能留假完成；批量候选和批量记录维护逐项报告，不假称全部成功。
- **巡检不等于自动修复。** 当前可入候选的补救主要是缺 type 和可收敛多 type，其余需要人工判断；规则版标签/题目建议不被称为已接入外部 LLM。
- **历史两个保留范围。** 本机 100、账号 200；停记账号不清空既有历史，不自动停止本机记录。
- **未知长度、并列与范围不擅自统一。** 词表数量、模型非默认公开状态、删除后历史关系、其他登录环境失效等在第 32 节分开记录，避免默示验收。

## 文档边界

全量文档采用现有业务的需求化表达，未附技术栈、库表、接口、架构图、视觉或交互方案。需求条目中仍会出现 HTML、SVG、ZIP、Markdown、JSONL 和 DSH，因为它们是作品或生成记录的业务输入类型；不是后端架构选择。

初始管理身份、持久保存、输入保护、引用一致性等表达为业务结果，不规定实现办法。没有把比赛样本导入格式、压测、备份故障题、评分或用量预算伪装成原站已实现的业务功能。

本次仅新增需求与核对资料，既有业务代码和原始采集包不改动。
