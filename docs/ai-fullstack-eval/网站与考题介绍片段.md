# DeepDemos：网站与 AI 考题介绍片段

版本：v0.3（按单模型持续更新调整）  
日期：2026-10-07  
目标时长：约 2 分钟；时间轴按 120 秒设计，实际以试读和剪辑为准。  
当前交付：文案、分镜及录制清单。尚未生成配音、实际录屏或视频成片。

更新安排：用户按新模型发布逐期测试，每期围绕一个模型；先以 P1 建立固定考题，P2/P3 作为后续可选专题，另定预算。完整视频形态见[视频形态策划](./视频形态策划.md)。

## 1. 这个片段让观众知道什么

片段放在第一期测试视频开头。观众看完应能回答：

1. deepdemos.top 是什么，有哪些主要使用场景。
2. 访客、作者和管理员分别会做什么。
3. AI 要从零交付什么，本轮先考哪些任务。
4. 功能怎样验收，页面审美怎样呈现。

网站介绍展示原站主要能力；“本轮考题”单独说明预演范围。这样观众既有整体认识，也知道这一期具体检查哪些行为。

旁白采用创作者本人讲解的口吻，使用“我”和“我的 demo 站”。不逐条念完整功能清单，而是用实际操作说明功能。

## 2. 可直接试读的完整旁白

这是我的 demo 站，已经收录了上千件作品。这次，我想让不同 AI 从零实现这个网站。

先看访客怎么用。你可以浏览作品，搜索关键词，再按模型或类别筛选。找到感兴趣的作品，点进去，就能直接体验。

详情页里，除了作品本身，还能看到作者、提示词和生成记录。游戏要能操作，网页里的资源要能加载，这些都会成为测试的一部分。

再看作者这一边。登录以后，可以上传网页或者作品包，填写介绍和模型信息。发布之后还能更新作品，让其他访客看到新的内容。

社区里，用户可以收藏、评分和讨论。管理员则负责审核内容、处理举报。网站需要分清每个人能看什么、能改什么。

它还有模型库和题目库，可以把同一道题下，不同模型做出的作品放在一起比较。

这个系列每期测一个新模型，统一使用 dsh，让它从空工程开始。相同版本的考题使用相同需求和内容样本，模型要交付能运行的前端、后端，以及保存作品的数据和文件。

这一期先做作品库：让作品能被找到和运行，重启后内容还在。后续有预算，再做作者上传、更新和需求升级专题，看看已有工程能不能继续维护。

功能会用同一套测试验收，修复前后的结果都保留。页面设计和操作体验直接展示，大家可以自己比较。

这次的新模型能把这些流程真正跑通吗？我们开始。

## 4. 本期与后续专题的任务卡

以下文案与功能清单第 12 节对应。当前每期新模型先测 P1，P2/P3 另定专题与预算；不把三阶段当作每期必做。范围调整时同步更新旁白、字幕和任务卡。

### 第一题：可浏览的作品库

提供约 50 件代表性真实作品，AI 从空工程实现导入、列表、搜索、单标签筛选、最新排序、分页、详情和预览。

屏幕精简文字：

> 找得到作品，也能把它打开运行。

验收演示路径：导入样本 → 搜索 → 标签筛选 → 打开详情 → 在作品中完成一次操作。

### 第二题：作者发布与更新

加入注册登录，支持登录作者上传单 HTML 和网页 ZIP、填写基础信息、发布及更新。

屏幕精简文字：

> 作者发得出去，其他访客看得到，更新后能看到新内容。

验收演示路径：测试作者登录 → 上传 → 独立访客浏览器查看 → 作者更新 → 访客看到变化 → 按需求验证重启后的持久化。

### 第三题：追加需求与回归

将单标签筛选升级为同键 OR、跨键 AND 的组合筛选，同时检查此前交付的浏览、预览、登录和发布行为。

屏幕精简文字：

> 加一项需求，再检查原来的功能。

观众解释示例：同时选择两个模型，找到其中任一个模型的作品；再选择“游戏”类别，结果只保留这些模型做的游戏。

精确字段、标签和预期结果在 P1/P3 需求文档中统一规定，录屏使用已准备且可以核对的样例。

## 5. 录制前准备哪些素材

先准备一个录屏样例列表，把作品地址、关键词和标签填入下表。此处尚未选定或抓取具体作品。

| 素材 | 选择条件 | 待填信息 |
|---|---|---|
| 首页与作品库 | 内容足够丰富，标题和封面有可见差异 | 录制版本、日期、入口地址、实际作品数量 |
| 搜索与筛选样例 | 关键词和标签都能产生明确结果 | 关键词、标签、预期命中作品 |
| 交互作品 | 加载稳定，一次操作产生明显变化 | 作品地址、进入操作、退出方式 |
| 生成过程样例 | 作者、提示词、生成日志信息完整 | 作品地址、需要展开的位置 |
| 作者发布样例 | 小体积单 HTML 或网页 ZIP，能明显区分初版和更新版 | 测试文件名、封面、标题、初版/新版变化 |
| 社区操作 | 测试用户已有可演示的收藏/评分/关联论坛主题 | 作品、主题、测试身份 |
| 管理操作 | 测试副本有待审作品和待处理举报 | 测试对象、操作前后预期 |
| 模型/题目比较 | 至少两组归属正确、可打开的作品 | 题目、模型、关联作品 |
| DSH 与任务材料 | 可公开的空工作目录、任务封面；模型界面按实际准备情况使用 | DSH 版本、profile、镜头中可展示的配置 |

“上千件作品”依据用户提供的站点现状。录制时核对实际快照；如数量变化，统一修改旁白和字幕。

上传、更新、收藏、评分、举报和审核演示在独立测试副本中完成。当前脚本任务不授权自动操作生产站点。后台镜头使用可公开的测试对象，账号秘密和非公开数据不入画。

## 6. 每个镜头的录制提示

| 镜头 | 录制提示 |
|---|---|
| S01 | 优先用当前线上首页；数量来自录制时核对的内容快照。 |
| S02 | 提前挑选能得到明确结果的关键词和标签，避免临场翻找。 |
| S03 | 挑选加载快、操作反馈明显、生成记录完整的作品；版本记录可作为补充插镜。 |
| S04 | 使用提前准备的测试作品和账号，在独立副本操作；完整流程另录，主片只取关键动作和结果。 |
| S05 | 讨论使用当前论坛入口；后台仅展示可公开的测试对象和字段。 |
| S06 | 这部分依据当前仓库功能；录制前核对选定版本。尚未上线时使用明确标注的本地演示，或采用文档内的替代旁白。 |
| S07 | 展示筹备材料，不摆拍已经完成的比赛；模型名单和配置冻结后再填入具体信息。 |
| S08 | 这段明确首轮预演范围；前面展示的是原站功能，不能把全站介绍等同于本轮完整考卷。 |
| S09 | 实际结果未产生时使用流程示意并标注，不填虚构成绩；视口和任务在正式录制前统一。 |
| S10 | 预演结果有限，收尾不宣称全行业排名或已经得出结论。 |

基础建议：横屏 16:9，统一浏览器缩放和视口；每个素材保留操作前后各几秒，方便后期衔接。

先录完一条完整用户流程，再截取关键动作。上传等待时间可以剪短，原始完整素材保留，成功画面来自同一次实际操作。

鼠标停留和简短放大用于指明操作对象。重要结果留出阅读时间，避免页面刚变化就切走。

## 7. 怎样把开场变成后续比较的参照

介绍里演示的核心用户旅程，在评测实现中使用相同任务和等价内容重放：

| 开场动作 | 参赛实现中的对应检查 | 后续视频画面 |
|---|---|---|
| 搜索和筛选作品 | 按统一数据与预期结果查找 | 各实现执行同一查询，展示结果 |
| 打开并运行作品 | 相同运行样例完成规定操作 | 展示加载、操作和错误情况 |
| 作者发布作品 | 同一测试文件、基础信息与公开策略 | 上传结果及独立访客视角 |
| 更新作品资源 | 同样的初版/新版，检查内容变化 | 更新前后画面与刷新结果 |
| 增加组合筛选 | 追加相同需求，回放公开用例与旧功能 | 首次提交、修复后和回归结果 |

社区、后台、模型库等镜头介绍全站能力。本轮 P1–P3 尚未要求的行为不在这一轮计分；正式进入相应阶段时再展示验收结果。

原站录屏标注“原站演示”，参赛实现标注选手编号和阶段。相同视口、录屏任务与内容用于比较，审美展示保留人工判断。

## 8. 验收方式的观众用说明

主片中的短版：

> 功能会用同一套测试验收，修复前后的结果都保留。页面设计和操作体验直接展示，大家可以自己比较。

需要多解释一点时，使用补充版，作为后续片段插入，不计入 120 秒：

> 比如上传成功以后，我会换一个浏览器打开作品，再按需求重启服务，检查它是否还在。加完新功能，还会重走旧流程。每次交付用掉的时间、费用，以及我有没有帮忙，也会记录下来。

前端功能可以进入浏览器测试。字体、色彩、布局和整体审美通过真实画面、人工试玩及点评独立呈现。

开场不承诺已选模型、已冻结预算或已得到排名；实际规则在正式测试前公开。

## 9. 线上版本不一致时怎样调整

当前脚本参考功能清单与仓库调查，尚未在录制环境逐项验证。录制前核对本片实际展示的功能。

| 情况 | 旁白与镜头处理 |
|---|---|
| 模型库/题目比较只在本地版本可用 | 使用明确标注的本地演示；若不展示，S06 改为“后续还会加入模型库和题目比较，让不同模型的作品能在同一道题下对照。”并用“后续评测方向”文字卡 |
| 某作品没有生成记录 | 换用记录完整的已验证作品，不填造记录 |
| 暂时没有可公开的后台素材 | 先用“作者—访客—管理员”角色图解释审核与举报；后续用真实测试副本镜头替换 |
| DSH 和任务环境还未配置 | S07 用统一条件文字卡；实际运行界面在环境准备完成后补录 |
| 预演题目发生调整 | 同步修改 S08、三张任务卡和对应需求；保留脚本版本 |

替代旁白也需要试读，时间轴可小幅调整。现场与本地使用不同版本时，镜头标注演示环境，避免让观众误解为同一部署。

## 10. 第一轮制作顺序

1. 先试读完整旁白，确认自然语速与叙述顺序。
2. 核对本片所需页面，填写素材样例表。
3. 准备独立测试账号和发布/审核样例，录制完整操作。
4. 按分镜选镜头，加入任务卡和重点字幕。
5. 核对旁白、实际画面和本轮需求是否一致，再制作最终配音和剪辑。

此阶段先形成可审阅脚本。网站业务代码、参赛工程和实际测试继续按项目规划推进。
