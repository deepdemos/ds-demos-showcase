# 浏览历史设计

> 状态：**账号侧后端已落地（2026-11-18）**；本机侧与账号侧的页面合并、开关界面还没接。
> 需求：[项目需求](项目需求.md) §15（HIST-001 – HIST-012）；设置键：[设置域设计](设置域设计.md) §4。
> 表结构见 [0033_account_view_history.sql](../db/migrations/0033_account_view_history.sql)（本文不复制 DDL）。

## 1. 两个来源，不是一个

HIST-002 要求用户能分辨一条记录来自哪里。所以历史天然有两半：

| 来源 | 存在哪 | 谁能看 | 上限 | 关掉之后 |
|---|---|---|---|---|
| 本机 | 浏览器 `localStorage` | 这台浏览器 | 前端偏好，默认 100（HIST-006） | 清掉即可，没有服务端记录 |
| 账号 | `account_view_history` | 只有本人（HIST-010） | `history.max_entries_account`，默认 200 | 只停新增，不删旧（HIST-008） |

**合并展示**是前端的事：按 slug 去重、取较近的一次、每行标来源。两份来源的
上限互不影响——账号上限是运营参数，本机上限是个人偏好，后端从不读后者。

## 2. 账号历史的写入

写入口挂在 `POST /api/v1/demos/{slug}/view` 上，与浏览计数同一时刻发生。
不为它单开端点：详情页已经为统计发过一次请求，再发一次只会多一个失败点。

判定顺序（见 `backend/internal/httpapi/history.go` 的 `recordAccountView`）：

1. 有没有登录？匿名浏览不写账号历史，计数照旧。
2. `history.record` 是不是 true？缺行读 `setting_keys.default_value`（默认 true），
   连注册表都缺行才兜 true。
3. 软删 / 擦除的作品不写——它们打不开，也不该占历史。
4. 同一个账号同一件作品只有一行：重复浏览是 `UPDATE viewed_at`，不是新行。
5. 写完按 `history.max_entries_account` 裁剪，只留最近 N 条。

任何一步失败都只记日志：历史是附加信息，记不下不该让一次浏览报错。

## 3. 账号历史的读与清

| 端点 | 做什么 | 关键判据 |
|---|---|---|
| `GET /api/v1/me/history` | 分页读自己的历史 | 未登录 401；只回自己的；软删 / 擦除不出现在结果里 |
| `DELETE /api/v1/me/history` | 清空自己的历史 | 幂等：没有记录也 204 |
| `PUT /api/v1/me/history/settings` | 开关 `history.record` | 只写本人；缺 `enabled` 回 400（不能把「没传」当关闭） |

「关闭并清空」是**两个动作的组合**：先 `PUT enabled=false`，再 `DELETE`。界面上
必须先说明会删掉已有记录再执行（HIST-009）。把两件事塞进一个开关，用户点「关」时
不会预期历史消失。

## 4. 为什么关掉不清

HIST-008 的原文是「只停新增、不删旧」。清空是一次不可逆操作，需要独立的确认；
关闭是隐私偏好，今天的决定不该替用户处理昨天的数据。

## 5. 不做 / 边界

- 不做他人历史：HIST-010，任何端点都不接受目标账号。
- 不做单条删除：需求只要求清空；单条删除要额外的确认与墓碑口径。
- 不做公开历史页：本机与账号历史都只对本人可见。
- 页面合并与开关界面：下一轮做；当前 `/me/history` 仍只读本机。

## 6. 与其它判据的关系

- 可见性：历史条目只过滤「软删 / 擦除」，不沿用 `demo_public_demos`——历史是
  本人看过什么，不是「现在公开什么」。作者看自己的草稿也会进历史（只有本人可见）。
- 隐私：`user_preferences` 的 `history.record` 不落审计（设置域 D9：隐私选择不该
  变成可追溯的操作记录）。
