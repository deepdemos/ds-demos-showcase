# ADR：本仓库的决策记录

## 约定

- **一个域一份文件**：`docs/adr/<域>.md`。不按「一份 ADR 一个文件」切——那是为几百条决策的仓库准备的；这里一共约一百条，按域分文件后总共不到十份，读得完。
- **编号沿用 `G`**：`G1`–`G22` 是历史台账里的跨域决策，迁入后编号不变；新决策从 `G23` 起。外部文档里已有的 `G7` 之类引用继续有效。
- **每条固定字段**：状态 / 证据 / 决策 / 为什么 / 放弃了什么 / 影响面 / 回退。缺任何一项就是没写完。
- **状态只有四个值**：`proposed`（待拍板）/ `accepted`（已生效）/ `superseded`（被后续决策取代，必须写取代者）/ `deprecated`（不再成立，保留原因）。
- **证据必须指向实物**：表 / 列在 `db/schema/*.sql` 或 `db/migrations/*.sql`；端点在 `api/openapi.yaml`；实现在 `backend/`；契约字段在 `components.schemas`。**指不到实物的决策，状态最多是 `proposed`。**
- **ADR 不写实现细节**：字段语义、状态机、理由；DDL 与契约原文不抄（`scripts/check-schema.mjs` 会拦）。

## 为什么编号不重来

`G` 号在 15 份文档里被引用 600–700 处。换成 `ADR-0007` 会让这些引用全部悬空，而引用方不会知道自己是悬空的——这正是 `docs/已知松点.md` 说的「门禁只证明符号还在，不证明语义还对」那类问题。

**保编号是本仓库对通用 ADR 格式的有理由偏离。**
