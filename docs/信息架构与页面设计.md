# 信息架构与页面设计

> 这份文件回答两个问题：**站点有哪些页面、它们从哪来、下一步去哪**；以及**新增/修改页面时必须遵守哪些结构规则**。
> 它不定义颜色、字体、品牌、动效——视觉设计由视觉负责人决定。

## 1. 唯一事实源

前端路由登记在 web/src/app/routes.ts：

- id：稳定标识，不随文案变化；路由元素在 web/src/app/route-elements.tsx 里按 id 对应。
- path：浏览器地址；404 用 *。
- title / description：浏览器标签页与页面抬头；不含站名。
- group：public / me / admin / auth / system；决定套哪套外壳。
- access：public / auth / permission（anyOf 权限键）；只做入口可见性与前端守卫，服务端仍是唯一判定。
- width：auth / form / narrow / default / wide；页面不再自己写 max-w-*。
- availability：ready / fixture；fixture 只允许在 DEV 注册。

web/src/app/router.tsx 只从清单生成路由，不再手写 path 与页面 import。新增页面时漏登记、漏元素、导航指向不存在的路由，web/src/app/routes.test.tsx 会红。

## 3. 导航模型

- 一级入口：作品库 / 探索 / 排行榜 / 社区讨论（外链）/ 投稿。搜索是顶栏工具，不占入口。
- 个人区：我的作品 / 收藏夹 / 浏览历史 / 通知 / 资料设置 / 偏好设置；/me 落 /me/demos。
- 管理区：收件箱 / 审核 / 申诉 / 模型 / 账号 / 审计 / 参数 / 公告 / 词表 / 精选；/admin 落 /admin/inbox；按权限键过滤。
- 认证页不套主导航；登录后回 return_to。
- 当前区用 aria-current 标出；导航不换行；小于 1024 收进菜单。

## 5. 页面结构规则

### 5.1 宽度

| 档位 | 最大宽度 | 用在哪 |
|---|---|---|
| auth | 384px | 登录/注册/验证/重置 |
| form | 672px | 投稿/编辑/资料/偏好/设置 |
| narrow | 768px | 收藏/历史/通知/排行/作者/规范 |
| default | 896px | 作品详情/模型详情 |
| wide | 1152px | 作品库/分类/管理表格/搜索 |

页面只声明 width，不再写 max-w-* 与 px-4 py-8；留白由 Page 壳统一。移动端左右 16px，平板 24px，桌面 32px。

### 5.2 页面抬头

每个页面必须有：h1、一句说明（可空）、一个主 CTA（列表/详情/表单各有口径）。操作在主 CTA 右侧；移动端落到标题下方。不要用营销文案，写清这一页能做什么。

### 5.3 状态

- loading：Skeleton 跟页面骨架走，不用整页 spinner。
- empty：说清为什么空、下一步做什么；筛选后空与确实没数据分开。
- error：中文原因 + 重试；不显示 JSON.parse、SQL、路径、原始 message。
- forbidden：留在壳内的 403 说明，不静默跳首页。
- not-available：生产访问 fixture 页面时说明“尚未接入”，给返回入口。
- auth-required：未登录跳 /login 并带 return_to。

### 5.4 表单

标签、说明、错误与控件成组；控件默认全宽；主按钮 primary；提交中禁用；服务端错误贴操作区；离开未保存表单要确认。分类选择器按维度折叠 + 搜索 + 已选摘要，不平铺全部词条。

### 5.5 列表与表格

筛选、排序、分页状态进 URL；列表卡至少给标题、作者、类型与一个能比较的指标；表格在窄屏转卡片或横向滚动容器；分页在移动端只留上一页/下一页。

## 6. 加页面的顺序

1. 在 web/src/app/routes.ts 加一行（id/path/title/group/access/width/availability）。
2. 在 web/src/app/route-elements.tsx 加元素。
3. 如果该页进导航，更新导航派生与权限。
4. 写页面：Page + PageHeader + PageSection；状态齐全；错误走翻译层。
5. 测试：页面三态、导航/守卫（如适用）；路由清单测试自动覆盖登记。
6. 同 PR 更新本文档的表格与 Dev Room（如果新增控件）。
7. 跑 typecheck、test、check:ui、file-size。

## 7. 边界

- 本文档只管结构/交互/文案口径，不管视觉。
- 产品页不使用暗色变体；主题演示只在 Dev Room。
- 新控件必须先进入控件库与 Dev Room，页面不得直接 import Ring UI。
- fixture 页面不得出现在生产构建；端点落地后先改 availability，再替换数据层。
