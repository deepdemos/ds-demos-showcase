# 基准来源（上游榜单速查页）

> 页面 `/benchmarks/sources`（#568 落地，#569 补规格）。代码在 `web/src/routes/BenchmarkSourcesPage.tsx`，内容在 `web/src/content/benchmark-sources.json`。
> 本文写页面规格、字段语义与维护规则，**不复制那 13 行数据**，也不复制分类枚举与档位中文文案 —— 它们各有唯一出处，抄一份就多一份会漂的事实。
> 词表见 [`GLOSSARY.md`](../GLOSSARY.md)「模型与基准」；站内已收录的基准另见 [`模型域设计.md`](./模型域设计.md) §5.6「基准的陈列口径」。

## 1. 是什么

站外主流评测榜的速查页：一张表回答「这些榜是什么、怎么防污染、跑在什么环境、指标与成本、多久更新、我们收不收」，**不回答「谁最强」**——跨榜不比较、不合成，也不给总分。

- 路由 `/benchmarks/sources`，公开可读，`availability: 'ready'`；不进一级导航，入口是 `/benchmarks` 目录页标题旁的「基准来源」链接。
- 与目录页的分工：目录页（`/benchmarks`）读 API，列**我们收录的基准**（五列）；来源页读静态 JSON，列**上游榜单**（含未收录、停更、只有外链的）。
- 两页不共享数据：同一张榜可能同时出现在两页，口径各自成立（见 §6「与 benchmarks 的关系」）。

## 2. 数据

**唯一事实源**：`web/src/content/benchmark-sources.json`；类型与分组逻辑在 `web/src/content/benchmark-sources.ts`。

| 顶层字段 | 内容 |
|---|---|
| `version` / `updatedAt` | 内容版本与全表最后核实日期；页脚渲染 `updatedAt` |
| `title` / `intro` | 页面标题与开场一句 |
| `columns[]` | 六列的解释文案（列级，全表共用）；页面「每列在说什么」一节直接渲染 |
| `tierLegend[]` | 四档的说明（`value` 只做枚举键；档位名在 `benchmark-tier.ts`，不在这里写第二遍） |
| `sources[]` | 上游榜单，当前 13 行（行数不是契约，加减行不算改页面结构） |

六列以 JSON 的 `columns[].label` 为准，顺序即页面顺序：

| 列 | 语义 |
|---|---|
| 评测名称与链接 | 榜名、发布方、官方榜地址；行级备注也挂在这一列 |
| 核心能力象限 | 这张榜主要测什么能力，多值；取值见 §6 |
| 防污染机制 | 上游怎么防止「模型在训练里见过题」；字段 `contamination` |
| 执行环境（Harness） | 跑分时套在模型外面的那层东西；字段 `harness` |
| 核心指标与效费比 | 主指标与源方公布的成本口径；字段 `metricCost` |
| 更新频率与维护方 | 多久更新、谁维护、最后核实；字段 `cadence` |

页面上的表头是短名（评测 / 能力象限 / 防污染 / Harness / 指标与效费比 / 更新与维护 / 档位），完整解释在「每列在说什么」一节读 `columns[]`；短名只是空间取舍，术语以 JSON 的列名为准。

`sources[]` 的一行：

| 字段 | 说明 |
|---|---|
| `id` | 行标识，全表唯一 |
| `name` / `publisher` | 榜名与发布方（`publisher` 是发布方，不一定是维护方） |
| `url` | 官方榜单地址；榜名链到它 |
| `benchmarkSlug` | 与站内 `benchmarks.slug` 对应的预留键；**当前页面不读它**（§6） |
| `displayTier` | 静态收录档位；取值与含义见 §3 |
| `categories` | 核心能力象限，多值；取值沿用 `benchmarks.category`（§6 有指针） |
| `contamination` / `harness` / `metricCost` / `cadence` | 四列正文，语义见上表 |
| `verifiedAt` | 这一行最后一次核实的日期；页面目前只渲染全表 `updatedAt`，行级日期留给维护与将来的展示 |
| `notes[]` | 行级备注，渲染在榜名下方，前缀 `※` |

四列正文的口径（术语定义见 `GLOSSARY.md`）：

| 列 | 写什么 | 不写什么 |
|---|---|---|
| 防污染机制 | 上游为「模型是否在训练里见过题」做的安排：私有题集、滚动换题、答案键封存、运行期断网等 | 没有就写「无」，**不推断**；可解性人审不是污染防护，别写成防护 |
| 执行环境（Harness） | 跑分时包在模型外面的那层：厂商 CLI、官方容器、浏览器 agent、模拟用户等 | 不写成「框架 / 脚手架」——脚手架常指代码结构 |
| 核心指标与效费比 | 主指标 + 源方公布的成本口径，单位照抄上游 | 缺失写「未公布」；**不换算、不估算**，不造「成本分」 |
| 更新频率与维护方 | 多久更新、谁在维护、最后一次核实 | 没有书面频率就写「没有书面频率」，不写成日更；维护方与发布方不是一回事时分清楚 |

## 3. 档位

档位说的是「这张榜我们怎么陈列」，不是「这张榜好不好」。取值只有四个，出处分两处：

- 库内三档（`table` / `cite` / `link`）：CHECK 在 `db/migrations/0040_benchmark_import.sql`，契约枚举在 `api/openapi.yaml`；
- 来源表多一档 `none`：**只在来源表里留档**（停更或授权不足），库里的 `display_tier` 没有这一档。

| 档位值 | 含义 |
|---|---|
| `table` | 分数可以写进 `benchmark_scores`，站内展示原始分与名次 |
| `cite` | 不入库；只给带署名的引用与官方榜外链 |
| `link` | 只有名称、一句话介绍与官方链接 |
| `none` | 不收录：停更或授权不足，只在来源表里留档 |

对外中文文案只写在 `web/src/content/benchmark-tier.ts` 的 `tierLabel`：目录页、详情页、来源页读同一份，本文不复述，避免第三份文案。四档各自的说明句在 JSON 的 `tierLegend[].explain`，页面「档位」一节逐条渲染。

## 4. 渲染规则

| 项 | 规则 |
|---|---|
| 分组 | 按 `categories` 里**第一个**能识别的值分组；识别顺序与组标题见 `web/src/content/benchmark-sources.ts` 的 `categoryOrder` / `categoryLabel`，识别不出落 `other` |
| 组序 | 同上；没有成员的组不渲染 |
| 组内排序 | 按名称升序（`localeCompare(…, 'zh-CN')`） |
| 分页 | 不分页：一行一榜，一次列完 |
| 空值 | 成本缺失一律「未公布」（页面有 `metricCost \|\| '未公布'` 兜底）；其余列在内容里写清「无」或「未公布」，不写 `—` |
| 未核内容 | 内部证据标记（`[A]` / `[B]` / 未核）**不上对外页**，内容里也不出现 |
| 行级备注 | `notes[]` 逐条渲染在榜名下方，前缀 `※` |
| 档位 | 徽标显示 `tierLabel[displayTier]`；页首「档位」一节逐档解释 |
| 链接 | 榜名链到 `url`，`target="_blank"` + `rel="noreferrer noopener"` |
| 表头 | 真 `<table>`，列头是 `<th scope="col">`；缺 `scope` 读屏对不上列 |

「缺值写 `—`」是站内基准页（[`模型域设计.md`](./模型域设计.md) §5.6「基准的陈列口径」）的口径，不适用于本页：本页讲的是**上游公布没公布**，所以写「未公布」；两个词各管一页，不要互换。

## 5. 文案

- 六列各一句解释，写在 JSON 的 `columns[]`；改文案改 JSON、走 PR。
- 页脚一句：数据最后核实日期；成本缺失写「未公布」，不换算、不估算。
- 不出现「即将上线」「综合分」「总分」；本页不排名、不给分。
- 全中文；功能性提示为准，不代写营销文案。

## 6. 与 `benchmarks` 的关系（未决）

- **现状**：来源页只读静态 JSON，**不查库**；`benchmarkSlug` 只是预留映射键，页面不读它。所以同一张榜可以「来源表写有分数、库里没有收录」，两页各说各的，互不校验。
- **未决（会影响对外行为）**：档位以谁为准。设计草案（#568 的 Q15）写「`benchmarkSlug` 命中 `benchmarks` 时以库中 `display_tier` 为准」，但实现没有接库，也没有测试。两条路：接库（多一次查询或构建期注入），或删掉这句草案、把静态值定为唯一口径。本票**不改行为**，等实现票拍板；在那之前，任何「库里的档位会覆盖来源表」的说法都不成立。
- **分类枚举不在本页定义**：`categories` 的取值与固定顺序见 [`模型域设计.md`](./模型域设计.md) §3.7「第三方基准（4 张表）」的 `benchmarks.category`。本页与 JSON 只允许出现该枚举里的值，多值按固定顺序序列化；要加值先改那里，不要在本页或内容文件里新造。
- **是否把 13 行搬进库**：不在本票范围。来源页是「业界有哪些榜」的速查，不是入库清单。

## 7. 维护与校验

- 新增一行：在 `sources[]` 追加对象，填全字段与 `verifiedAt`；`updatedAt` 取全表最近一次。
- 更新一行：改字段 + 更新 `verifiedAt`；不要只改 `cadence` 里的日期而漏改字段。
- 停更 / 授权变化：把 `displayTier` 改成 `none` 并在 `notes[]` 写原因，不删行——删了就看不出「为什么没有这张榜」。
- 校验（**建议，尚未进 CI**）：`id` 唯一、`url` 必填、`displayTier` 在四档内、`categories` 在 7 值内、`verifiedAt` 可解析成日期。
  现在只有两道兜底：`BenchmarkSourcesPage.test.tsx` 断言「每行的档位都在 `tierLegend` 里」「每行都能在页面上找到」；`scripts/check-single-source.mjs` 只守档位文案的唯一出处。缺口记在 [`已知松点.md`](./已知松点.md) §71「来源表内容没有校验门禁」。
