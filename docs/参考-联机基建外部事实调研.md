# 中文 UGC 站点「静态 Demo 多人联机」外部事实调研

> 仅外部事实与引用，不含架构建议；查不到的明确标注。

## 1. WebRTC 不打 TURN 的直连成功率

- appear.in（2017，千万级通话记录）：**已连通通话中 17.7% 最终走 TURN 中继**（TURN/UDP 12.1%、TURN/TCP 5%、TURN/TLS 0.5%），走 SFU 的仅 4%；整体失败率约 0.5%。即"约 1/5 的成功连接离不开 TURN"。[medium.com/the-making-of-appear-in](https://medium.com/the-making-of-appear-in/what-kind-of-turn-server-is-being-used-d67dbfc2ff5d)
- TokBox/OpenTok（2016，10 万通话）：ICE 失败 **2.0%（1541 例）**，真正连接失败 **0.2%（192 例）**；147 例是浏览器取不到 TURN 候选（企业代理需授权）。[webrtchacks.com](https://webrtchacks.com/really-12-percent-webrtc-calls-fail/)
- 根因在网络侧：CGNAT 覆盖 **17–18% 的 eyeball AS**，蜂窝网络 AS **>90% 部署 CGN**（Richter et al., IMC 2016）。[ar5iv](https://ar5iv.labs.arxiv.org/html/1605.05606)
- 更早的 NAT Check（USENIX 2005，n=380 自愿样本）：UDP 打洞可支持 **82%**、TCP **64%**；hairpin UDP 仅 24%（样本自选，偏乐观）。[usenix.org](https://static.usenix.org/events/usenix05/tech/general/full_papers/ford/ford_html/)
- 中国大陆运营商网络的 STUN-only 成功率：**未找到可靠来源**。

## 2. Cloudflare 橙云与实时通信

- WebSocket：**所有套餐都支持**（Network 中开关）；官方只写"无数据双向传输一段时间后关闭"，**未公布秒数**，自定义空闲超时仅 Enterprise 可联系客户团队；第三方一致口径为 **100 秒空闲**（非官方数字）。[network/websockets](https://developers.cloudflare.com/network/websockets/) ｜ [websocket.org](https://websocket.org/guides/infrastructure/cloudflare/)
- 橙云仅代理 **A/AAAA/CNAME 的 HTTP/HTTPS**，端口只含 80/8080/8880/2052/2082/2086/2095 与 443/2053/2083/2087/2096/8443；**非 HTTP 服务官方建议改灰云**，要代理其他端口（含 UDP）只能上 Spectrum，**全端口 UDP 仅 Enterprise**。→ **coturn 的 3478/udp 与 49152-65535/udp 无法透过橙云**。[network-ports](https://developers.cloudflare.com/fundamentals/reference/network-ports/) ｜ [proxy-status](https://developers.cloudflare.com/dns/proxy-status/)
- 官方限制清单：客户端↔CF keep-alive / HTTP2 idle **400s**；CF↔源站建连 **19s**、ACK **90s**、Proxy Idle **900s**、Proxy Read **125s**（524，Enterprise 可调）、Proxy Write **30s**；URL **16KB**、请求头 **128KB**、响应头 **128KB**。WebSocket 只算 1 个请求，带宽只计 CF→客户端。[connection-limits](https://developers.cloudflare.com/fundamentals/reference/connection-limits/)
- Cloudflare Realtime TURN：`turn.cloudflare.com` 支持 **3478/udp、3478/tcp、5349/tcp(TLS)、443/tcp** 与 **TURN REST API**，**不支持 DTLS / RFC 6062 / RFC 6156**；与 SFU 同用免费，否则 **$0.05/实时 GB**，SFU+TURN **共享 1000 GB 免费额度**；单 allocation 限新 IP >5/s、5–10 kpps、50–100 Mbps；**不含 Cloudflare 中国网络**；**不需要企业计划**。[turn](https://developers.cloudflare.com/realtime/turn/) ｜ [pricing](https://developers.cloudflare.com/realtime/sfu/pricing/) ｜ [rfc-matrix](https://developers.cloudflare.com/realtime/turn/rfc-matrix/)

## 3. 自建 coturn 的运维与滥用防护

- 官方 flag：`--use-auth-secret`（TURN REST API：`username="timestamp:user"`，`password=base64(hmac-sha1(secret, username))`）+ `--static-auth-secret`；配额 `-q/--user-quota`、`-Q/--total-quota`、`-s/--max-bps`、`-B/--bps-capacity`；relay 端口默认 **49152–65535**。[README.turnserver](https://github.com/coturn/coturn/blob/master/README.turnserver)
- 资源量级：官方称单机可承载"数千到数万条常规流量会话"，瓶颈在 NIC/RSS、ulimit 文件描述符、内核 UDP hash；`--multiplex-peer` 专为解除 relay 端口范围造成的 **~16k allocation 上限**而设。[coturn wiki](https://github.com/coturn/coturn/wiki/TURN-Performance-and-Load-Balance)
- 所有配额**默认 0＝无限制**；Enable Security 的最小推荐为 `user-quota=100`、`total-quota=10000`、`max-allocate-lifetime=3600`，并警告 **total-quota/bps-capacity 是全局的，攻击者可用有效凭证耗尽全局配额（486）**，凭证 API 不设防时可批量造用户名绕过 user-quota。[enablesecurity.com](https://www.enablesecurity.com/blog/coturn-security-configuration-guide/)
- 真实滥用案例：Enable Security 公开的 **Slack TURN 服务器滥用（$3,500 赏金）**；Zoom 曾用 `allowed-peer-ip` 白名单封堵"经其 TURN 做 C2 通信"；TURN 可被用于约 **4× 放大的反射攻击**。[Slack 案例](https://www.enablesecurity.com/blog/slack-webrtc-turn-compromise-and-bug-bounty/) ｜ [威胁分析](https://www.enablesecurity.com/blog/turn-server-security-threats/)
- 防护清单：`lt-cred-mech`+`use-auth-secret`、全量 `denied-peer-ip`（含 `::ffff:0.0.0.0-::ffff:255.255.255.255` 防 CVE-2026-27624）、`no-rfc5780`、`no-tcp-relay`、`no-cli`、`unauthorized-ratelimit`（4.14+，默认 10 rps/源 IP）、`proc-user`；**绝不用 `no-auth`**；必须保持最新版（web-admin 曾有"任何错误密码都能登录"的认证绕过，约 2019→4.9.0 才修）。

## 6. 浏览器平台约束

- **`sandbox="allow-scripts"`（不透明源）iframe**：`RTCPeerConnection` 与 DataChannel **不受 Permissions Policy 管辖**，规范层面未禁用；`getUserMedia` 受 `microphone`/`camera` 指令管辖，其 **default allowlist = `self`**，被拦截时抛 `NotAllowedError`；跨源 iframe 必须由父页 `<iframe allow="microphone; camera">` 委托，`allow` 只是在响应头策略上的**进一步收紧**。→ **P2P/DataChannel 可用，麦克风/摄像头必须显式委托**；不透明源场景**规范无明文裁决**。[MDN microphone](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Permissions-Policy/microphone) ｜ [MDN iframe](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)
- **BroadcastChannel**：官方定义为"同一 origin **且同一 storage partition**"的浏览上下文之间通信；不透明源与父页既不同源、也不共享 storage partition → **不能用于"父页 ↔ sandbox demo"的同机多标签联机**。[MDN](https://developer.mozilla.org/en-US/docs/Web/API/Broadcast_Channel_API)
- **DataChannel 消息尺寸**：`maxMessageSize` 在 `pc.sctp`（RTCSctpTransport）而非 DataChannel 上，2023-05 起 Baseline 可用；SDP 缺 `max-message-size` 时按 **64 KB** 处理，0 表示不限；多数现代浏览器可发 **≥256 KB** 单条，但无 RFC 8260 交织时大消息会队头阻塞。[MDN](https://developer.mozilla.org/en-US/docs/Web/API/RTCSctpTransport/maxMessageSize) ｜ [Using data channels](https://developer.mozilla.org/en-US/docs/Web/API/WebRTC_API/Using_data_channels)
- 社区实测（lgrahl 读源码）：Chromium 超 **256 KiB** 会因 EMSGSIZE 直接关通道；Firefox 57 前 FF→Chrome 有序可靠通道上限仅 **16 KiB**，建议 chunk **16384 B**。[lgrahl.de](https://lgrahl.de/articles/demystifying-webrtc-dc-size-limit.html)
- 背压与可靠性：`bufferedAmountLowThreshold` **默认 0**、**规范无推荐阈值**；`ordered` 默认 true、`maxRetransmits` 默认 null，即"可靠有序"是默认，unreliable/unordered 必须显式声明。单 PC 理论上限 65,534 条 channel。实际吞吐上限数值 **未找到可靠来源**。[MDN](https://developer.mozilla.org/en-US/docs/Web/API/RTCDataChannel/bufferedAmountLowThreshold)

## 7. 同类平台怎么做

- **itch.io**：HTML5 以 iframe 嵌入，资源托管在"HTML CDN 子目录"，仅要求外域请求必须 HTTPS；ZIP ≤1000 文件、解压 ≤500 MB、单文件 ≤200 MB；**官方文档完全没有联机/信令设施**。[itch.io/docs/creators/html5](https://itch.io/docs/creators/html5)
- **Poki**：唯一官方支持 P2P 的——**Netlib** 用 WebRTC DataChannel（可靠/不可靠双通道），Poki 免费托管信令 + STUN/TURN（**Cloudflare TURN**），直连失败回落中继；但默认 CSP **封禁一切外部请求**（联机服务器也须白名单批准），且**聊天系统一律禁止**（建议 emoji）。[netlib](https://developers.poki.com/guide/netlib) ｜ [外链政策](https://developers.poki.com/guide/external-resources-policy) ｜ [玩家安全](https://developers.poki.com/guide/content-player-safety)
- **CrazyGames**：SDK **不含传输层**，只给房间/好友/邀请元数据；官方原话"房间不必存在于服务器上，可视为玩家直接相连（例如 WebRTC）"；**有 chat 必须上脏话过滤或 AI 审核**，平台可强制 `disableChat`。[multiplayer](https://docs.crazygames.com/requirements/multiplayer/) ｜ [sdk](https://docs.crazygames.com/sdk/game/)
- **Newgrounds**：newgrounds.io 组件仅 App/CloudSave/Event/Gateway/Loader/Medal/ScoreBoard，**无联机/信令**（CloudSave 明确"面向单用户存档"）。[newgrounds.io](https://www.newgrounds.io/help/components/)
- **Steam**：官方路径是 **SDR 中继网络** + Steam Networking Sockets；Valve 仓库确认 Steam 版可访问 SDR 中继服务（认证/信令/中继）。[SDR](https://partner.steamgames.com/doc/features/multiplayer/steamdatagramrelay) ｜ [GameNetworkingSockets](https://github.com/ValveSoftware/GameNetworkingSockets)
- **Roblox**：语音是平台服务，**仅 13+ 且通过年龄/ID 验证、限部分国家、单体验上限 100 人**；架构为 client-server 服务端权威。[voice-chat](https://github.com/Roblox/creator-docs/blob/main/content/en-us/chat/voice-chat.md) ｜ [client-server](https://create.roblox.com/docs/projects/client-server)
- **"E2E 加密 / 不可审核"这一点**：**未找到任何平台"明文条款要求通信必须可审核"**。可核查的是结果导向的硬约束：Poki 全面禁 chat、CrazyGames 强制可审核 chat 且平台可一键关闭、Roblox 语音年龄门控；监管侧 COPPA 把儿童音频/影像列为个人信息、英国 OSA 第 3 部分对"用户对用户服务"设注意义务。Discord/Steam/Epic 相关条款原文**未取到**。[16 CFR 312](https://www.ecfr.gov/current/title-16/chapter-I/subchapter-C/part-312) ｜ [OSA Part 3](https://www.legislation.gov.uk/ukpga/2023/50/part/3/chapter/2)

- **官方文档明确**：CF WebSocket 全套餐支持与"自定义空闲超时仅 Enterprise"、端口与连接限制清单、CF Realtime TURN 价格/端口/不含中国网络；coturn 全部 flag 与默认端口；MDN 的 Permissions Policy 默认 allowlist、BroadcastChannel 同源+同 partition 条件、maxMessageSize 位置与 64 KB 缺省；itch.io 嵌入与 ZIP 限额；Poki Netlib/禁聊/CSP；CrazyGames chat 审核；Roblox 语音 13+；COPPA/OSA 与中国法规条文。
- **社区经验/第三方**：CF WebSocket **100 秒空闲**（官方未公布数字）；lgrahl 的 16 KiB/256 KiB 分片经验；Enable Security 的配额起点值；TokBox/appear.in 通话统计（厂商自测，非同行评审）；Ford NAT Check 自愿样本。
- **查不到**：中国大陆运营商网络 STUN-only 成功率；DataChannel 吞吐上限数值；Twilio Network Traversal 静态单价；国内可用托管 TURN/SFU 定价；平台"通讯须可审核"的明文条款；"中继转发第三方流量"是否属电信业务。

## 对本站的适用性判断

1. **直连成功率**：TURN 不是可选项——约 1/5 的成功连接要靠中继，只做 B 路线会稳定损失这部分用户。
2. **橙云**：现有 CF 前置只保护 HTTP/HTTPS；WebSocket 中继可继续走橙云（需心跳，建议 <100s），但**自建 coturn 的 UDP 必须改灰云直连并暴露真实 IP**。
3. **coturn**：单机可撑数千会话，但配额默认全开等于裸奔；必须上 TURN REST 短时凭证 + `denied-peer-ip` + 配额 + 最新版。
4. **托管替代**：不想暴露源站就选 **CF Realtime TURN（$0.05/GB、无企业门槛）**，代价是它不覆盖中国网络；Poki 用 CF TURN 托管 Netlib 是同类先例。
5. **SDK 生态**：Ably/Pusher/Supabase 免费档撑不住 60fps 状态流；**CF Durable Objects + WS 休眠**是"零后端作者 + 权威房间"最贴合的托管形态。
6. **浏览器约束**：`sandbox="allow-scripts"` 下 P2P/DataChannel 可用，但**麦克风/摄像头必须由父页 `allow=` 显式委托**，且 **BroadcastChannel 无法穿透不透明源**——同机多标签联机不能靠它。
7. **平台先例**：同类平台要么完全不提供联机（itch.io/Newgrounds），要么提供 P2P 但严格管控聊天（Poki 禁聊、CrazyGames 强制审核）——本站若上语音/聊天，审核成本是硬性的。
8. **合规**：待确认项集中在"是否构成电信业务"与"定几级"，建议动手前先做备案 / 等保 / 内容安全三项专业咨询。
