# 作者指南：网页与压缩包作品

面向投稿者。只讲「怎么做出一个能通过审核、打开就能玩的作品」，不讲平台内部实现。

## 一、先选对类型

投稿页上要选「作品类型」。选错类型会被服务端挡回来，提示会告诉你检测到了什么、
这个类型收什么。对应关系见 `docs/作品形态接入清单.md`，这里是常用两条：

| 你做了什么 | 选哪个类型 | 传什么 |
| --- | --- | --- |
| 一个自包含的 `.html` 或 `.svg` | 网页作品 | 就传这一个文件 |
| 一个带 css/js/图片的站点 | 网页作品或压缩包作品 | 传 zip，根目录放 `index.html` |
| Godot 导出的 Web 包 | Godot 游戏 | 传 zip |

## 二、单文件作品：只有一个文件

单文件投稿**只收那一个文件**，同目录的 `.css`、`.js`、图片不会被一起上传。

所以单文件必须是自包含的：

- 样式写在 `<style>` 里，脚本写在 `<script>` 里；
- 图片要么是 SVG 里的矢量，要么用 `data:` 内联；
- 不要 `src="./app.js"`、`href="style.css"` 这类外部引用——它们会 404。

要带资源，就用压缩包。

## 三、压缩包作品：根目录必须有 index.html

打 zip 之前先确认三件事：

1. **`index.html` 在压缩包的最外层**，不要在某个子目录里；
2. 所有资源用**相对路径**引用（`./assets/app.js`，不要 `/assets/app.js`）；
3. 不要在压缩包里套一层同名文件夹。

```
bundle.zip
├── index.html          ← 必须在最外层
├── app.js
└── assets/
    ├── style.css
    └── cover.png
```

反面例子：把构建产物的 `dist/` 整个打包，`index.html` 跑到 `dist/index.html`。
平台只认根目录的入口，遇到这种包会回一句「压缩包根目录必须有 index.html」——
这是刻意的：根目录不是入口的包打开就是白页。

## 四、Godot 游戏

用 Godot 的「导出 → Web」得到一组文件，**把导出的全部文件按原结构**打成一个 zip：

- 入口仍然是根目录的 `index.html`；
- 包里必须同时有脚本（`.wasm`，Godot 3.x 是 `.asm.js`）和资源包（`.pck`）——
  平台靠这两样判断它是 Godot 包；
- 导出设置里的资源路径保持相对路径，不要写死站点根路径。

## 五、大小与配额

- 单个作品包上限**默认 200 MiB**（运维可调，见 `docs/运行手册-可变常量.md`）；
- 同时处于「待审」的投稿有条数上限，超了会回 429，按响应头 `Retry-After`
  的秒数等一会儿再投。

## 六、投稿之后

- 草稿只有你能看；`/preview/{slug}/` 是预览地址（作者与审核员可看）；
- 审核通过后需要点「发布」，选渠道与可见性，作品才会出现在作品库；
- 修改已发布的作品不会立刻影响线上：改动先进入审核，通过后才替换对外内容。

## 七、常见失败与含义

| 提示 | 意思 | 怎么办 |
| --- | --- | --- |
| 压缩包根目录必须有 index.html | zip 里最外层没有入口 | 重新打包，把 `index.html` 放最外层 |
| 「网页作品」不收这种文件（检测到 single:jpg） | 选错了类型 | 按提示里给出的可收清单改选类型 |
| 提交内容不合格 | 文件本身不合法（不是合法 UTF-8、不是 zip 等） | 用本机工具重开一次，确认文件没坏 |
| 413 / 包太大 | 超过大小上限 | 压一压资源，或拆成更小的作品 |
