# 契约兼容性

**这份文件回答一个问题**：改了 `api/openapi.yaml`，会不会打断已经在用它的调用方？

门禁是 `node scripts/check-api-compat.mjs`（CI 的 `contract` job）。它把生成出来的
Go 类型表面抽成快照存进 [`surface.json`](./surface.json)，和当前生成物比，按下面的
判定表分类。**基线要跟着 PR 一起提交**——`surface.json` 变了，review 就能看见契约变了。

## 为什么不直接 diff YAML

YAML 里改一个缩进、调一个字段顺序、换一种等价的写法，都会产生 diff，而对调用方
毫无影响。真正决定「会不会打断」的是**生成出来的类型表面**：JSON 字段名、可空性、
类型、枚举取值、端点与参数。所以比的是这一层。

比的是 **Go 生成物**而不是 YAML，还有第二个原因：Go 类型是编译期强制的东西。如果
某个改动在 Go 里不产生差异（比如纯文档性修改），那它对后端就没有约束力，也就不用
走兼容判定。

## 判定表

| 改动 | 判定 | 说明 |
| --- | --- | --- |
| 新增端点 | ✅ 兼容 | 老客户端不知道它，照常用别的 |
| 删除端点、或改路径/方法 | ❌ 破坏 | 老调用方会 404 |
| 新增可选查询参数 | ⚠️ 提示 | 服务端要能容忍不传 |
| 删除查询参数 | ❌ 破坏 | 传了会 400，或静默失效 |
| 字段从可空变必填 | ❌ 破坏 | 老数据里 `null` 的会被判非法 |
| 字段从必填变可空 | ⚠️ 提示 | 客户端要处理 `null` |
| 新增字段 | ⚠️ 提示 | 老客户端忽略未知字段；文档与响应体积要跟上 |
| 删除字段 / 改名 | ❌ 破坏 | 与「新增」不对称：读的人拿不到它了 |
| 改字段类型 | ❌ 破坏 | 反序列化会炸 |
| 新增枚举取值 | ⚠️ 提示 | 见下面的「边界」第 2 条 |
| 删除枚举取值 | ❌ 破坏 | 正在传这个值的人会收到未知值 |
| 删模型 / 改名 | ❌ 破坏 | |

`❌` 会让 CI 红。要过就得二选一：

1. **改成兼容形态**——加字段而不删字段；加枚举值而不删值；要换类型就加一个新字段，
   老字段标弃用后再删（跨版本）。
2. **承认这是破坏性变更**：跑 `node scripts/check-api-compat.mjs --update` 重签基线，
   并在 PR 描述里写清「谁会被打断、他们怎么迁移」。这一步是让人做决定，不是让门禁
   自动通过。

## 边界：它抓不到什么

门禁是**结构比对**，不是语义理解。以下三种它一定放过去：

1. **同名改语义**。`page` 从「从 1 开始」改成「从 0 开始」，类型还是 `int`，
   门禁看不见，调用方的翻页会静默错位。这类改动只能靠 review 和变更记录。
2. **加枚举值导致客户端 `switch` 不穷尽**。门禁会给 ⚠️，但如果客户端写的是
   `switch (state) { case 'published': ...; default: throw }`，新增一个取值就会在
   运行时炸。**这是本次门禁里唯一「提示级别但真能打断人」的项**，别当它是噪音。
3. **约束收紧**。`pageSize` 上限从 200 降到 100、字符串长度上限变小、必填字段的
   格式变严——这些在 OpenAPI 里是 `maximum` / `maxLength` / `pattern`，不影响 Go
   类型，所以不在快照里。改这类约束要在 PR 里明说。

反过来说，它**能**抓到的正是最容易手滑的那几类：删字段、改名、改类型、
可空性翻转、删枚举值。这些恰恰是 YAML diff 里最难一眼看出来的。

## 为什么契约是 OpenAPI 3.0.3 不是 3.1

`oapi-codegen` v2.5.0 不支持 3.1（上游 issue #373）：3.1 的正确写法
`type: [string, 'null']` 会让生成直接失败，退回 3.0 的 `nullable: true` 又让文件
既不是合法 3.1 也不是合法 3.0。所以钉在 3.0.3。详见 [`README.md`](./README.md)。

**这不影响本文件的判定**：可空性在 3.0.3 里是 `nullable: true`，生成出来是
`*T`，快照里就是 `optional: true`。等工具支持 3.1 再升，判定表不用改。

## 什么时候重签基线

`--update` 会**整份覆盖** `surface.json`。所以它只能在这些时候用：

- 加了新端点 / 新字段 / 新枚举值（兼容变更本身也要重签，否则下一次比对会一直报「新增」）；
- 有意做破坏性变更，且在 PR 里写明了影响面。

**不要**为了「让 CI 绿」直接 `--update`。如果 diff 里出现「字段被移除」，先问一句
「真的没有人还在读它吗」。
